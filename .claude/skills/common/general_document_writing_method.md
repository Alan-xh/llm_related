## 一、适用范围

本规范适用于以下技术文档类型：

| 文档类型 | 示例 |
| --- | --- |
| 语法参考手册 | CMake 语法详解、Python API 参考 |
| 入门教程 | 快速上手、Hello World 指南 |
| 操作指南 | 部署手册、配置说明 |
| 设计文档 | 架构说明、模块设计 |
| 技术博客 | 原理剖析、实践总结 |

---

## 二、文档结构规范

### 2.1 总体结构

推荐采用 **总—分—总** 结构：

| 部分 | 作用 | 要求 |
| --- | --- | --- |
| 总（开头） | 告诉读者会读到什么 | 3~5 句话说明背景、目标、读者收益 |
| 分（主体） | 按逻辑展开各观点 | 每节只讲一件事，层级不超过 4 层 |
| 总（结尾） | 10 秒内让读者抓住重点 | 用列表或表格总结核心结论 |

### 2.2 章节组织

- 使用**语义化标题**，避免"第一部分""其他"这类无信息量的标题。
- 标题层级建议不超过 4 级（`#` 到 `####`）。
- 每节保持**最小自洽**：读者跳读任意一节都能看懂。
- 编号与语义结合，例如：`2.5.3 foreach 循环变量 + RANGE start stop step`。

### 2.3 段落颗粒度

- 一段只讲一个观点。
- 段落长度建议控制在 **3~6 行**。
- 超过 6 行考虑拆分或改为列表。

## 三、排版规范

### 3.1 中英文标点

**说明**：在中文文档中，不要出现中英文标点混用的情况。

| 说明 | 中文 | 英文 |
| --- | --- | --- |
| 逗号 | ， | , |
| 句号 | 。 | . |
| 分号 | ； | ; |
| 问号 | ？ | ? |
| 感叹号 | ！ | ! |

**错误写法 ❌**

```text
作为一名程序员,日常大部分的时间主要在埋头编码、调试.
```

**推荐写法 ✅**

```text
作为一名程序员，日常大部分的时间主要在埋头编码、调试。
```

**例外**：代码块、命令、路径、URL、英文原文引用中，保留英文标点。

---

### 3.2 专用名词拼写

**说明**：专有名词必须使用官方大小写形式。

**错误写法 ❌**

```text
我热爱 java 编程语言！
```

**推荐写法 ✅**

```text
我热爱 Java 编程语言！
```

**常见易错专有名词**：

| 错误 | 正确 |
| --- | --- |
| java | Java |
| python | Python |
| github | GitHub |
| javascript | JavaScript |
| android | Android |
| ios | iOS |
| mysql | MySQL |
| linux | Linux |
| npm | npm（全小写） |
| cmake | CMake |

---

### 3.3 英文左右空格

**说明**：遇到英文字符或单词，请在左右都加上空格，让文本阅读更舒适。这是文档与平面设计的通用规范，苹果设计语言中尤为明显。

**错误写法 ❌**

```text
窄带LED背光组件使 MacBook Pro支持P3广色域显示，为照片和视频带来绚丽逼真的色彩。
```

**推荐写法 ✅**

```text
窄带 LED 背光组件使 MacBook Pro 支持 P3 广色域显示，为照片和视频带来绚丽逼真的色彩。
```

**加空格规则**：

| 场景 | 示例 |
| --- | --- |
| 中文 + 英文单词 | 使用 CMake 构建 |
| 中文 + 数字 | 共 3 个参数 |
| 中文 + 英文标点 | 见 `README.md` 文件 |
| 英文 + 中文 | CMake 是跨平台的 |
| 数字 + 单位 | 耗时 5 秒 |

**不加空格的情况**：

- 中文全角标点与英文之间：`使用 CMake，即可构建。`
- 代码块内部。
- URL、文件路径内部。

---

### 3.4 代码块与代码高亮

**行内代码**：用于命令、变量名、函数名、文件名、路径等。

```text
先定位到你的目录，然后输入命令 `ls -al` 即可列出该目录下的所有文件。
```

**代码块**：用于多行代码、配置、命令序列。

````text
```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("我的第一个 Java 程序：Hello World。");
    }
}
```
````

**规范要求**：

1. 代码块必须标注语言类型（如 `java`、`cmake`、`bash`、`json`）。
2. 无法确定语言时使用 `text`。
3. 代码块与正文之间空一行。
4. 代码块内保留原始标点，不做中英文转换。
5. 示例代码应**可运行**，避免伪代码和省略关键上下文。

---

### 3.5 列表与表格

- 并列项使用无序列表，步骤使用有序列表。
- 对比信息优先使用表格。
- 列表项末尾不加句号（除非是完整句子）。
- 表格对齐方式统一，表头与内容语义清晰。

---

### 3.6 引用块

- 引用他人观点、原文、规范条文时使用 `>` 引用块。
- 说明性文字也可用引用块，与代码形成视觉分层。
- 引用块内保留原文标点。

## 四、行文规范

### 4.1 句子长度

**原则**：技术文章忌用复杂长句和重句。

**原因**：句子一长，大脑需要花太多时间理解字面意义，无法专注于句子要传达的内容，这与写作目的完全相悖。

**建议**：

- 单句控制在 **15 个词以内**。
- 长句用标点切分为短句。
- 重复率不高时，尽量用简单词汇。

**改写示例**：

原句：

```text
主要原因是，当句子一长我们的大脑需要花太多的时间来理解这个句子的字面意义而不能专注于理解这个句子要传达的内容因而这与我们的目的完全南辕北辙。
```

改写后：

```text
主要原因是，当句子一长，我们的大脑需要花太多时间，来理解这个句子的字面意义。而此时我们的大脑无法专注句子本身要传达的内容，这与我们的目的完全相悖。
```

---

### 4.2 图文并茂

**原则**：有条件时，尽量插入与逻辑和表达内容相关的图片。

**收益**：

- 降低读者阅读负担。
- 可用图表、GIF、视频等丰富形式表达观点。
- 搜索引擎对相关图片和视频增加权重，有利于搜索流量增长。

**规范**：

- 图片需配文字说明。
- 图表需标注坐标轴、单位、图例。
- 动图控制在 3~5 秒循环，避免干扰阅读。

---

### 4.3 起承转合

**原则**：技术文章虽偏议论文，但同样需要注意起承转合。

**推荐结构**：总—分—总。

| 部分 | 作用 |
| --- | --- |
| 总 | 文首先告诉读者会读到什么。不感兴趣的读者可省下时间，感兴趣的读者正好有个好引子 |
| 分 | 分散表达各观点。例如本文分为三部分：关于内容、关于标点、关于行文 |
| 总 | 最后总结。假设读者没有时间详读全文，总结能让读者在 10 秒内知道你表达了什么 |

**逻辑串联**：

- 多个观点之间需有合理逻辑关系。
- 可用"首先/其次/最后""因为/所以""然而/因此"等连接词。
- 避免观点并列但无递进、无对比、无因果。

---

### 4.4 引用链接

**原则**：把你引用的内容放在合适的位置，既尊重原作者，也方便读者继续阅读。

**说明**：

- 不要觉得引用文章会让人觉得你在抄袭观点。只要你有新鲜观点、论据，或更规范的总结，读者会感激你。
- 丰富的引用链接有助于搜索引擎确定你的权威性。你不光写出来了，还指向了靠谱的参考文献，搜索引擎也会认为这篇文章靠谱程度很高。

**规范**：

- 引用处紧跟链接，或使用脚注。
- 链接文字应描述目标内容，避免"点击这里"。
- 引用规范条文时注明出处与版本。
- 参考列表统一放在文末。

## 五、写作流程

### 5.1 写前

1. 确定文档定位：教程、参考、操作指南，还是解释说明。
2. 明确目标读者与阅读场景。
3. 列出大纲，按逻辑排序。
4. 收集素材与引用来源。

### 5.2 写中

1. 按大纲逐节撰写，每节只讲一件事。
2. 统一使用"语法 → 语义 → 示例 → 注意事项"模板（适用于参考型内容）。
3. 示例代码必须可运行。
4. 边写边检查标点、空格、专有名词。

### 5.3 写后

1. 通读全文，检查句子长度与逻辑连贯性。
2. 检查中英文标点、英文左右空格、专有名词拼写。
3. 检查代码块语言标注与可运行性。
4. 检查引用链接与参考列表。
5. 请他人试读，收集反馈。

## 六、检查清单

发布前逐项核对：

- [ ] 中文文档中无中英文标点混用
- [ ] 专有名词大小写正确
- [ ] 英文与中文之间已加空格
- [ ] 代码块已标注语言类型
- [ ] 示例代码可运行
- [ ] 单句不超过 15 个词
- [ ] 段落不超过 6 行
- [ ] 标题语义清晰，层级不超过 4 级
- [ ] 表格与列表格式统一
- [ ] 引用链接规范，参考列表完整
- [ ] 全文符合总—分—总结构
- [ ] 文末有 10 秒可读的总结

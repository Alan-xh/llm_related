# 3. 高效微调与适配器

## 1. 概述

**PEFT（Parameter-Efficient Fine-Tuning）** 指在微调时只更新极少量新增参数（通常 <1%）、冻结主干，从而在显存、存储、多任务切换上获得数量级节省的技术族。对语音领域尤其重要：

* 语音模型常为「音频 Encoder（Conformer/Whisper）+ LLM 解码器」双塔，全参微调动辄几十 GB 显存；
* 说话人自适应、方言/小语种定制、领域热词增强等场景需要**一个底座 + N 个轻量插件**，而不是 N 份全量拷贝；
* 多任务叠加时要防止新任务冲掉旧能力（灾难性遗忘），冻结主干天然提供保护。

```
                ┌─────────────────────────────────────────────┐
  全参微调:      │ ██████████████████████████████████  100%    │  7B 模型 AdamW 需 ~84GB 显存
  Adapter:      │ ▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░   0.5~8%  │  冻结主干, 只训练瓶颈模块
  Prefix/P:     │ ▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░   <1%      │  只训练软提示向量
  LoRA:         │ ▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░   0.1~1%   │  低秩旁路 ΔW=BA
  QLoRA:        │ ▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░   0.1~1%   │  4bit 底座 + LoRA, 单卡可调 33B
                └─────────────────────────────────────────────┘
                                 (█ 可训练 ▓ 冻结)
```

## 2. PEFT 方法族：Adapter / Prefix / P-tuning / LoRA / QLoRA

### 2.1 Adapter（Houlsby Adapter, 2019）

在 Transformer 每层（通常在 attention 与 FFN 之后）插入瓶颈结构：

$$h \leftarrow h + f(h W_{down} W_{up})$$

* $W_{down} \in \mathbb{R}^{d \times r}$ 降维、$W_{up} \in \mathbb{R}^{r \times d}$ 升维，$r \ll d$（如 $d=768,\ r=64$）；
* 参数量 $2dr$ / 层，约占总参数 0.5~8%（取决于 $r$ 与插入位置）；
* 缺点：**串行结构引入推理延迟**（每层多两次小矩阵乘），需要 serve 时合并不了；优点是即插即用、多任务可热切换。

### 2.2 Prefix-tuning（2021）与 P-tuning（v1/v2）

**Prefix-tuning**：在每层 self-attention 的 KV 前面拼接可学习的软提示 $P_K, P_V \in \mathbb{R}^{L_p \times d}$：

$$\text{Attn}(q, [P_K; K], [P_V; V])$$

* 只训练这些前缀向量（再经重参数化 MLP 稳定训练），参数 $2 L_p d \times N_{layer}$；
* 不改模型结构、无推理结构变化，但**占用了序列长度**（$L_p$ 通常 10~100），且深层效果对初始化敏感。

**P-tuning v1**：只在输入 embedding 层加可学习 prompt；**P-tuning v2**：把它推广到**每一层**都加（即 Deep Prompt Tuning），效果逼近全参微调，是 NLU 任务上 LoRA 之前的主流选择。

### 2.3 LoRA（Low-Rank Adaptation, 2021）与公式推导

**低秩假设**：微调引起的权重更新 $\Delta W$ 具有低「内在秩」--Aghajanyan 等人观察到预训练模型在适配任务时权重的变化落在低维子空间。于是约束：

$$W' = W_0 + \Delta W = W_0 + BA, \quad B \in \mathbb{R}^{d_{out} \times r},\ A \in \mathbb{R}^{r \times d_{in}},\ r \ll \min(d_{in}, d_{out})$$

$$h = W_0 x + \Delta W x = W_0 x + \frac{\alpha}{r} B(Ax)$$

* $W_0$ 冻结，梯度只流向 $A, B$；$A$ 用高斯初始化，$B$ 初始化为 **0**（保证训练起点 $\Delta W = 0$，不破坏预训练权重）；
* $\alpha$ 是缩放因子，$\alpha/r$ 控制更新的有效幅值（经验上 $\alpha$ 固定 16~32、调 $r$）；
* **参数量**：单个 Linear 从 $d_{in} d_{out}$ 降到 $r(d_{in} + d_{out})$。例：$d=4096,\ r=8$ 时比例为 $\frac{8 \times 8192}{4096^2} \approx 0.39\%$；
* **训练显存下降的关键**：优化器状态（AdamW 的一二阶动量）只对 $A,B$ 分配，7B 模型从 ~84GB 降到 ~20GB 级；
* **推理零延迟**：训练完可显式合并 $W' = W_0 + \frac{\alpha}{r}BA$，部署与原模型完全一致；
* **作用位置**：原论文只在 attention 的 $W_q, W_v$；工程实践（QLoRA 论文实验）表明**全部 Linear（q/k/v/o + MLP 的 gate/up/down）都挂 LoRA** 效果最好。

**为什么低秩可行（直觉推导）：** 设 $\Delta W$ 的奇异值分解 $\Delta W = U\Sigma V^T$，若其有效秩为 $k$（前 $k$ 个奇异值占能量 99%），则秩 $r \ge k$ 的 $BA$ 即可精确重构主能量。微调是「适配一个已经收敛的解」，任务更新的自由度远小于权重本身自由度。

### 2.4 QLoRA（2023）

在 4bit 量化底座上训练 LoRA，三件套：

1. **NF4（NormalFloat4）**：按正态分位数设计的 4bit 信息论最优格式（预训练权重近似正态分布，分位数量化比均匀 INT4 保留更多有效位）；
2. **Double Quantization**：对量化常数再量化，省出 ~0.37 bit/参数；
3. **Paged Optimizer**：优化器状态在显存峰值时溢出到 CPU 内存（NVIDIA unified memory），防 OOM。

效果：65B 模型在单张 48GB 卡上完成微调，效果接近 16bit 全参微调。显存构成（7B 模型训练时粗估）：NF4 权重 ~3.5GB + LoRA 参数与优化器状态 ~0.2~0.5GB + 激活值（与 batch/seq 长度相关）。

### 2.5 方法横向对比

| 方法 | 新增参数占比 | 推理额外延迟 | 显存节省 | 可合并部署 | 语音常用度 |
| --- | --- | --- | --- | --- | --- |
| 全参微调 | 100% | 0 | 基准 | - | 底座训练/大规模数据 |
| Adapter | 0.5~8% | **有**（串行） | 中 | 否（需保留结构） | 音频 encoder 适配（Whisper adapter） |
| Prefix / P-tuning v2 | <1% | 无（但占 seq 长度） | 中 | 否 | 表格/分类任务 |
| LoRA | 0.1~1% | **零**（可合并） | 大 | **是** | **Speech-LLM/TTS 全栈最主流** |
| QLoRA | 0.1~1% | 零（合并前需反量化） | 极大（4bit 底座） | 是 | 单卡微调大 Speech-LLM |

## 3. 语音领域应用：Adapter 接入与 LoRA 微调

### 3.1 Adapter 接入音频 Encoder（Whisper -> LLM 的桥）

Speech-LLM（如 SALMONN、Qwen-Audio 类、SpeechGPT）的经典做法：冻结音频 encoder 与 LLM，只在中间加**轻量 adapter** 对齐模态：

```
  音频 x ──> [Whisper Encoder (冻结)] ──> h_audio (1500帧 × d)
                        │
                        ▼
              ┌──────────────────────────┐
              │ Adapter = 线性投影 +      │   <- 只训练这部分 (几 M ~ 几十 M 参数)
              │ 2~6 层 Transformer/      │
              │ CTC 压缩 (75Hz->25Hz)   │
              └──────────────────────────┘
                        │
                        ▼
              [LLM (冻结或 LoRA)] ──> 文本/语音 token 输出
```

* SALMONN 用 **Q-former 风格**（可学习 query 交叉注意力抽取 Whisper 特征）+ Window-level Q-Former 压缩帧率；
* 压缩帧率（1500 帧 25Hz 语音 token）是关键：LLM 上下文有限，1500 个帧向量直接喂入既贵又难学；
* 该阶段训练数据为 `<语音, 转写/响应>` 对，训练后即具备语音理解能力。

### 3.2 LoRA 微调 Whisper

* 圻景：领域方言/小语种/医疗术语 ASR，Whisper-large-v2/v3 全参微调需多卡，LoRA 只需单卡（large-v3 全参 ~40GB+ 级，LoRA(r=32) 训练态 ~20GB 内）；
* `target_modules` 通常选 encoder-decoder 的所有 Linear 或仅 decoder（识别能力主要在 decoder）；
* 与 DPO/RLHF 组合：Whisper 转写幻觉治理可用偏好对（有幻觉 vs 无幻觉转写）做 DPO，同样以 LoRA 形式挂载。

### 3.3 LoRA 微调 Speech-LLM / TTS

* **Speech-LLM（VALL-E 类 / 语音对话模型）**：对 codec LM 的 attention 与 FFN 挂 LoRA，做音色/情感/方言风格化微调，一个底座 + 多套风格 adapter（每个几十 MB）；
* **TTS acoustic model**：低资源说话人适配（<5 分钟目标人数据，LoRA r=8~16）即可完成音色克隆，防止小数据全参微调把模型「训崩」；
* **分层策略**：模态对齐阶段训 adapter，指令/偏好对齐阶段对 LLM 挂 LoRA，二者可叠加。

### 3.4 语音 PEFT 配置经验表

| 场景 | 方法 | rank $r$ | target_modules | 数据量 |
| --- | --- | --- | --- | --- |
| Whisper 领域适配 | LoRA | 32 | q_proj,v_proj（或全部 Linear） | 100h+ |
| 音色克隆 | LoRA | 8~16 | decoder 的 attention | 1~30 min |
| Speech-LLM 指令对齐 | LoRA | 16~64 | 全部 Linear | 10k~1M 条 |
| 模态桥接（训练初期） | Adapter/Q-former | - | 新增模块 | 10k~1M 小时级语音 |
| 单卡 33B+ Speech-LLM | QLoRA | 64 | 全部 Linear | 视任务 |

## 4. 多任务防遗忘：Replay、L2-SP 与正则

微调（尤其连续微调，continual learning）中，新任务梯度会覆盖旧任务的解。冻结主干的 PEFT 天然缓解，但仍需以下手段：

### 4.1 Replay（回放/重演）

新任务 batch 中混入旧任务数据（5%~20%），等价于在联合分布上优化：

$$\mathcal{L} = \mathcal{L}_{new} + \lambda \mathcal{L}_{replay}, \quad \lambda \approx 0.1 \sim 0.5$$

语音实践：方言适配时混入通用普通话数据；TTS 风格微调时混入底座预训练分布样本。代价最小、效果最稳，**工业界首选**。

### 4.2 L2-SP 正则

约束参数不远离预训练初始值 $\theta_0$（只对主干参数，sparse 部分放开）：

$$\mathcal{L} = \mathcal{L}_{task} + \lambda \big( \Vert\theta - \theta_0\Vert_2^2 - \Vert\theta^s - \theta_0^s\Vert_2^2 \big)$$

比纯 weight decay（拉向 0）更合理--拉向「预训练好解」。LoRA 的 $B=0$ 初始化 + 小 $\alpha/r$ 本质上就是一种隐式 L2-SP。

### 4.3 EWC（Fisher 信息加权）与其他

$$\mathcal{L} = \mathcal{L}_{task} + \frac{\lambda}{2}\sum_i F_i (\theta_i - \theta_{0,i})^2$$

对「重要参数」（Fisher 信息大）施加大惩罚。语音中用的少于 Replay/L2-SP（实现与调参成本高）。另有 adapter 级隔离方案：每个任务独立 adapter，推理时路由/拼接，互不干扰（但参数随任务线性增长）。

## 5. 训练工程技巧：混合精度、梯度检查点、DeepSpeed/FSDP

### 5.1 混合精度（AMP）

* 原理：前向/反向大部分算子用 FP16/BF16，权重主副本与优化器状态保持 FP32（master weights）；loss scale 动态调整防 FP16 下溢；
* **BF16 优先**：指数位与 FP32 相同（8 位），无 loss scale 需求、数值更稳，A100/H100/4090 以上无脑选 BF16；FP16 只在旧卡（V100/T4）上用；
* 注意：CTC/RNN-T loss、softmax 等数值敏感模块内部保持 FP32；语音 codec 的 GAN 判别器对精度不敏感可全程半精度；
* 显存粗算：7B 模型 BF16 训练态 ≈ 权重 14GB + AdamW 状态(FP32 m,v + FP32 master) 84GB ≈ **~100GB**（全参）；PEFT 下 optimizer 状态只覆盖可训练参数，骤降至 ~20GB。

### 5.2 梯度检查点（Gradient Checkpointing）

* 以重计算换显存：前向只存每层边界激活，反向时重算层内激活，显存从 $O(L)$ 降到 $O(\sqrt{L})$，代价约 **30% 额外计算**；
* Speech 场景刚需：长音频（30s Whisper = 1500 帧）+ 大 LLM，激活值是显存大头；`model.gradient_checkpointing_enable()` 一行开启，注意配合 `use_cache=False`。

### 5.3 DeepSpeed ZeRO 与 PyTorch FSDP

| 特性 | ZeRO-1 | ZeRO-2 | ZeRO-3 | FSDP (full sharding) |
| --- | --- | --- | --- | --- |
| 切分对象 | optimizer 状态 | + 梯度 | + 参数 | 参数+梯度+优化器（等价 ZeRO-3） |
| 显存节省 | ~4x | ~8x | $N$ 卡线性 | $N$ 卡线性 |
| 通信模式 | - | - | 前反向 all-gather | 前反向 all-gather + reduce-scatter |

* 经验：单机多卡用 FSDP（PyTorch 原生、与 HF Trainer 无缝）；多机大模型用 DeepSpeed ZeRO-3（+ offload 把优化器/参数卸到 CPU/NVMe）；
* **PEFT 与 ZeRO-3 的坑**：LoRA 参数也需要被正确切分/收集，新版 peft 与 accelerate 已兼容，但 ref 模型（DPO）与被冻结底座共用分片可省一半显存；
* 语音数据长尾（音频长度方差大）：用 bucketing 按时长分桶组 batch，减小 padding 浪费，配合 `length_grouped_sampler`。

## 6. 代码实战：PEFT 库微调 Whisper 与 Speech-LLM

```python
import torch
from peft import LoraConfig, get_peft_model, TaskType
from transformers import WhisperForConditionalGeneration

# ============ 1. LoRA 微调 Whisper (ASR 领域适配) ============
model = WhisperForConditionalGeneration.from_pretrained(
    "openai/whisper-large-v3", torch_dtype=torch.bfloat16
)
lora_cfg = LoraConfig(
    r=32, lora_alpha=64, lora_dropout=0.05, bias="none",
    target_modules=["q_proj", "k_proj", "v_proj", "out_proj"],
    task_type=TaskType.SEQ_2_SEQ_LM,
)
model = get_peft_model(model, lora_cfg)
model.print_trainable_parameters()
# 输出类似: trainable params: 15.7M || all params: 1550M || trainable%: 1.01

# ============ 2. 训练循环要点 (混合精度 + 梯度检查点 + bucketing) ============
from transformers import Seq2SeqTrainingArguments, Seq2SeqTrainer
args = Seq2SeqTrainingArguments(
    output_dir="./whisper-lora-medical",
    per_device_train_batch_size=16,
    gradient_accumulation_steps=2,          # 有效 batch = 16*2*N_gpu
    learning_rate=1e-4,                     # LoRA 学习率比全参大 10~100x
    bf16=True,                              # 混合精度 (A100 以上)
    gradient_checkpointing=True,            # 省显存, 换 ~30% 计算
    group_by_length=True,                   # 按音频时长分桶, 减少 padding
    num_train_epochs=3,
    save_total_limit=2,
)
# trainer = Seq2SeqTrainer(model=model, args=args, train_dataset=..., data_collator=...)
# trainer.train()

# ============ 3. 推理前合并: 零延迟部署 ============
# merged = model.merge_and_unload()   # W' = W0 + (alpha/r) B A
# merged.save_pretrained("./whisper-lora-medical-merged")

# ============ 4. 语音 LLM 侧: 只对 LLM 挂 LoRA, 音频 encoder 走 adapter ============
class SpeechLLM(torch.nn.Module):
    def __init__(self, audio_encoder, adapter, llm):
        super().__init__()
        self.audio_encoder = audio_encoder          # Whisper Encoder, 冻结
        self.adapter = adapter                      # 线性投影 + 2 层 Transformer, 训练
        self.llm = llm                              # 底座 LLM, 挂 LoRA
    def forward(self, wav, prompt_ids):
        with torch.no_grad():
            h = self.audio_encoder(wav).last_hidden_state      # [B, 1500, d]
        h = self.adapter(h)                                    # [B, 375, d_llm] (4x 帧率压缩)
        return self.llm(inputs_embeds=torch.cat(
            [h, self.llm.get_input_embeddings()(prompt_ids)], dim=1))

if __name__ == "__main__":
    print_trainable = lambda m: sum(p.numel() for p in m.parameters() if p.requires_grad)
    # 典型量级: Whisper-large-v3 1.55B 全参 -> LoRA 15.7M (1%)
    #           7B Speech-LLM 全参 70亿 -> LoRA(r=32, 全Linear) 约 40~80M (0.6~1.1%)
```

## 7. 参数量与显存对比表（7B 模型实例）

| 微调方式 | 可训练参数 | 显存（训练态, 单卡估算） | 存储/任务 | 推理延迟 |
| --- | --- | --- | --- | --- |
| 全参微调 | 7.0 B (100%) | ~100 GB（BF16 + AdamW） | 14 GB/任务 | 基准 |
| Adapter (r=64) | ~0.2 B (3%) | ~35 GB | 0.4 GB/任务 | +5~10% |
| Prefix-tuning | ~0.02 B (0.3%) | ~30 GB | 40 MB/任务 | 无（占 seq 长度） |
| LoRA (r=32, 全 Linear) | ~0.05 B (0.7%) | ~25 GB | 100 MB/任务 | **零（可合并）** |

> 7B 全参 BF16 训练态显存 = 权重 14GB（BF16）+ master 权重 28GB + AdamW 动量 28GB + 动量二阶 28GB + 激活/梯度，LoRA 把后四项中与参数等大的部分压缩到仅覆盖 0.7% 参数。

## 8. 总结与最佳实践

* **方法选型**：通用默认 **LoRA（全部 Linear，r=16~64，lr 1e-4 级）**；单卡大模型用 QLoRA；模态桥接/需要任务热切换用 Adapter；序列任务上 P-tuning v2 仍是轻量备选。
* **语音特有节奏**：先训 adapter 打通模态，再 LoRA 对齐指令/偏好；音色克隆用小 rank（8~16）+ 小学习率防过拟合小数据。
* **防遗忘三板斧**：Replay（混 5~20% 旧数据，首选）> L2-SP/隐式正则（LoRA 的 $B=0$ 初始化自带）> EWC（谨慎使用）。
* **工程三件套**：BF16 混合精度 + gradient checkpointing（省 30% 算力换数倍激活显存）+ FSDP/ZeRO-3（多卡切分参数梯度优化器）；长音频配 bucketing。
* **部署**：LoRA 训完即合并（$W' = W_0 + \frac{\alpha}{r}BA$），线上与原模型同构、零额外延迟。

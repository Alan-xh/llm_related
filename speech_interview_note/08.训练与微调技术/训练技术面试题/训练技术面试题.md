# 训练技术面试题（语音模型训练范式、PEFT 与对齐技术高频考点）

## 1. 概述

语音大模型（Speech-LLM、Neural Codec TTS、语音对话系统）的训练链路已经从单一任务监督学习，演进为「预训练 -> SFT -> 偏好对齐（RLHF/DPO）」的多阶段范式，并伴随 PEFT（LoRA/Adapter/QLoRA）与分布式训练工程（混合精度、梯度检查点、DeepSpeed/FSDP）的系统性配合。

本文档汇总训练与微调技术在语音算法岗面试中的高频考点：训练范式选型（全参/PEFT/RLHF）、核心机制推导（RVQ、DPO、LoRA）、工业界实战问题（数据配比、灾难性遗忘、loss 尖刺），以及 Q&A 形式的高频问答，与同目录前三篇技术文档互为引用。

```
现代语音大模型训练全链路:

  海量无标注音频 ──> [预训练: SSL(HuBERT/w2v) / Codec(EnCodec/DAC) 训练]
        │
  语音-文本对   ──> [SFT: ASR/TTS/语音对话指令微调]  (全参 或 LoRA/Adapter)
        │
  偏好对(AB)   ──> [对齐: RM + PPO  或  DPO/KTO]    (几乎必配 PEFT)
        │
  部署          <── [合并/量化: merge LoRA, INT8/4bit]
```

---

## 2. 训练范式对比：全参微调 / PEFT / RLHF

三者不是互斥选项，而是训练流水线中不同阶段的选型问题：

| 维度 | 全参微调（Full FT） | PEFT（LoRA/Adapter 等） | RLHF / DPO（对齐） |
| --- | --- | --- | --- |
| **训练信号** | 监督标签（next-token / 重构） | 同左（参数子集） | 人类/模型偏好（偏序） |
| **更新参数量** | 100%（7B 模型 ~100GB 显存） | 0.1%~8%（单卡可训） | 常配 PEFT（policy + ref） |
| **目标** | 最大化似然 $\log p(y\mid x)$ | 同左 | 最大化奖励 - KL 惩罚 |
| **适用阶段** | 底座训练、大规模领域适配 | 小数据定制、多任务插件 | 指令/风格/安全性对齐 |
| **数据量级** | 1kh~10wh 小时语音 | 5min~100h | 1w~100w 偏好对 |
| **主要风险** | 灾难性遗忘、小数据过拟合 | 容量上限（rank 不够） | reward hacking、对齐税 |
| **典型组合** | - | QLoRA + 指令微调 | SFT -> LoRA-DPO |

**面试答题框架**：先按「数据量、算力、任务性质（知识注入 vs 行为对齐）」三轴判断。知识注入（新语种、新领域词表）倾向全参或高 rank LoRA；行为对齐（语气、幻觉抑制）用 SFT + DPO；算力受限优先 QLoRA。

## 3. 核心机制推导：RVQ / DPO / LoRA

### 3.1 RVQ（Residual Vector Quantization）

codec 的核心量化器。给定隐帧 $z_t$，$n$ 层码本级联量化残差：

$$k_i = \arg\min_k \Vert r_t^{(i-1)} - c_k^{(i)} \Vert_2,\qquad r_t^{(i)} = r_t^{(i-1)} - c_{k_i}^{(i)},\qquad \hat{z}_t = \sum_{i=1}^{n} c_{k_i}^{(i)}$$

* **为什么不用单层大码本**：固定 bitrate $B = F \cdot n \cdot \log_2 K$ 下，单层需 $K = 2^{B/F}$ 个码字（指数爆炸），而 $n$ 层小码本以线性开销获得近似指数容量（残差逐层变小）；
* **可变 bitrate**：SoundStream 的 quantizer dropout--训练时随机只用前 $n'$ 层，推理按带宽截断；
* **codebook collapse**：GAN 训练下码字命中高度集中，活跃码字 <50% 即需介入；解法是 **EMA 码本更新** $c_k \leftarrow m_k / N_k$ + 死码重启（未命中码字用 batch 内随机向量覆盖）。

### 3.2 DPO：从 RLHF 目标到闭式解

四步推导（面试要求能完整写出）：

```
DPO 推导链路 (从上到下逐级化简):

  [RLHF 目标]   max_π  E[r(x,y)] - β·KL(π ‖ π_ref)
        │  (变分求极值, 写出最优解)
        ▼
  [最优策略]    π*(y|x) = π_ref(y|x)·exp(r/β) / Z(x)
        │  (取对数反解出 r)
        ▼
  [奖励重写]    r(x,y) = β·log(π*/π_ref) + β·log Z(x)
        │  (代入 Bradley-Terry: p(y_w ≻ y_l) = σ(r_w - r_l))
        ▼
  [闭式解]      Z(x) 在相减中抵消 => 偏好概率只依赖两个似然比
                L_DPO = -log σ( β·log[π(y_w)/π_ref(y_w)] - β·log[π(y_l)/π_ref(y_l)] )
```

1. KL 约束的奖励最大化：$\max_\pi \mathbb{E}_\pi[r(x,y)] - \beta\,\mathbb{D}_{KL}[\pi \Vert \pi_{ref}]$；
2. 最优策略闭式解：$\pi^*(y\mid x) = \frac{1}{Z(x)}\pi_{ref}(y\mid x)\exp\big(\frac{r(x,y)}{\beta}\big)$；
3. 反解奖励：$r(x,y) = \beta\log\frac{\pi^*(y\mid x)}{\pi_{ref}(y\mid x)} + \beta\log Z(x)$；
4. 代入 Bradley-Terry 偏好模型，$Z(x)$ 在 chosen/rejected 相减中**抵消**：

$$\mathcal{L}_{DPO} = -\mathbb{E}\left[\log\sigma\Big(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)} - \beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)}\Big)\right]$$

要点：$\beta$ 同时控制对 KL 的约束强度与偏好损失的温度；语音里 $y$ 是 codec token 序列，$\log \pi_\theta(y\mid x)$ 即 LLM 序列 logprob；ref 可用 LoRA `disable_adapter()` 零成本得到。

### 3.3 LoRA：低秩更新

$$W' = W_0 + \Delta W = W_0 + \frac{\alpha}{r}BA,\quad B \in \mathbb{R}^{d_{out}\times r},\ A \in \mathbb{R}^{r \times d_{in}}$$

* **低秩假设的依据**：Aghajanyan 等人发现预训练模型适配下游任务时，权重更新的「内在秩」很低（前 $k$ 个奇异值占 99% 能量，$k \ll d$）；
* **初始化**：$A$ 高斯、$B = 0$，保证起点 $\Delta W = 0$，不破坏底座（也是隐式的 L2-SP 正则）；
* **参数量**：$d_{in}d_{out} \to r(d_{in}+d_{out})$，7B 模型全 Linear 挂 $r=32$ 约 0.7%；
* **显存本质**：AdamW 状态（2 份 FP32 动量 + master 权重）只覆盖可训练参数，从 ~12 bytes/param 降到只付给 0.7% 参数；
* **零延迟部署**：$W_0 + \frac{\alpha}{r}BA$ 显式合并；
* **QLoRA**：NF4 分位数量化底座 + 双重量化 + Paged Optimizer，单卡 48GB 可调 65B。

## 4. 工业界实战问题与优化策略

### 4.1 数据配比（Data Mixture）

多任务语音指令微调的典型配比问题（数字量级示例）：

| 任务 | 数据占比 | 作用 |
| --- | --- | --- |
| ASR（多语种/多口音） | 30~40% | 锚定基础识别能力，防遗忘 |
| TTS / 语音续写 | 20~30% | 生成能力（codec token LM） |
| 语音翻译 / SLU | 10~20% | 跨语言与语义理解 |
| 通用对话（含纯文本） | 15~25% | 语言能力与指令跟随（文本数据反而重要） |
| 对齐阶段偏好对 | 单独阶段 | DPO/RLHF 不与 SFT 混训 |

工程要点：配比不是拍脑袋--按 **loss 收敛均衡性**动态调权（某任务 loss 降不下去就加权重或过采样）；长音频与短音频、干净与带噪按底座预训练分布对齐；纯文本指令数据保留 20%+ 能显著抑制语音任务的过度拟合与幻觉。

### 4.2 灾难性遗忘（Catastrophic Forgetting）

微调新任务后旧任务退化。防线由弱到强：

1. **冻结主干 + PEFT**（LoRA rank 限制更新子空间本身即保护）；
2. **Replay**：混入 5~20% 旧任务/预训练分布数据，工业界首选，成本最低；
3. **L2-SP**：$\lambda\Vert\theta - \theta_0\Vert^2$ 把参数拉向预训练解而非原点（比 weight decay 合理）；
4. **EWC**：Fisher 信息加权的参数锚定 $F_i(\theta_i-\theta_{0,i})^2$，语音中较少用（调参重）；
5. **任务级 adapter 隔离**：每任务独立 adapter，推理路由。

监控手段：训练中每隔 N 步在**旧任务验证集**上评测（ASR 微调时盯 WER 回退 >5% 相对即报警）。

### 4.3 Loss 尖刺（Loss Spike）与训练不稳

长周期语音大模型训练的常见事故与处置：

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| loss 突然 NaN/inf | 混合精度下溢/上溢、脏数据（超长音频、损坏标注）、学习率过大 | BF16 替代 FP16；数据预过滤（时长/文本长度截断）；lr warmup + 梯度裁剪（clip 1.0） |
| loss 尖刺后可自行恢复 | 异常 batch（极端长音频 OOM 边缘、错位标注） | 跳过 batch + 日志记录；bucketing 让 batch 内长度一致 |
| GAN codec 训练崩塌 | 判别器过强 / 码本 collapse | loss balancer（EnCodec 梯度范数均衡）、EMA 码本更新 |
| WER 突然劣化再难恢复 | 灾难性遗忘 / 数据分布突变（换数据源） | 回滚 checkpoint + Replay 混合 |
| DPO 的 reward margin 涨但人工评变差 | reward hacking / 偏好数据噪声 | 降 $\beta$ 不行反而升 $\beta$、清洗偏好对、加 KTO/IPO 正则 |

**checkpoint 策略**：每小时级保存 + 保留尖刺前后快照，便于回滚对比；正式实验记录随机种子与数据顺序（可复现性是面试加分项）。

## 5. 高频面试问答（Q&A）

### Q1: LoRA 的 rank $r$ 怎么选？是不是越大越好？

**答**：
经验范围 $r = 8 \sim 64$。简单任务（音色/风格）$r=8\sim16$ 足够；知识密度高的任务（新语种、专业领域）需要 $r=32\sim64$ 甚至更高。$r$ 超过任务内在秩后收益迅速递减，反而增大过拟合与显存开销；QLoRA 论文实验表明在全部 Linear 层挂小 rank 优于只在 $W_q,W_v$ 挂大 rank（作用范围比 rank 本身更重要）。调参顺序建议：先定 target_modules（默认全 Linear），再扫 $r \in \{8,16,32\}$，$\alpha$ 固定为 $2r$ 或 32。

---

### Q2: 为什么 LoRA 训练学习率（1e-4 量级）比全参微调（1e-5 量级）大 10~100 倍？

**答**：
1. LoRA 参数量极小（<1%），梯度噪声相对大，小学习率学不动；
2. $B=0$ 初始化使 $\Delta W$ 从 0 出发，需要更快的增长速度才能在有限 step 内追上任务需求；
3. 主干冻结，不存在「大学习率破坏预训练权重」的风险--更新被约束在低秩子空间内，天然更安全。
反向推论：全参微调学习率大时会直接冲出预训练极小值盆地，造成灾难性遗忘。

---

### Q3: DPO 与 PPO 各自的适用场景？为什么工业界越来越多用 DPO？

**答**：
* **PPO**：需要在线采样、RM 打分、GAE 优势估计，policy/ref/RM/value 四模型并存，工程复杂、超参敏感；优势是能持续探索新样本（off-distribution 优化）；
* **DPO**：闭式偏序损失，只需 policy + ref 各一次前向，简单稳定；缺点是局限于偏好对的离线分布（覆盖不足时上限受限），且对偏好数据质量敏感。
工业界偏好 DPO 的核心原因：成本（显存/人力）低一个量级、无 reward hacking 中间环节、效果在指令与风格对齐上普遍追平 PPO。语音领域（codec token 长序列、episode 长）PPO 的 credit assignment 更难，DPO 优势进一步放大。

---

### Q4: 语音 RLHF 的奖励模型怎么设计？单用 MOS 预测器行不行？

**答**：
不行。单目标奖励必然被投机（policy 会生成「低沉含糊但 MOS 预测器打高分」的语音）。工业实践是复合奖励：$r = w_1 r_{ASR}(-CER) + w_2 r_{MOS} + w_3 r_{spk\_sim} + w_4 r_{stable} + w_5 r_{LLM\_judge}$，其中内容项（ASR 转写比对）权重最大或做一票否决；各分项 z-score 归一后加权；上线后定期用人工偏好对回归测试 RM 的 pairwise accuracy（健康值 >70%），监控 hacking。

---

### Q5: 微调 Whisper 做方言识别，两周后通用普通话 WER 反而涨了 8%（相对），怎么办？

**答**：
典型灾难性遗忘。处置顺序：
1. 立刻改用 LoRA（冻结主干），而不是全参微调；
2. 训练数据混入 10~20% 通用普通话数据（Replay）；
3. 降低学习率与 epoch，加早停（监控通用验证集 WER）；
4. 若必须全参，加 L2-SP 正则锚定预训练参数；
5. 数据层检查方言数据是否分布偏窄（单一录音条件），做增广（加噪/混响/带宽扰动）。

---

### Q6: 训练中出现 loss 尖刺（loss 从 0.3 突然跳到 2.0 再缓慢回落），如何定位？

**答**：
排查清单：
1. **数据**：该 step 的 batch 是否含异常样本（超长音频、空标注、文本-音频错位、编码损坏）--先看 dataloader 日志与样本 id；
2. **数值**：FP16 下溢（换 BF16）、梯度范数爆炸（加 clip、查是否某层梯度异常）；
3. **学习率**：是否踩到 warmup 结束的峰值或 scheduler 突变；
4. **并行**：分布式下某卡数据分片异常、all-reduce 通信错误；
5. **GAN/多任务**：判别器/辅助损失失衡（codec 的 balancer 失效）。
处置：可自愈的偶发尖刺记录跳过；反复出现则回滚 checkpoint 修数据后再续训；根因 80% 在数据。

---

### Q7: codec 训练中如何判断并解决 codebook collapse？

**答**：
判断：统计每层 RVQ 码字命中的 perplexity/活跃码字比例（usage = 有效命中码字数 / K），健康 >90%，<50% 即异常，伴随音质发闷、token 分布熵骤降。解决：EMA 码本更新（$c_k \leftarrow m_k/N_k$，decay 0.99）+ 死码重启（长时间未命中的码字用 batch 内随机编码向量覆盖）；进阶用码本熵正则、affine 归一化，或改 LFQ（逐维二值量化，从结构上消灭 collapse）。面试加分：能说出 EMA 为什么优于梯度更新（GAN 对抗下 VQ 梯度路径不稳，统计量更新更平滑）。

---

### Q8: 7B 的 Speech-LLM 只有一张 A100-40G，怎么做指令微调 + DPO 全流程？

**答**：
1. **SFT 阶段用 QLoRA**：底座 NF4 量化（~3.5GB）+ LoRA r=32 全 Linear（~50M 可训练参数），配 gradient checkpointing 与 batch=1 + 梯度累积，40G 足够（BF16 或 FP16 + max_seq_len 截断到 2k~4k token）；
2. **DPO 阶段**：policy 用同一 LoRA；ref 模型不单独加载--用 `disable_adapter()` 把 LoRA 关掉前向得到 ref logprob，显存省一半；
3. 长音频侧做帧率压缩（codec 75Hz -> 25Hz 或 delay pattern），控制序列长度；
4. 训练细节：lr 1e-4（SFT）/ 5e-6~5e-5（DPO 的 LoRA），$\beta=0.1$ 起步，偏好对 1~5 万条即可见效；
5. 若有第二张卡或多机，换 DeepSpeed ZeRO-3 + offload 可上更大 rank 或全参。

---

### Q9（进阶）: 同一个底座要支持 20 个客户的私有音色/领域模型，架构上怎么设计？

**答**：
「一个底座 + 多租户 LoRA 插件」：底座统一部署（可量化 INT8/4bit），每个客户一份 LoRA 权重（几十 MB，r=8~16，仅用其 5~30 分钟音频训练）；推理侧按请求路由加载对应 adapter（peft 支持多 adapter 热切换，或 merge 后多实例）。好处：存储/迭代成本线性降低、底座升级所有客户共享、客户数据物理隔离（LoRA 权重可私有存储）。对比全参方案：20 份 14GB 拷贝不可接受。面试延伸点：多 adapter 之间的干扰与正交性（可用不同随机种子初始化 A 增大子空间差异）。

---

### Q10: SFT 之后跑 DPO，发现 chosen 与 rejected 的隐式奖励差（margin）持续上升，但人工听起来没有变好，问题出在哪？

**答**：
典型的 DPO 过拟合 / 偏好数据信号泄漏：
1. **偏好对构造有系统性偏差**：例如 rejected 全部来自「注入缺陷」的构造样本（降采样/加噪），模型学到的是「检测缺陷」而非「说得更像人」，在真实分布上无效--检查偏好对来源多样性；
2. **margin 上升 ≠ 真实偏好改善**：DPO 可以无限拉开似然比（IPO 称之为 overfitting 现象），但人工感知存在天花板--监控人工侧评（小规模 AB test）而非只看训练指标；
3. **chosen 概率同时在下降**：DPO 已知现象（both go down，只 rejected 降得更快），隐式奖励上升主要靠压制 rejected--检查 chosen 的绝对 logprob 曲线，若下降明显则偏好数据噪声大或 $\beta$ 过小；
4. **对齐税**：KL 距离过大导致基础能力（WER、指令跟随）退化--升 $\beta$、减少 epoch、或换 IPO/KTO 正则更稳的变体。

## 6. 总结

* **范式选型三轴**：数据量（小时/万条）、算力（卡数/显存）、任务性质（知识注入 vs 行为对齐）--全参用于底座与大规模知识注入，PEFT 用于定制与插件化，RLHF/DPO 用于偏好对齐，三者常组合成流水线。
* **三大推导必须熟练**：RVQ（残差级联 + bitrate 公式 $B = F\cdot n\cdot\log_2 K$ + collapse/EMA）、DPO（四步闭式推导、$Z(x)$ 消去）、LoRA（低秩假设、$B=0$ 初始化、参数量 $r(d_{in}+d_{out})$、合并部署）。
* **工业界实战主题**：数据配比按 loss 均衡动态调整（保留 20%+ 纯文本）、防遗忘优先 Replay、loss 尖刺 80% 查数据、DPO 防 hacking 靠数据清洗与正则变体。
* **工程底座**：BF16 混合精度、gradient checkpointing、FSDP/ZeRO、bucketing、checkpoint 策略--这些「常识」正是面试区分度所在。

# 1. 语音Tokenizers与Neural Audio Codec

## 1. 概述

**Neural Audio Codec（神经音频编解码器）** 是将连续音频信号压缩为**离散 token 序列**、并能在解码端高质量还原音频的模型。它由 Encoder、量化器（Quantizer）与 Decoder 三部分组成，训练目标通常是「重构损失 + 感知损失 + 对抗损失 + 量化约束」的组合。

在 LLM 时代，Neural Audio Codec 的价值远超「压缩」本身：它把语音变成了 LLM 可以处理的**离散词表**，是 Speech-LLM（AudioPaLM、Spectron、VALL-E、Qwen-Audio 系列）与全双工语音对话（Moshi、GLM-4-Voice）的基石。与之配套的两个概念：

* **Acoustic tokens（声学 token）**：由 codec 的 RVQ 码本产生，保留音色、韵律、环境声等细粒度信息，帧率高（如 75Hz）。
* **Semantic tokens（语义 token）**：通常由自监督模型（HuBERT/w2v-BERT）中间层表征做 K-means 聚类得到，保留内容与语义，帧率低（如 25~50Hz），但丢失音色。

典型代表工作：**SoundStream（Google, 2021）** 首次提出 RVQ + 对抗训练的 codec 范式；**EnCodec（Meta, 2022）** 开源了该范式的标准实现；**DAC（Descript Audio Codec, 2023）** 将音质推向接近透明（PESQ/VisQ 大幅提升）；**SpeechTokenizer（2023）** 与 **SemanticCodec（2024）** 则尝试把语义信息蒸馏进 codec token，模糊 semantic/acoustic 二分边界。

## 2. 核心架构：Encoder - Quantizer - Decoder

### 2.1 整体架构

```
                        ┌─────────────────────────────────────────────┐
                        │              Neural Audio Codec             │
                        │                                             │
  Waveform x ∈ R^L ───> │  ┌─────────┐   ┌──────────┐   ┌─────────┐  │ ───> 重建波形 x̂
  (24kHz, L 采样点)     │  │ Encoder │──>│   RVQ    │──>│ Decoder │  │      (24kHz)
                        │  │ (SEANet)│   │ Q1..Qn 级│   │ (SEANet)│  │
                        │  └─────────┘   └──────────┘   └─────────┘  │
                        │       │              │             ▲        │
                        │       │         离散 token          │        │
                        │       │      [n, T/stride]         │        │
                        │       │              │      STFT/L1/L2 +    │
                        │       │              └──── Multi-Scale      │
                        │       │                 STFT Discriminator  │
                        │       │                 + MSD + RVD         │
                        │       └── Commit Loss (VQ 约束)              │
                        └─────────────────────────────────────────────┘

  下采样: stride = 320 (24kHz 音频 => 75Hz 帧率)
  RVQ:    n = 8 层码本, 每层 K = 1024 个码字, 维度 d = 128
  Bitrate = 75 × 8 × log2(1024) = 6000 bps = 6 kbps
```

### 2.2 Encoder / Decoder：SEANet 卷积组

Encoder 与 Decoder 是镜像结构的**一维卷积栈**（又称 SEANet / ConvNet），每级包含「下采样卷积 + 若干 Residual Block（含 Dilated Depthwise Conv 与 SE 通道注意力）」：

* **Encoder**：`stride=2` 的下采样卷积级联。例如 4 级 `[2,4,5,8]`，总 stride = 320，把 24kHz 波形压成 75Hz 的隐帧序列，通道从 1 升到 128（或 512）。
* **Decoder**：转置卷积逐级上采样还原波形，最后输出单通道音频（或配合 tanh 归一）。

关键点：**总 stride 决定帧率**，帧率 = 采样率 / 总 stride。24kHz / 320 = 75Hz（EnCodec、SoundStream 基础配置）；Moshi 用 12.5Hz（stride 1600，12Hz 实为 40ms/帧）；部分 Speech-LLM 为省 token 改用 50Hz（stride 480）。

### 2.3 训练目标

$$\mathcal{L} = \lambda_{rec}\,\mathcal{L}_{rec} + \lambda_{adv}\,\mathcal{L}_{adv} + \lambda_{feat}\,\mathcal{L}_{feat} + \lambda_{commit}\,\mathcal{L}_{commit}\ (+\ \lambda_{se}\,\mathcal{L}_{sem})$$

| 损失项 | 形式 | 作用 |
| --- | --- | --- |
| $\mathcal{L}_{rec}$ | 时域 L1 + 多分辨率 STFT（L1/L2 谱损失） | 频谱重构，保住共振峰结构 |
| $\mathcal{L}_{adv}$ | 多尺度 STFT 判别器（MPD/MS-STTD/MSD）+（DAC）**RVD 随机量化判别器** | 提升感知音质，消除过度平滑 |
| $\mathcal{L}_{feat}$ | 判别器中间特征匹配损失（Feature Matching） | 稳定 GAN 训练 |
| $\mathcal{L}_{commit}$ | VQ 的 codebook loss / commitment loss | 约束编码向量贴近码字 |
| $\mathcal{L}_{sem}$ | （SpeechTokenizer）第一层 RVQ 与 HuBERT 表征做余弦蒸馏 | 注入语义信息 |

## 3. RVQ（Residual Vector Quantization）原理与推导

### 3.1 单层 VQ 回顾

给定连续隐帧 $z_t \in \mathbb{R}^{d}$ 与码本 $\mathcal{C} = \{c_1, \dots, c_K\}$，VQ 做最近邻查找：

$$q(z_t) = c_{k^*}, \quad k^* = \arg\min_{k} \Vert z_t - c_k \Vert_2$$

训练损失（Straight-Through Estimator，梯度直通）：

$$\mathcal{L}_{VQ} = \Vert \text{sg}[z_t] - c_{k^*}\Vert_2^2 + \beta\,\Vert z_t - \text{sg}[c_{k^*}]\Vert_2^2$$

* 第一项（codebook loss）：把码字拉向编码器输出，实践中用 **EMA 更新**而非梯度；
* 第二项（commitment loss）：约束编码器输出不要频繁跳离码字，$\beta$ 常取 0.25。

### 3.2 RVQ 级联量化

单层 VQ 的表达能力受限于 $K$。要达到高 bitrate 需要 $K$ 指数级增长，因此 SoundStream 引入**残差级联**：用 $n$ 个小码本逐层量化残差。

$$r_t^{(0)} = z_t, \quad k_i = \arg\min_k \Vert r_t^{(i-1)} - c_k^{(i)} \Vert_2, \quad r_t^{(i)} = r_t^{(i-1)} - c_{k_i}^{(i)}$$

$$\hat{z}_t = \sum_{i=1}^{n} c_{k_i}^{(i)}, \qquad \text{tokens}(t) = [k_1, k_2, \dots, k_n]$$

即：第 $i$ 层码本负责刻画前 $i-1$ 层没能覆盖的残差，层数越深补的细节越细（第 1 层最「粗」接近语义/能量包络，越往后越细到相位与噪声纹理）。**每层只传 1 个索引**，$n$ 层 RVQ 每帧输出 $n$ 个 token。

**误差上界**：设每层量化误差为 $\epsilon_i = \Vert r^{(i-1)} \Vert \cdot \rho_i$（$\rho_i$ 为该层相对量化失真），总误差满足

$$\Vert z_t - \hat{z}_t \Vert_2 = \Vert r_t^{(n)} \Vert_2 \le \prod_{i=1}^{n} \rho_i \cdot \Vert z_t \Vert_2 \quad (\rho_i < 1 \text{ 时指数衰减})$$

这解释了为什么「多层小码本」远优于「单层大码本」：指数级容量 vs 线性级开销。

### 3.3 Bitrate 计算公式

$$\text{Bitrate} = F_{frame} \times n \times \log_2 K \quad \text{bps}$$

| 配置 | 帧率 $F$ | 层数 $n$ | 码本 $K$ | Bitrate |
| --- | --- | --- | --- | --- |
| EnCodec 24kHz base | 75 Hz | 2 | 1024 | 1.5 kbps |
| EnCodec 24kHz base | 75 Hz | 8 | 1024 | 6 kbps |
| EnCodec 24kHz base | 75 Hz | 32 | 1024 | 24 kbps |
| SoundStream 3kbps | 50 Hz | 4 | 1024 | 3 kbps（训练时用更多层做 dropout） |
| DAC 44kHz | 86 Hz | 9 | 1024 | 8 kbps |
| Mimi (Moshi) | 12.5 Hz | 8+1 | 2048 | 1.1 kbps（12.5×8×11 + 语义 12.5×11） |

> **面试要点**：SoundStream 训练时对 RVQ 层做 **quantizer dropout**（随机只用前 $n'$ 层），使单个模型支持可变 bitrate（3~18kbps），推理时按带宽预算截断层数即可，无需重训。

### 3.4 Codebook Collapse 与 EMA 更新

**现象**：GAN 对抗训练下，VQ 极易发生 **codebook collapse**——绝大多数帧只命中少数几个码字（如 1024 个码字只有 <100 个活跃），量化容量骤降、音质崩坏；极端情况是所有输出塌到同一码字。

**EMA（指数滑动平均）更新**：不经过梯度，直接统计每个码字的命中加权均值：

$$N_k^{(t)} = \gamma N_k^{(t-1)} + n_k, \quad m_k^{(t)} = \gamma m_k^{(t-1)} + \sum_{j: k_j^* = k} z_j$$

$$c_k \leftarrow \frac{m_k^{(t)}}{N_k^{(t)}}, \quad \gamma \approx 0.99$$

配合 **dead code 重置**（若某码字长时间未命中，用 batch 内随机编码向量覆盖，DAC 用 `dead_code_threshold`/随机 restart），可将活跃码字比例维持在 >95%。

**其他缓解手段**：

1. **码本归一化 / whitening**（如 improved VQ diffusion 的 affine 归一化）；
2. **随机重启 + codebook 熵正则**（鼓励命中分布均匀，熵最大化）；
3. **LFQ（Lookup-Free Quantization，MAGLEV/SpeechSemantic）**：直接对每一维做二值化签名，绕开码本查找，天然无 collapse；
4. **EMA decay 调度**：训练早期 $\gamma$ 小（更新快），后期调大（稳定）。

## 4. 代表性模型对比：SoundStream / EnCodec / DAC / SpeechTokenizer / SemanticCodec

### 4.1 SoundStream（Google, 2021）

* 首个「ConvNet + RVQ + 对抗训练」端到端 codec，在 3kbps 上超过 Opus/EVS 等传统编解码器（MUSHRA 评分）；
* 贡献三件套：**quantizer dropout（可变 bitrate）**、**多尺度判别器**、**SEANet 结构**，后续工作几乎全部沿用。

### 4.2 EnCodec（Meta, 2022）

* 开源（`facebookresearch/encodec`），24kHz/48kHz 两个版本；48kHz 版支持立体声与 MS-STFT 判别器；
* 训练加 **LSTM（双向）** 于 encoder/decoder 顶部、**balancer** 机制动态调权各损失梯度范数；
* 在 AudioLM/VALL-E/MusicLM 中被广泛用作 acoustic tokenizer（本仓库 VALL-E 笔记同款底座）。

### 4.3 DAC / Descript Audio Codec（2023）

定位「高保真通用 codec」，核心改进：

1. **周期性判别器**与 **MS-STTD**（对数尺度多分辨率 STFT 判别器）替代 MSD；
2. **RVD（Random Quantizer Dropout）**：训练时对 RVQ 随机丢弃部分层再送判别器，强迫各层残差自洽、抑制 artifacts（如嘶嘶声、金属感）；
3. **蛇形激活 Snake activation**（$\sin$ 周期激活）替代 ReLU/ELU，显著改善周期信号（音乐/语音谐波）建模；
4. **大规模训练数据 + 强增广**（混响/带宽/编解码仿真链），44.1kHz 下 8kbps 即可接近透明音质。

### 4.4 SpeechTokenizer（2023）与 SemanticCodec（2024）

* **SpeechTokenizer**：在 RVQ 第 1 层引入 HuBERT 表征蒸馏（余弦相似度损失 + 蒸馏权重调度），使**第一层 RVQ token 直接承载语义**，后续层补声学细节。效果：单用第 1 层 token 做 ASR/语义任务接近 HuBERT K-means token；全层用于 TTS 兼顾音色。
* **SemanticCodec（2024）**：极端路线——先用极深 RVQ（如 4096 个语义码字 × 若干层）编码语义，再接一个 **acoustic codec 将 semantic token 映射为 EnCodec token / 波形**。语义码本大（数千），保证语义离散度（避免同音塌缩），对 TTS 的内容保真与 zero-shot 音色克隆更友好。

### 4.5 综合对比表

| 模型 | 年份 | 采样率 | 帧率 | RVQ 层×码本 | Bitrate | 特点 |
| --- | --- | --- | --- | --- | --- | --- |
| SoundStream | 2021 | 24kHz | 50 Hz | 4~75 × 1024 | 3~18 kbps | quantizer dropout、开山之作 |
| EnCodec | 2022 | 24/48kHz | 75 Hz | 2~32 × 1024 | 1.5~24 kbps | 开源标准件、AudioLM/VALL-E 底座 |
| DAC | 2023 | 24/44.1kHz | 86 Hz | 9 × 1024 | 4~8 kbps | RVD、Snake 激活、近透明音质 |
| SpeechTokenizer | 2023 | 16kHz | 50 Hz | 8 × 1024 | 4 kbps | 第 1 层语义蒸馏、语义/声学统一 |
| Mimi (Moshi) | 2024 | 24kHz | 12.5 Hz | 8 × 2048 + 语义 | ~1.1 kbps | W2v-BERT 蒸馏 + Split RVQ、低帧率全双工 |
| SemanticCodec | 2024 | 16/24kHz | — | 深层语义 RVQ | — | 语义码本极大化、TTS 内容保真 |

## 5. Semantic vs Acoustic Tokens

### 5.1 Semantic tokens：HuBERT K-means

对 HuBERT（或 w2v-BERT）第 7~9 层（经验最优层）输出逐帧做 K-means 聚类（$K=500 \sim 1000$，GPT-SSL/AudioLM 常用 500~8192）：

$$s_t = \arg\min_{k} \Vert h_t^{(l)} - \mu_k \Vert_2, \quad h_t^{(l)} = \text{HuBERT}_l(x)_t$$

* 优点：帧率低（HuBERT 20ms/帧，若再 2 倍下采样即 25~50Hz）、token 分布更「语言化」，适合 LLM 建模语义；
* 缺点：**丢失音色、能量、情感**，无法从 semantic token 恢复说话人，必须级联声学 vocoder。

### 5.2 双流建模与融合趋势

```
AudioLM 方案（双流）:
  Audio ─> [HuBERT + K-means] ─> semantic tokens  ─> LM (内容) 
                                     │ (作为 prompt)
                                     ▼
          ─> [EnCodec RVQ] ─────> acoustic tokens ─> LM (音色细节)

SpeechTokenizer / Mimi 方案（单流）:
  Audio ─> [Codec + 语义蒸馏到第1层RVQ] ─> [语义层, 声学层...] ─> 单一 LLM 统一建模
```

单流（unified token）的优势：一个 LLM 同时管理解与生成，延迟低（Moshi 全双工 <200ms）；代价是语义层的表达能力被码本尺寸与蒸馏质量卡住。

### 5.3 选型建议（TTS / 理解任务）

| 任务 | 推荐 token 方案 | 理由 |
| --- | --- | --- |
| ASR / SLU / 语音翻译（理解） | HuBERT K-means semantic；或 codec 第 1 层（SpeechTokenizer） | 丢音色换语义密度、序列短 |
| TTS / 语音克隆 | EnCodec/DAC acoustic（8 层以上）+ 语义条件 | 需要音色/韵律/环境细节 |
| 全双工语音对话 | Mimi 式单流低帧率（12.5Hz） | 序列长度可控、双工延迟 |
| 音乐 / 通用音频 | DAC / EnCodec（高帧率高层数） | 谐波与立体声细节要求高 |

## 6. 关键权衡：码本大小 / 层数 / 帧率

### 6.1 三者关系

固定 bitrate 预算 $B = F \cdot n \cdot \log_2 K$ 下的三方权衡：

* **帧率 $F$ 高**（75Hz）：音质与时间分辨率好，但 LLM 侧序列长（1 分钟音频 = 4500 帧 × n 层 = 3.6 万 token，KV-Cache 爆炸）；
* **帧率低**（12.5~25Hz）：序列短、对话友好，但 codec 需更强的序列建模（Mimi 在 RVQ 前插 Transformer 层）且流式延迟受帧长下限约束（12.5Hz 一帧 80ms）；
* **码本 $K$ 大**：单层容量大，但 K-means/VQ 查找与 codebook collapse 风险上升，embedding 表显存增大；
* **层数 $n$ 深**：残差更细、音质更高，但 LLM 解码要处理多码本（常flatten 或 delay pattern），序列等比变长。

### 6.2 75Hz vs 50Hz 的实际差异

* EnCodec 24kHz 原生 75Hz（stride 320），token 效率差；SpeechTokenizer 保持 75Hz 但蒸馏语义；**Moshi/Mimi 砍到 12.5Hz** 并用 Split RVQ（一半层并行、一半残差）把 8 层信息压进 12.5Hz；
* 工程经验：语音对话 LLM 帧率 **≤25Hz** 时，1 秒音频 ≤25×n 个 token，可在单卡 A100 上做到实时全双工；75Hz 通常只用于离线 TTS。

## 7. PyTorch 代码实战：RVQ 前向与 EMA 更新

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class ResidualVQ(nn.Module):
    """多层残差向量量化 (RVQ)，含 EMA 码本更新与死码重启。"""
    def __init__(self, dim=128, codebook_size=1024, num_quantizers=8, decay=0.99, eps=1e-5):
        super().__init__()
        self.dim, self.K, self.n = dim, codebook_size, num_quantizers
        self.decay, self.eps = decay, eps
        # 码本初始化: 均匀分布 + L2 归一化, 避免初始塌缩
        emb = torch.randn(num_quantizers, codebook_size, dim)
        self.register_buffer("codebook", F.normalize(emb, dim=-1))
        # EMA 统计量
        self.register_buffer("ema_cluster_size", torch.zeros(num_quantizers, codebook_size))
        self.register_buffer("ema_embed_sum", emb.clone())

    def forward(self, z):
        """
        z: [B, T, dim]  Encoder 输出
        return: 量化输出 z_q [B,T,dim], tokens [B,T,n], commit_loss
        """
        residual = z
        z_q, tokens, commit_loss = 0.0, [], 0.0
        for i in range(self.n):
            cb = self.codebook[i]                              # [K, dim]
            # 最近邻查找 (cosine 距离)
            dist = torch.cdist(residual.unsqueeze(2), cb.unsqueeze(0)).squeeze(2)  # [B,T,K]
            idx = dist.argmin(dim=-1)                          # [B,T]
            q = F.embedding(idx, cb)                           # [B,T,dim]
            # EMA 更新 (仅训练时)
            if self.training:
                with torch.no_grad():
                    onehot = F.one_hot(idx, self.K).float()    # [B,T,K]
                    n_k = onehot.sum(dim=(0, 1))               # [K]
                    embed_sum = torch.einsum("btk,btd->kd", onehot, residual)
                    self.ema_cluster_size[i].mul_(self.decay).add_(n_k, alpha=1 - self.decay)
                    self.ema_embed_sum[i].mul_(self.decay).add_(embed_sum, alpha=1 - self.decay)
                    # Laplace 平滑 + EMA 码字更新
                    N = self.ema_cluster_size[i].clamp(min=1e-5)
                    self.codebook[i] = self.ema_embed_sum[i] / N.unsqueeze(-1)
                    # 死码重启: 命中数过低的码字用 batch 内随机向量覆盖
                    dead = self.ema_cluster_size[i] < self.eps * self.K
                    if dead.any():
                        rand_vec = residual.reshape(-1, self.dim)[torch.randperm(residual.numel() // self.dim)[:dead.sum()]]
                        self.codebook[i][dead] = F.normalize(rand_vec, dim=-1)
            # 残差级联 + commitment loss + 梯度直通 (straight-through)
            commit_loss = commit_loss + F.mse_loss(residual, q.detach())
            q_st = residual + (q - residual).detach()          # 前向用 q, 反向梯度直通 residual
            z_q = z_q + q_st
            tokens.append(idx)
            residual = residual - q.detach()
        return z_q, torch.stack(tokens, dim=-1), commit_loss / self.n

class SimpleCodec(nn.Module):
    """最小可训练 codec 骨架 (生产实现参考 encodec/dac 官方库)。"""
    def __init__(self, dim=128, stride=320):
        super().__init__()
        self.encoder = nn.Sequential(
            nn.Conv1d(1, 32, kernel_size=7, padding=3),
            *[nn.Conv1d(32, dim, kernel_size=4, stride=s, padding=s // 2) for s in (2, 4, 5, 8)],  # stride=320
        )
        self.rvq = ResidualVQ(dim=dim, codebook_size=1024, num_quantizers=8)
        self.decoder = nn.Sequential(
            *[nn.ConvTranspose1d(dim, 32, kernel_size=4, stride=s, padding=s // 2) for s in (8, 5, 4, 2)],
            nn.Conv1d(32, 1, kernel_size=7, padding=3), nn.Tanh(),
        )

    def forward(self, wav):  # wav: [B, 1, L]
        z = self.encoder(wav).transpose(1, 2)         # [B, T, dim], T = L/320
        z_q, tokens, commit = self.rvq(z)
        rec = self.decoder(z_q.transpose(1, 2))       # [B, 1, L]
        return rec, tokens, commit

if __name__ == "__main__":
    model = SimpleCodec()
    wav = torch.randn(2, 1, 24000)                    # 2 条 1 秒 24kHz 音频
    rec, tokens, commit = model(wav)
    print(f"重建波形: {rec.shape}")                    # [2, 1, 24000]
    print(f"token 序列: {tokens.shape}")               # [2, 75, 8] => 75Hz × 8 层
    print(f"commitment loss: {commit.item():.4f}")
    # bitrate 校验: 75 Hz × 8 层 × 10 bit = 6000 bps
    print(f"bitrate = {75 * 8 * 10} bps")
```

## 8. 高频面试要点速查

* **为什么用 RVQ 而不是单层大 VQ？** 指数容量 vs 线性开销；每层只补残差、可截断实现可变 bitrate；层数即质量旋钮。
* **EnCodec 与 DAC 的本质区别？** DAC 用 RVD（随机量化层 dropout 进判别器）+ Snake 周期激活 + 更强判别器组合，显著压低 artifacts（嘶声/金属感）；EnCodec 是更早的通用开源基线。
* **codec token 能直接做 ASR 吗？** 原生 EnCodec token 语义弱（第 1 层含部分语义）；SpeechTokenizer/Mimi 通过蒸馏让第 1 层接近 HuBERT K-means 的语义水平。
* **codebook collapse 怎么发现？** 监控每层码字命中直方图/活跃码字比例（perplexity of token usage）；健康状态活跃比例 >90%，低于 50% 需介入（EMA、重启、LFQ）。
* **怎么把 8 层 token 喂给 LLM？** flatten（帧内层拼接成 8 个连续 token）、delay pattern（第 i 层延迟 i 步，Moshi/GPT-4o 疑似方案）、或独立 embedding 相加（早期 AudioLM hierarchical 方式）。

## 9. 总结与最佳实践

* **范式统一**：SoundStream 确立的「SEANet ConvNet + RVQ + 多判别器 GAN + commitment loss」是所有现代 codec 的模板；DAC 强化判别器与激活函数，SpeechTokenizer/Mimi 用语义蒸馏统一 semantic-acoustic 双流。
* ** bitrate 心法**：$B = F \times n \times \log_2 K$；语音对话选低帧率（12.5~25Hz）+ 中等层数，离线高保真 TTS/音乐选高帧率 + 深层 RVQ（DAC）。
* **训练稳定性三板斧**：EMA 码本更新 + 死码重启 + 损失 balancer（EnCodec 式梯度范数均衡）；collapse 监控指标是活跃码字比例。
* **工程落地**：理解任务优先 semantic（或蒸馏第 1 层）；生成任务优先 acoustic；全双工对话走单流低帧率 + delay pattern。

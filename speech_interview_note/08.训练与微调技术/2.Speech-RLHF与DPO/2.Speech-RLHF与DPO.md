# 2. Speech-RLHF与DPO

## 1. 概述

RLHF（Reinforcement Learning from Human Feedback）通过「人类偏好信号 -> 奖励模型 -> 策略优化」三段式流程，把模型输出对齐到人类主观偏好。它在 LLM（InstructGPT/ChatGPT）上的成功自然延伸到语音领域，但语音的偏好是**多维的**：内容正确性之外，还有音质（naturalness）、说话人相似度（speaker similarity）、情感韵律（prosody/emotion）、延迟，以及语音特有的**幻觉**（重复、漏读、插字、跳读）。

语音场景的对齐目标可形式化为：

$$\theta^* = \arg\max_\theta\; \mathbb{E}_{x \sim \mathcal{D},\, y \sim \pi_\theta(\cdot \mid x)} \big[ r(x, y) \big] - \beta\, \mathbb{D}_{KL}\big[\pi_\theta(\cdot\mid x)\,\Vert\,\pi_{\text{ref}}(\cdot\mid x)\big]$$

其中 $x$ 为提示（文本 prompt 或语音 prompt），$y$ 为生成的语音（或语音 token 序列），$\pi_{\text{ref}}$ 为 SFT 初始策略，KL 惩罚防止策略漂移破坏语音自然度。

本文覆盖：LLM RLHF 流程回顾（SFT -> RM -> PPO）、语音偏好特殊性、RLHF 在 TTS/语音对话上的应用（SpeechAlign、RLHF for TTS 等）、**DPO 从 RLHF 目标到闭式解的完整推导**、语音偏好数据构建、奖励模型设计（speaker sim + MOS 预测器 + LLM judge）。

## 2. LLM RLHF 流程回顾：SFT -> RM -> PPO

### 2.1 三阶段流水线

```
┌──────────────┐    ┌──────────────────┐    ┌─────────────────────────────┐
│ Stage 1: SFT │───>│ Stage 2: RM 训练 │───>│ Stage 3: PPO 强化学习       │
│ 监督微调     │    │ (y_w, y_l) 对比  │    │ policy = SFT 模型 (冻结副本 │
│ 通用语料     │    │ 偏好对 -> 打分   │    │         作为 ref/KL 锚点)   │
└──────────────┘    └──────────────────┘    └─────────────────────────────┘
      1~3 epochs        Bradley-Terry 损失      reward = RM(x,y) - β·KL(π‖π_ref)
```

**Stage 1（SFT）**：在高质量 `<指令, 回复>` 对上做 next-token prediction，赋予模型基础指令跟随与格式能力。

**Stage 2（Reward Model）**：同一 prompt 采样多个回复，人工标注偏好对 $(y_w \succ y_l)$（chosen vs rejected），用 **Bradley-Terry 模型**训练打分头：

$$\mathcal{L}_{RM} = -\mathbb{E}_{(x, y_w, y_l)}\left[ \log \sigma\big(r(x, y_w) - r(x, y_l)\big) \right]$$

**Stage 3（PPO）**：把 LM 视作策略 $\pi_\theta(y \mid x)$，最大化奖励同时用 KL 约束偏移：

$$\mathcal{L}_{PPO} = \mathbb{E}\Big[ \min\big(\rho_t A_t,\; \text{clip}(\rho_t, 1-\epsilon, 1+\epsilon) A_t \big) \Big], \quad \rho_t = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{old}(a_t \mid s_t)}$$

$$R(x, y) = r_{RM}(x, y) - \beta \big(\mathbb{D}_{KL}[\pi_\theta \Vert \pi_{ref}]\big)$$

其中 $A_t$ 为 GAE 估计的优势函数。工程上需要 4 份模型同时在显存：policy（训练）、ref（冻结）、RM（冻结）、value（训练），开销巨大。

### 2.2 PPO 的问题（DPO 的动机）

1. 实现复杂：采样、GAE、clip、KL 估计环环相扣，超参敏感（$\beta$, $\epsilon$, lr, KL coef）；
2. 显存与算力：4 模型并存，语音模型（含 codec + LLM）更是雪上加霜；
3. 奖励投机（reward hacking）：RM 打分高不等于人真的喜欢。

## 3. 语音对齐的特殊性：多维偏好

与文本对齐「有用/无害/真实」不同，语音偏好至少有 5 个正交维度，且**相互冲突**：

| 偏好维度 | 主观指标 | 客观代理指标 | 冲突点 |
| --- | --- | --- | --- |
| 内容正确性 | 听写准确率 | WER/CER（把生成语音过 ASR 与参考比对） | 与音质无关，漏读/插字/幻觉直接拉高 WER |
| 音质自然度 | MOS (1~5 分) | PESQ / ViSQOL / UTMOS（神经 MOS 预测） | 高采样率、高码率 codec 利好音质 |
| 说话人相似度 | SMOS (AB test) | speaker embedding 余弦相似度（ECAPA/Resemblyzer） | 克隆音色 vs 平均化出「安全音」 |
| 情感韵律 | EMOS / CMOS | 情感分类一致率、F0 相关系数 | 情感夸张常牺牲相似度与可懂度 |
| 幻觉/稳定性 | 人工计数 | 重复 n-gram 率、跳读率、时长比（生成/参考） | 高温采样利多样性但诱发重复 |

**语音幻觉（TTS hallucination）的典型形态**：长静音/标点密集处重复短语、数字与符号读错、多音字错误、跨句跳读或漏读、口吃式卡顿。这些在纯客观指标（如 speaker sim）下不可见，必须进偏好维度。

因此语音 RM 通常不是单一标量头，而是**多目标加权**（见第 6 节）：

$$r(x, y) = w_1 r_{ASR}(x,y) + w_2 r_{MOS}(y) + w_3 r_{sim}(x,y) + w_4 r_{emo}(x,y) + w_5 r_{stable}(y)$$

## 4. RLHF 在 TTS / 语音对话上的应用

### 4.1 RLHF for TTS（MOS 驱动微调）

早期路线：训练一个**神经 MOS 预测器**（如 UTMOS、MOSNet，输入语音输出 1~5 分预测）作为可微/可查询的代理奖励，对 TTS 系统做 RL 微调（PPO 或更简单的策略梯度 REINFORCE）：

* 奖励：$r(y) = \widehat{MOS}(y) + \lambda \cdot \text{sim}(y, x_{ref}) - \mu \cdot \text{WER}(y)$；
* 策略：TTS 的自回归 token 生成（如 VALL-E 的 codec language model）逐 token 采样，episode 结束算总奖励；
* 效果：在少量数据上可把 MOS 提升 0.1~0.3，同时必须挂 KL 锚，否则模型学会「说短句骗 WER、压嗓门骗 MOS」等投机行为。

### 4.2 SpeechAlign（2023/2024）

微软提出的语音大模型对齐框架，核心思想与 InstructGPT 平移到语音：

1. 用多任务语音指令数据（ASR/TTS/翻译/情感识别等）做 SFT；
2. 人工/模型构造语音偏好对（同一指令下两种响应语音，按内容正确+音质+风格标注胜负）；
3. 训练语音 RM + PPO/SLiC 式偏好优化，对齐后的 SpeechLLM 在指令跟随与零样本任务上显著提升。

其贡献在于验证：**偏好优化可统一用于语音的理解与生成双任务**，且 RM 可由「ASR 转写 + 文本 RM」复合构造，降低标注成本。

### 4.3 语音对话全双工对齐（Moshi / GLM-4-Voice 路线）

全双工语音对话的 RLHF 关键差异：

* **动作空间是流式 token**（Mimi codec + 文本 token 交织），奖励必须考虑**轮次级**（打断是否得体、回答是否切题）而非句级；
* 延迟本身是偏好维度（回复太快抢话、太慢呆滞），reward 里加入 turn-taking 合理性项；
* 常用两段式：先对齐底层文本 LLM（标准 RLHF/DPO），再用 SFT + 轻量 DPO 对齐「文本 -> 语音」的韵律与风格，避免在高维语音 token 空间直接跑 PPO。

### 4.4 路线对比表

| 方案 | 奖励来源 | 优化算法 | 适用场景 | 成本 |
| --- | --- | --- | --- | --- |
| RLHF for TTS（MOS 驱动） | 神经 MOS 预测器 + speaker sim | PPO / REINFORCE | TTS 音质提升 | 中（RM 便宜，策略训练贵） |
| SpeechAlign | 人工+模型复合偏好 -> 语音 RM | PPO / 偏好损失 | SpeechLLM 多任务对齐 | 高 |
| DPO（语音版） | 偏好对（无需 RM 在线打分） | 闭式偏序损失 | TTS/Speech-LLM 主流 | 低（只需 policy + ref） |
| 两段式（文本先对齐） | 文本 RM -> 语音 SFT/DPO | DPO + SFT | 全双工语音对话 | 中 |

## 5. DPO 原理推导：从 RLHF 目标到闭式解

### 5.1 起点：KL 约束的奖励最大化

$$\max_{\pi_\theta}\; \mathbb{E}_{y \sim \pi_\theta}\big[r(x, y)\big] - \beta\, \mathbb{D}_{KL}\big[\pi_\theta(y\mid x)\,\big\Vert\,\pi_{ref}(y\mid x)\big]$$

### 5.2 第一步：最优策略的闭式表达

对该约束优化问题写拉格朗日函数并求变分导数为零，可得最优解：

$$\pi^*(y \mid x) = \frac{1}{Z(x)}\, \pi_{ref}(y \mid x)\, \exp\!\Big(\frac{1}{\beta} r(x, y)\Big), \quad Z(x) = \sum_y \pi_{ref}(y \mid x) \exp\!\Big(\frac{r(x,y)}{\beta}\Big)$$

（$Z(x)$ 是配分函数，与 $\theta$ 无关但难以计算。）

### 5.3 第二步：用最优策略反解奖励

对上式取对数并移项，把 $r$ 用 $\pi^*$ 表示：

$$r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{ref}(y \mid x)} + \beta \log Z(x)$$

### 5.4 第三步：代入 Bradley-Terry 消去 $Z(x)$

BT 模型只关心奖励**差值**：

$$p(y_w \succ y_l \mid x) = \sigma\big(r(x, y_w) - r(x, y_l)\big)$$

将第二步的 $r$ 代入，$\beta \log Z(x)$ 在相减时**完全抵消**：

$$p(y_w \succ y_l \mid x) = \sigma\Big(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{ref}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{ref}(y_l \mid x)}\Big)$$

### 5.5 DPO 损失函数

于是得到**无需 RM、无需 PPO 采样**的偏序损失：

$$\boxed{\;\mathcal{L}_{DPO} = -\mathbb{E}_{(x, y_w, y_l)}\left[ \log \sigma\Big(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{ref}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{ref}(y_l \mid x)}\Big) \Big) \right]}$$

梯度（隐式奖励模型解释）：

$$\nabla_\theta \mathcal{L}_{DPO} = -\beta\, \mathbb{E}\Big[ \underbrace{\sigma(\hat{r}_l - \hat{r}_w)}_{\text{胜负判错程度}} \Big( \nabla_\theta \log \pi_\theta(y_w \mid x) - \nabla_\theta \log \pi_\theta(y_l \mid x) \Big) \Big]$$

其中隐式奖励 $\hat{r} = \beta \log \frac{\pi_\theta}{\pi_{ref}}$。直觉：判错越离谱（$\sigma(\hat{r}_l - \hat{r}_w)$ 越大），对 chosen 的上推与对 rejected 的下压越强。

**语音落地注意**：$y$ 是语音 token 序列（如 codec token + delay pattern），$\log \pi_\theta(y\mid x)$ 就是 LLM 头上的序列 log-likelihood；ref 模型即 SFT 后冻结的初始 policy，前向一次记录 logprob 即可，训练显存只需 policy + ref（且 ref 可用 LoRA 权重回滚近似，进一步省显存）。

### 5.6 DPO 变体速览

| 变体 | 改动 | 解决问题 |
| --- | --- | --- |
| IPO | $\log\sigma$ 换成 $(\hat{r}_w - \hat{r}_l - 1/\tau)^2$ | 过拟合偏好对、chosen 概率无限涨 |
| KTO | 只需 (样本, 好/坏标签)，无需成对 | 标注不成对场景（TTS 单样本打 MOS 很自然） |
| SimPO | 去掉 ref，用长度归一化 logprob 直接比 | 省显存、对长度偏置更稳 |
| R-DPO / length-regularized | 奖励中扣掉长度项 | 语音里对抗「短句骗 WER」 |

## 6. 语音偏好数据构建

### 6.1 AB 对比（MUSHRA / ABX 风格）

```
标注界面 (一条偏好样本的生成流程):
  prompt: 文本 "今天天气真不错" + 参考音频(音色/情感)
      ├─> 系统 A 生成 y_A ─┐
      └─> 系统 B 生成 y_B ─┴─> 听音人二选一 (或 7 分制: A 远好/略好/相当/...)
  
  质检: 每组混入 1 条金标准对 (已知优劣) 过滤乱标者
  每条数据至少 3 人标注, 取多数票 / Bradley-Terry 全局打分
```

* **规模量级**：LLM 对齐常用 10 万级偏好对；语音因标注贵（必须听），常见 1~10 万级，靠**模型构造偏好对**（下述）扩充。
* **构造式偏好对**：同一 TTS 用不同温度/seed 采样多条，按「复合客观分 + LLM judge」自动排序取首尾构造 $(y_w, y_l)$；或系统性注入缺陷（降采样、加噪、截断、错误多音字）作为 rejected--便宜但需防分布偏窄。

### 6.2 MOS / SMOS 主观测试规范

* **MOS（自然度）**：1~5 分，ITU-T P.800；正式测试每条 ≥20 听音人，95% 置信区间 ±0.15 以内才可信；
* **SMOS（相似度）**：与参考音色 ABX；
* **CMOS/DMOS**：对比式 MOS，比较两个系统的相对差，样本需求更小。

工程红线：论文/汇报中 MOS 必须报告听音人数、置信区间、是否 MUSHRA 正规流程，否则数字无意义（面试常考）。

## 7. 奖励模型设计：speaker sim + MOS 预测器 + LLM judge

```
                       ┌──────────────────────────────────────────┐
  prompt x, 生成语音 y │  r(x,y) = Σ w_i r_i                      │
                       ├──────────────────────────────────────────┤
                       │ r_ASR:    生成语音 -> ASR 转写 -> 与参考  │
                       │           文本算 WER/CER -> r = -CER     │
                       │ r_MOS:    UTMOS/神经MOS预测器 -> [1,5]    │
                       │ r_sim:    ECAPA-TDNN embedding 余弦      │
                       │           sim(spk(y), spk(x_ref))        │
                       │ r_stable: 重复率/时长比惩罚 -> [0,1]      │
                       │ r_judge:  ASR转写 + GPT-4级LLM 打分      │
                       │           (内容正确/指令跟随/安全性)      │
                       └──────────────────────────────────────────┘
  权重: 通常 w_ASR 最大 (内容错 = 一票否决), 量级示例:
        r = 5·r_ASR + 1·r_MOS + 2·r_sim + 1·r_stable + 3·r_judge
```

设计要点：

1. **r_ASR 一票否决**：内容错误（幻觉/漏读）在任何音质下都不可接受，故 WER 项权重最大或用乘法门控；
2. **各 r_i 先 z-score 归一**再加权，避免量纲不一导致某项主导；
3. **LLM judge**：语音先过 ASR 转文本，再让强 LLM 按 rubric 打分（正确性/完整性/风格跟随）；对「幻觉重复」类缺陷最敏感；
4. **防 hacking**：定期用人工偏好对回归测试 RM 与真实偏好的一致率（pairwise accuracy，健康值 70~75%+）；不一致率上升说明策略在投机。

## 8. 代码实战：语音 DPO 损失（PyTorch + HuggingFace TRL 风格）

```python
import torch
import torch.nn.functional as F

def dpo_loss(policy_logps, ref_logps, beta=0.1):
    """
    policy_logps: [B]  policy 模型对整条序列的 sum(log p)  (chosen 与 rejected 拼接后一次前向)
    ref_logps:    [B]  冻结 ref (SFT 初始模型) 的同款 logprob
    B = 2N, 前 N 条为 chosen, 后 N 条为 rejected
    """
    n = policy_logps.size(0) // 2
    pi_w, pi_l = policy_logps[:n], policy_logps[n:]        # log π(y_w|x), log π(y_l|x)
    rf_w, rf_l = ref_logps[:n], ref_logps[n:]
    # 隐式奖励: r̂ = β (log π_θ - log π_ref)
    logits = beta * ((pi_w - rf_w) - (pi_l - rf_l))         # [N]
    loss = -F.logsigmoid(logits).mean()
    # 监控指标
    with torch.no_grad():
        acc = (logits > 0).float().mean()                   # 偏好准确率
        margin = logits.mean()                              # chosen-rejected 隐式奖励差
    return loss, acc, margin

def sequence_logprob(model, input_ids, labels, loss_mask):
    """Speech-LLM 中 y 为 codec token 序列时的 log p(y|x) 计算。"""
    out = model(input_ids=input_ids).logits                 # [B, T, V]
    logps = torch.log_softmax(out[:, :-1].float(), dim=-1)
    tok_lp = logps.gather(-1, labels[:, 1:].unsqueeze(-1)).squeeze(-1)  # [B, T-1]
    return (tok_lp * loss_mask[:, 1:]).sum(dim=-1)          # 只对语音 token 位求和

# trainer = DPOTrainer(
#     model=speech_llm,                 # SFT 后的 Speech-LLM (ref 默认取其初始权重)
#     args=DPOConfig(beta=0.1, max_length=4096, max_prompt_length=1024),
#     train_dataset=preference_pairs,   # {"prompt": ..., "chosen": ..., "rejected": ...}
#     peft_config=peft_config,

if __name__ == "__main__":
    torch.manual_seed(0)
    B = 8
    # 模拟: policy 已比 ref 更偏好的 logprob
    policy_logps = torch.randn(2 * B)
    ref_logps = policy_logps - 0.3 * torch.randn(2 * B)
    loss, acc, margin = dpo_loss(policy_logps, ref_logps, beta=0.1)
```

## 9. 高频面试要点速查

* **DPO 为什么等价 RLHF？** 在 KL 约束奖励最大化的最优解中反解出 $r = \beta\log(\pi^*/\pi_{ref}) + \beta\log Z$，代入 BT 偏好概率时配分函数 $Z(x)$ 相减抵消，于是偏好概率只依赖策略与 ref 的似然比--RM 被策略本身「隐式」参数化。
* **DPO 一定要 ref 模型吗？** 标准式需要；SimPO 用长度归一化 logprob 去掉 ref；LoRA 场景可把 adapter 置零（`disable_adapter()`）当 ref，一份权重两用。
* **语音 RLHF 比文本难在哪？** 偏好多维且互相冲突；奖励多数不可微（MOS、speaker sim 需外部模型）；episode 是几千个 codec token 的长序列，credit assignment 难；标注必须「听」，数据贵一个量级。
* **怎么防 TTS 在 RL 中投机？** 多目标奖励（内容一票否决）+ KL 锚 + 长度/时长正则 + 定期人工偏好对回归测试 RM 一致率。

## 10. 总结与最佳实践

* **流程迁移**：LLM 的 SFT -> RM -> PPO 三段式可平移到语音，但奖励必须多维复合（内容 + 音质 + 相似度 + 稳定性），单一 MOS 奖励必然被 hack。
* **算法选型**：优先 DPO/其变体（成本低、稳定）；全双工对话先对齐文本层再对齐语音层；只在有强 RM 且 PPO 基建成熟时才上 PPO。
* **数据是壁垒**：人工 AB 偏好贵而准，模型构造偏好（采样 + 客观分排序 + LLM judge）便宜但分布窄，实践中以 1:5~1:10 配比混合。
* **评估闭环**：主观（MOS/SMOS/CMOS，报告人数与置信区间）+ 客观（WER、speaker sim COS、UTMOS、重复率）双轨制，RLHF/DPO 之后必须复测 KL 与基础能力（防对齐税）。

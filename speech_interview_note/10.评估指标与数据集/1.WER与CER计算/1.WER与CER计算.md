# 1. WER 与 CER 计算

## 1. 概述

**WER（Word Error Rate，词错率）** 与 **CER（Character Error Rate，字错率）** 是语音识别（ASR）领域最基础、使用最广泛的客观评估指标。二者本质上衡量的是同一件事：**识别假设（Hypothesis）与参考标注（Reference）之间的编辑距离（Levenshtein Distance）占参考文本长度的比例**。

* **WER**：以**词（Word）**为最小对齐单元，是英文等以空格分词语言的标准指标。
* **CER**：以**字符（Character/汉字）**为最小对齐单元，是中文、日文等无空格分词语言的标准指标。

在工业界与学术论文中，一条基本经验是：

* 英文 ASR 论文（如 Whisper、Conformer）通常报告 WER；
* 中文 ASR 论文与中文场景业务通常报告 CER；
* 中英混合场景则常同时报告 WER 与 CER，或以 CER 为主。

看似简单的指标背后隐藏着大量工程细节：**编辑距离的动态规划求解、文本归一化（Text Normalization）、数字/标点/大小写/简繁体的处理策略、指标本身的缺陷（对同义替换惩罚过重）** 等。这些细节往往才是面试中真正考察的点。

---

## 2. 编辑距离与动态规划推导

### 2.1 问题定义

给定参考序列 $R = (r_1, r_2, \dots, r_N)$（长度 $N$）与假设序列 $H = (h_1, h_2, \dots, h_M)$（长度 $M$），编辑距离定义为：**将 $H$ 变换为 $R$ 所需的最少编辑操作次数**，操作包括：

* **替换（Substitution, S）**：把 $H$ 中某个单元替换成 $R$ 对应单元，代价 1；
* **删除（Deletion, D）**：$H$ 中多出了单元，需删掉，代价 1；
* **插入（Insertion, I）**：$H$ 中漏掉了单元，需插入，代价 1。

> 注意：经典编辑距离还允许"转置（Transposition）"作为 Damerau-Levenshtein 距离的扩展，但 WER/CER 标准定义中**不使用转置操作**——两个相邻字符顺序颠倒被记为 2 次替换。

### 2.2 DP 状态定义

设 $D(i, j)$ 表示 **$H$ 的前 $i$ 个单元与 $R$ 的前 $j$ 个单元之间的编辑距离**。

构建 $(M+1) \times (N+1)$ 的 DP 表格：

* 行方向（$i$）：对应假设 $H$；
* 列方向（$j$）：对应参考 $R$。

### 2.3 边界条件

$$D(i, 0) = i \quad (\text{参考为空，假设的 } i \text{ 个单元全部是多余插入})$$

$$D(0, j) = j \quad (\text{假设为空，需要插入 } j \text{ 个单元才能变成参考})$$

### 2.4 状态转移方程

$$D(i, j) = \min \begin{cases} D(i-1, j) + 1 & \text{（删除：} h_i \text{ 是多余单元）} \\ D(i, j-1) + 1 & \text{（插入：漏掉了 } r_j\text{）} \\ D(i-1, j-1) + \text{cost}(i, j) & \text{（对齐/替换）} \end{cases}$$

其中：

$$\text{cost}(i, j) = \begin{cases} 0 & h_i = r_j \quad (\text{完全匹配，零代价}) \\ 1 & h_i \neq r_j \quad (\text{一次替换}) \end{cases}$$

### 2.5 DP 表格示例

计算 `H = "cat"` 与 `R = "cut"` 的编辑距离（逐字符）：

```
            ""  c   u   t
        "" [ 0  1   2   3 ]
        c  [ 1  0   1   2 ]
        a  [ 2  1   1   2 ]
        t  [ 3  2   2   1 ]   <-- D(3,3) = 1 (一次替换: a -> u)

回溯路径: (0,0) -> (1,1)匹配c -> (2,2)替换a/u -> (3,3)匹配t
结果: S=1, D=0, I=0, N=3, CER = 1/3 ≈ 33.3%
```

复杂度为 $O(M \times N)$，空间可用滚动数组优化至 $O(\min(M, N))$。

### 2.6 回溯得到 S / D / I

DP 只给出总距离，若要拆分出 $S$、$D$、$I$ 三类错误（badcase 分析必需），需要从 $D(M, N)$ **回溯（Backtracking）**：

1. 若 $D(i, j)$ 来自 $D(i-1, j-1) + 1$ 且 $h_i \neq r_j$：记一次**替换**，移动到 $(i-1, j-1)$；
2. 若来自 $D(i-1, j) + 1$：记一次**插入**（假设多），移动到 $(i-1, j)$；
3. 若来自 $D(i, j-1) + 1$：记一次**删除**（假设漏），移动到 $(i, j-1)$；
4. 若来自 $D(i-1, j-1)$ 且 $h_i = r_j$：匹配，移动到 $(i-1, j-1)$。

> **术语澄清**：在 ASR 语境下，"Deletion" 指**参考中的词被模型删掉了（漏识）**，"Insertion" 指**模型插入了参考中不存在的词（多识/幻觉）**。以参考 $R$ 为基准描述，而 DP 回溯以假设 $H$ 为基准时方向相反，实现时务必统一口径。

## 3. WER 公式与定义

### 3.1 标准公式

$$\text{WER} = \frac{S + D + I}{N} = \frac{S + D + I}{S + D + C}$$

其中：

* $N$：参考文本总词数（$N = S + D + C$）；
* $C$：正确识别的词数（Correct）；
* $S$、$D$、$I$：替换、删除、插入的错误词数。

对应地，**词正确率（Word Accuracy / WAcc）**：

$$\text{WAcc} = 1 - \text{WER} = \frac{N - S - D - I}{N} = \frac{C - I}{N}$$

注意 WAcc 中减去了 $I$，即插入错误同样拉低正确率。

### 3.2 分母为什么是 N 而不是 M

WER 以**参考文本**为分母，保证同一测试集上不同模型可比（$N$ 固定），而假设长度 $M$ 因模型而异。由此带来一个重要特性：

> **WER 可以超过 100%**。当模型严重幻觉、插入大量词（$I$ 很大）时，如 $N=100$，$S=20$，$D=10$，$I=150$，则 WER = 180%。这在 Whisper 类 AED 模型的长静音/强噪声场景中并不罕见，本身就是模型幻觉的信号。

### 3.3 句级与语料级聚合

* **句级 WER**：单条音频的编辑距离 / 单条参考词数。短句 WER 波动极大（漏一个词的 5 词句 WER 即 20%）。
* **语料级 WER（标准做法）**：**先累加所有句子的 $S$、$D$、$I$、$N$，再整体相除**（micro-average），而非对句级 WER 求平均（macro-average）。后者会被短句主导，不代表真实词错水平。

$$\text{WER}_{\text{corpus}} = \frac{\sum_i S_i + \sum_i D_i + \sum_i I_i}{\sum_i N_i}$$

## 4. CER 与中文评估

### 4.1 为什么中文用 CER

中文文本没有空格分词，"词"的边界本身依赖分词器（且分词标准不统一），以词为单位计算 WER 会引入分词器的额外误差与争议。因此中文 ASR 统一采用**字错率 CER**：

* 以**单个汉字**（以及英文单词、数字串等原子单元）为对齐单元；
* 标注与识别结果都无需分词，客观且可复现。

### 4.2 中英混合文本的处理

中文真实场景大量夹杂英文单词与数字（如"用 Python 实现"、"拨打 110"），常见做法：

* 汉字逐字切分，英文按词切分，数字归一化成统一格式后切分；
* 例：`"GPT4发布了"` → `["GPT4", "发", "布", "了"]`。

### 4.3 WER 与 CER 的量级差异

同一个系统，英文 WER 与中文 CER 不能直接对比；一般经验：

| 场景 | 典型水平 |
| --- | --- |
| 中文朗读/听写（纯净）CER | 2% ~ 5%（工业标杆 < 3%） |
| 中文普通话业务场景 CER | 5% ~ 10% |
| 英文 LibriSpeech test-clean WER | 2% ~ 4%（SOTA 已到 ~1.7%） |
| 英文真实远场 noisy WER | 10% ~ 30% |

同一个错误（一个汉字错）对 CER 贡献为 1；而英文一个多字符词错对 WER 贡献也为 1——中文单字信息密度高，CER 数值通常显著低于英文 WER 数值。

### 4.4 词错率 vs 字错率的选择原则

| 维度 | WER（词为单位） | CER（字为单位） |
| --- | --- | --- |
| **适用语言** | 英文、德文等空格分词语言 | 中文、日文等 |
| **是否依赖分词** | 否（天然空格） | 否（逐字切分） |
| **错误敏感性** | 一个字母错即整词算错 | 单字粒度，更细腻 |
| **数值大小** | 偏大（词长 > 1 字） | 偏小 |
| **可懂度相关性** | 与人工纠错成本更相关（改词） | 与逐字校对更相关 |

面试常问：**中文为什么不报告 WER？** 答：分词标准不统一导致指标不可复现，且分词误差会污染评估；字符级是唯一无歧义的对齐单元。

## 5. 文本归一化（Text Normalization）

归一化是 WER/CER 计算中**工程量最大、最容易出错**的环节。未经归一化的对比毫无意义——标注写 `五公里` 而模型输出 `5公里`，实质正确却会被记错。

### 5.1 归一化项目清单

| 类别 | 示例（原始 -> 归一化） | 说明 |
| --- | --- | --- |
| **大小写** | `Hello` -> `hello` | 英文统一小写 |
| **标点符号** | `你好，世界！` -> `你好世界` | 通常全部剥离 |
| **数字格式** | `100` <-> `一百` / `one hundred` | 中英文数字需统一转写规范 |
| **常见单位/符号** | `%` <-> `百分之`；`$` <-> `美元`；`℃` <-> `摄氏度` | 与标注规范对齐 |
| **简繁体** | `语音` <-> `語音` | 统一为简体（或与标注一致） |
| **英文缩写** | `U.S.A.` -> `usa` | 去点、合并 |
| **语气词/填充词** | ` uh / 呃 / 嗯` | 依据标注规范决定保留或删除 |
| **特殊符号** | `&` -> `and`；`+` -> `plus` | Whisper 的 EnglishTextNormalizer 处理 30+ 类规则 |

### 5.2 Whisper 的 Normalizer

Whisper 开源仓库提供了一个著名的 `EnglishTextNormalizer`，处理：

* 数字归一化（`50%` -> `50 percent`、British 拼写统一）；
* 标点/大小写/空格规整；
* 口语填充词剔除。

**面试高频追问**：Whisper 论文里 LibriSpeech WER 很低，自己测却偏高——常见原因就是**没有使用官方 normalizer**，或标注与模型数字转写规范不一致。

### 5.3 归一化的坑

1. **过度归一化**：把真实错误掩盖（如模型输出完全颠倒的数字串，若只保留数字位对比可能漏判）。
2. **中英混合数字**：`2024年` vs `二零二四年`，必须先确定标注规范（阿拉伯数字 or 汉字），两侧统一。
3. **标点该不该算**：若业务需要标点（字幕生成），则应评估带标点的 CER，或单独报告标点 F1。

## 6. WER 的缺陷与相关指标对照

### 6.1 WER 的核心缺陷

1. **同义替换惩罚过重（最重要）**：
   假设说 `"我今天很开心"`，识别成 `"我今天很高兴"`——语义完全一致，WER/CER 记 2 次替换。WER 对**语义等价但字面不同**的输出没有分辨能力。LLM 时代这个问题被放大：大模型转述、口语化改写、翻译场景下 WER 严重失真。
2. **所有错误等权**：把否定词"不"识别错与把"嗯"识别错，对语义影响天差地别，但 WER 同记 1 错。
3. **无法度量多候选/半正确**：数字 `1024` 识别成 `1042`，按词记 1 错（全错），按字符记 2 替换，都不能反映"数字大体对了"。
4. **对插入不设上限**：导致 WER > 100% 的可能性，指标在幻觉场景下不直观。

### 6.2 BLEU / TER / 其他指标对照

| 指标 | 领域 | 计算方式 | 与 WER 对比 |
| --- | --- | --- | --- |
| **WER/CER** | ASR | 编辑距离 $(S+D+I)/N$ | 基准指标 |
| **TER** (Translation Error Rate) | 机器翻译 | 编辑距离 + 允许**短语级转置** | 比 WER 多转置操作，更贴近译文流畅性 |
| **BLEU** | 机器翻译 | N-gram 精确率 + 长度惩罚的几何平均 | 只奖精确匹配、无编辑距离；只减分不加分，与人工评价相关性在 ASR 改写场景差 |
| **METEOR** | 机器翻译 | 考虑同义词、词干对齐 | 部分缓解同义替换问题 |
| ** Semantic ER / BERT-Score** | Speech-LLM | 语义嵌入相似度 / BERT 余弦 | 语义级评估，适合 LLM 转述场景 |
| **NER-WER / 实体 F1** | 业务 ASR | 仅对人名/地名/数字等关键实体算错率 | 业务最关心的"关键信息准确率" |
| **GPS / 温度计类指标** | 会议纪要场景 | 语义对齐后打分 | 评估内容要点覆盖率 |

工业界实践：**通用 CER + 分维度 CER（数字 CER、热词召回、标点 F1）+ 语义指标（可选）组合使用**，单一 WER 无法支撑业务决策。

## 7. Python 实现与工具

### 7.1 手写编辑距离与 WER 计算

```python
import numpy as np
from typing import List, Tuple


def levenshtein_dp(hyp: List[str], ref: List[str]) -> Tuple[int, int, int, int]:
    """
    计算假设序列 hyp 与参考序列 ref 的编辑距离，并拆分出 S/D/I。
    返回 (S, D, I, C)
    """
    M, N = len(hyp), len(ref)
    # DP 表: D[i][j] = hyp[:i] 与 ref[:j] 的编辑距离
    dp = np.zeros((M + 1, N + 1), dtype=np.int32)
    dp[:, 0] = np.arange(M + 1)   # 参考为空：hyp 全部是插入
    dp[0, :] = np.arange(N + 1)   # 假设为空：全部需要"补"（对应参考被删）

    for i in range(1, M + 1):
        for j in range(1, N + 1):
            cost = 0 if hyp[i - 1] == ref[j - 1] else 1
            dp[i][j] = min(
                dp[i - 1][j] + 1,        # 插入 (hyp 多出 hyp[i-1])
                dp[i][j - 1] + 1,        # 删除 (ref 中 r[j-1] 被漏识)
                dp[i - 1][j - 1] + cost  # 匹配 / 替换
            )

    # 回溯拆分错误类型
    S = D = I = C = 0
    i, j = M, N
    while i > 0 or j > 0:
        if i > 0 and j > 0 and dp[i][j] == dp[i - 1][j - 1] + (0 if hyp[i - 1] == ref[j - 1] else 1):
            if hyp[i - 1] == ref[j - 1]:
                C += 1
            else:
                S += 1
            i, j = i - 1, j - 1
        elif i > 0 and dp[i][j] == dp[i - 1][j] + 1:
            I += 1   # hyp 多出 -> Insertion
            i -= 1
        else:
            D += 1   # ref 被漏 -> Deletion
            j -= 1
    return S, D, I, C


def normalize(text: str, lang: str = "zh") -> List[str]:
    """极简归一化示例（生产环境需完整规则表）"""
    import re
    text = text.lower()
    text = re.sub(r"[，。！？、；：,.!?;:\s]", "", text)  # 去标点
    if lang == "zh":
        return list(text)                    # 中文逐字切分
    return text.split()                      # 英文按空格切分


def compute_wer(hyp: str, ref: str, lang: str = "zh") -> dict:
    h, r = normalize(hyp, lang), normalize(ref, lang)
    S, D, I, C = levenshtein_dp(h, r)
    N = len(r)
    return {
        "S": S, "D": D, "I": I, "C": C, "N": N,
        "WER/CER": round((S + D + I) / max(N, 1), 4),
        "Accuracy": round((C - I) / max(N, 1), 4),
    }


if __name__ == "__main__":
    # 中文示例
    print(compute_wer("我今天狠高兴", "我今天很开心", lang="zh"))
    # {'S': 2, 'D': 0, 'I': 0, 'C': 4, 'N': 6, 'WER/CER': 0.3333, 'Accuracy': 0.3333}

    # 英文示例（幻觉插入导致 WER > 100% 的演示）
    print(compute_wer("the the the cat sat on the mat the the", "cat on mat", lang="en"))
    # N=3, 大量插入 -> WER 远超 100%
```

### 7.2 打分工具 jiwer

工业界最常用的打分库是 **jiwer**（pip 安装，被 Hugging Face `evaluate` 封装为 `wer` 指标）：

```python
import jiwer

transform = jiwer.Compose([
    jiwer.ToLowerCase(),
    jiwer.RemoveMultipleSpaces(),
    jiwer.RemovePunctuation(),
    jiwer.Strip(),
    jiwer.ReduceToListOfListOfWords(),   # 英文按词; 中文可先逐字切分
])

wer = jiwer.wer(
    ["the cat sat on the mat", "hello world"],
    ["the cat sat on mat", "hello world"],
    truth_transform=transform,
    hypothesis_transform=transform,
)
print(f"WER: {wer:.4f}")
```

其他工具：

* **torchmetrics**：`WordErrorRate` / `CharErrorRate` 类，可嵌入训练循环在线监控；
* **SCTK / sclite**（NIST）：老牌学术评测工具，输出详细的对齐报告（dtl 文件逐词标注 S/D/I）；
* **Whisper 官方 normalizer**：`whisper.normalizers.BasicTextNormalizer / EnglishTextNormalizer`。

### 7.3 工程要点

1. **微平均聚合**：全量语料累加 S/D/I/N 后再除，不要平均句级错误率；
2. **报告 S/D/I 分布**：Insertion 高提示幻觉，Deletion 高提示 VAD 截断或声音小，Substitution 高提示口音/同音字问题；
3. **置信区间**：可用 bootstrap 重采样估计 WER 的 95% 置信区间（学术评测标配），两个模型 WER 差异小于置信区间宽度时不可下结论。

---

## 8. 总结与最佳实践

* **核心公式**：$\text{WER} = (S + D + I) / N$，分母固定为参考词数，故 WER 可大于 100%（幻觉信号）。
* **DP 求解**：$O(M \times N)$ 的经典 Levenshtein 动态规划，回溯路径可拆分 S/D/I 三类错误用于 badcase 归因。
* **中文用 CER**：避免分词歧义，汉字逐字对齐，量级上 CER 通常显著低于英文 WER。
* **归一化决定评估质量**：大小写、标点、数字、简繁、语气词必须两侧统一规则；Whisper 评测务必使用官方 normalizer。
* **不要只看 WER**：同义替换惩罚过重是 WER 的根本缺陷，LLM 时代应辅以语义指标（BERT-Score）、实体级指标（数字 CER、热词 F1）与主观评测。
* **工业落地组合拳**：语料级 micro-WER + 分场景分桶 WER + S/D/I 错误分布 + bootstrap 置信区间，四件套才是完整的客观评估报告。

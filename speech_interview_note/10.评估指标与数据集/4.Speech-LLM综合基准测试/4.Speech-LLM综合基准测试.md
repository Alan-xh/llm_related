# 4. Speech-LLM 综合基准测试

## 1. 概述

传统语音任务的评估是"一任务一指标"：ASR 用 WER/CER，TTS 用 MOS，增强用 PESQ/STOI。但 **Speech-LLM（语音大模型，如 Qwen-Audio、SALMONN、Qwen2.5-Omni、GLM-4-Voice 等）** 把识别、翻译、问答、对话、音频理解统一进一个模型，单一任务指标无法刻画整体能力。于是 2021 年以来出现了一批**综合基准测试（Benchmark）**，试图用一套标准化的多任务测试集 + 统一协议，回答"这个语音大模型到底有多强、强在哪、弱在哪"。

```
 评估范式演进:

 2011~2020  单任务指标时代      WER (ASR) | MOS (TTS) | PESQ (增强)
                │
 2021       SUPERB             冻结 SSL 表征 + 轻量下游头, 10 项理解任务
                │
 2022       SUPERB-SR / SpeechBench / VoiceMOS     扩展到恢复任务/多语/主观分预测
                │
 2024       AudioBench / VoiceBench / Sakura       面向 Audio-LLM / 语音对话助手
                │
 2024~      Seed-TTS eval / TTS Arena              零样本克隆评测 + 众包对战 Elo
```

选型逻辑一句话：**测表征理解选 SUPERB 系，测多模态音频理解选 AudioBench，测语音对话助手选 VoiceBench / Sakura，测 TTS 与克隆选 Seed-TTS eval + TTS Arena**。

---

## 2. 为什么需要综合基准：单任务指标的失效

Speech-LLM 的输出往往是**开放式文本**（回答问题、执行指令），不存在唯一参考文本：

1. **同一语义多种表达**：回答"今天天气怎么样"可以是任意合理表述，WER/BLEU 无法打分，需要 **LLM-as-a-Judge**（用 GPT-4 级裁判模型按维度打分）或**可验证规则**（多选题、约束检查）；
2. **能力耦合**：语音问答错，可能是听错（感知）、没听懂指令（理解）、还是答错知识（推理）？需要解耦测试（speech-only / text-only 对照）；
3. **跨模态对照**：同一道题以文本形式输入 vs 语音形式输入，分数差（speech-text gap）本身就是核心指标--Sakura 系列基准的核心洞察。

---

## 3. SUPERB：语音理解表征基准

### 3.1 设计思路

**SUPERB**（Speech processing Universal PERformance Benchmark，Yang et al., 2021）评估的是**SSL 自监督表征（wav2vec 2.0、HuBERT、WavLM 等）+ 冻结上游 + 轻量下游头**的通用性：

```
 [Audio] --> [冻结 SSL Upstream (wav2vec2/HuBERT)] --> [加权帧级池化]
                                                        │
                                    [轻量下游头 (小型NN)] --> 各任务输出
```

* 上游完全冻结，只训练参数量极小的下游头（避免大模型微调掩盖表征本身差异）；
* 帧级表征经**加权池化（learnable weighted summation）**聚合成句/词向量。

### 3.2 十项任务构成

| 任务 | 缩写 | 数据集 | 指标 |
| --- | --- | --- | --- |
| 音素识别 | PR | LibriSpeech | PER |
| 词识别 (ASR) | ASR | LibriSpeech | WER |
| 说话人识别 | SID | VoxCeleb1 | Acc |
| 说话人确认 | SV | VoxCeleb1 | EER |
| 情感识别 | ER | IEMOCAP | Acc |
| 意图分类 | IC | SLURP | SER / SLU-F1 |
| 槽位填充 | SF | Snips | F1 / WER |
| 关键词检测 | KS | Speech Commands | Acc |
| 例句检索 (Query-by-Example) | QE | QUESNE | TMV@FAR |
| 说话人分离 | SD | Libri2Mix | DER |

**地位**：SSL 表征时代的标准考场，WavLM 在其上确立最强表征地位；后续 **SUPERB**（扩展版）追加更多任务，**Dynamic-SUPERB** 引入指令化的动态任务集。

### 3.3 SUPERB-SR：语音恢复（Speech Restoration）扩展

**SUPERB-SR**（2022）把基准从"理解"扩展到"**生成/恢复**"任务：上游 SSL 表征 + 轻量生成头，直接输出修复后的波形。任务包括：

* **去噪（Denoising）**、**去混响（Dereverberation）**、**去削波（Declipping）**、**超分辨率（Super-Resolution，带宽扩展 8k->16k/44.1k）**、**目标说话人提取**；
* 数据集：VoiceBank+DEMAND、DNS Challenge、REVERB 等；
* 指标：PESQ、STOI、SI-SDR、LSD（对数谱距离）；
* 意义：验证"同一份 SSL 表征既能理解也能恢复"，是语音万能表征路线的早期证据。

## 4. SpeechBench：多语言识别与翻译基准

**SpeechBench**（Microsoft，2022）聚焦**多语言 ASR 与语音翻译（Speech Translation, ST）**的跨语言综合评测：

* **任务构成**：
  * 多语言 ASR：CoVoST / mSLAM / FLEURS 等多语种测试集上的 WER/CER；
  * 语音翻译（S2TT，语音到目标语文本）：CoVoST-2（21 个翻译方向，X->En 与 En->X）上的 BLEU；
* **贡献**：把分散的多语 ASR/ST 测试集统一成一套协议与榜单，配合 **mSLAM 多语种语音-文本预训练**提出；
* **局限**：仍限于"语音->文本"映射类任务，不覆盖对话与开放式问答。

---

## 5. AudioBench：Audio-LLM 万能基准

**AudioBench**（2024，"AudioBench: A Universal Benchmark for Audio Large Language Models"）面向**音频大模型（Audio-LLM）**，把能力拆成三大板块：

```
 AudioBench
 ├── 1. Speech Understanding (语音理解)
 │     ├── ASR:            LibriSpeech (clean/other), EML
 │     ├── Speech QA:      SLURP-QA, SLUE-QA (口语问答)
 │     └── Speech Translation: CoVoST-2 (En->De/Zh, X->En)
 ├── 2. Audio Understanding (音频理解, 非语音)
 │     ├── Audio Captioning:     AudioCaps, Clotho
 │     ├── Audio Scene QA:       Clotho-AQA (场景问答/多选)
 │     └── Audio, Speech & Music 混合理解
 └── 3. Voice Understanding (音色维度)
       ├── Accent (口音), Gender (性别), Emotion (情感)
       └── 均以多项选择形式考察
```

* **评测方式**：ASR/翻译用 WER/BLEU 客观指标；开放式 QA 与 caption 采用 **GPT-4 辅助裁判打分**；
* **贡献**：给出 Qwen-Audio、SALMONN、Whisper-LLM 级联等系统的统一横评，揭示了端到端模型在音频理解上与级联方案的差距；
* **同类**：AIR-Bench（音频推理）、MMAU（音乐/音频理解）等后续基准进一步细分。

---

## 6. VoiceBench：语音对话助手基准

**VoiceBench**（2024，Chen et al.）明确瞄准 **LLM 驱动的语音助手（Voice Assistant）**，核心问题是：**"把文字基准题用语音问出来，助手还能答对吗？"**

### 6.1 任务构成

| 板块 | 内容 | 数据来源 | 评测 |
| --- | --- | --- | --- |
| **ASR** | 基础听写能力 | LibriSpeech (clean/other)、CommonVoice | WER |
| **口语问答 (Spoken QA)** | 以语音形式提问的知识/推理题 | 用 TTS 将 Alpaca-eval、TriviaQA、MMLU 等**文本基准合成为语音** | GPT-4 判分 |
| **事实性与指令遵循** | 知识正确性、回答质量 | 同上合成 | LLM-as-a-Judge |
| **语音翻译** | En<->多语 | CoVoST-2 子集 | BLEU |

### 6.2 关键设计：TTS 合成语音考题

文本基准题（如 MMLU 选择题、TriviaQA 问答）经 TTS 转成语音再喂给模型，从而：

* 直接测出 **speech-text gap**：同一模型文本版得分 vs 语音版得分之差；
* 可控生成多种说话人（口音/语速/噪声）考察鲁棒性；
* 结论：级联（Whisper + 强 LLM）在 QA 上普遍优于当时的端到端 Speech-LLM，端到端优势主要在延迟与韵律保留。

## 7. Sakura 系列基准：SESB / Speech-IFEval / Speech-MT

**Sakura**（2024/2025，"Sakura: ... evaluation benchmarks of spoken dialogue systems"）系统研究了"把文本 LLM 基准语音化"的价值，提出三个精修基准与一个评测工具链（sakura-bench）：

### 7.1 SESB（Speech Evaluation using Synthetic Speech Benchmark）

* 将文本 LLM 基准（英文 MMLU、日文 JMMLU 等）用高质量 TTS **合成语音版**（含正常/噪声/口音等条件）；
* 考察：模型在**语音输入**下的知识与推理能力保持度（speech 版 vs text 版分数差）；
* 发现：不少语音对话模型在语音版基准上大幅掉分，说明"听得见"不等于"听得懂"；强级联系统掉分更小。

### 7.2 Speech-IFEval（语音指令遵循）

* 把 **IFEval（可验证指令遵循基准）** 的指令题转成语音输入；
* 指令约束是**可程序化校验**的（如"回答不超过 50 词"、"必须包含关键词 X"、"全小写"、"JSON 格式"），不需要人工或裁判打分；
* 专测：语音输入下模型对输出格式/长度/内容约束的遵循率（strict/prompt-level pass rate）；
* 意义：对话助手的真实体验一半取决于"听话"，而非"答题"。

### 7.3 Speech-MT（语音翻译，LLM 裁判评测）

* 语音到文本翻译任务（含 En->Ja 等方向），使用 **LLM-based evaluation**（如 GPT-4o 按充分性/流畅性打分）替代 BLEU；
* 动机：BLEU 对合法意译惩罚严重，LLM 裁判更接近人类质量判断；
* 同时提供与传统指标的相关性分析。

### 7.4 Sakura 的核心结论

1. **级联 vs 端到端**：在纯"内容能力"上，级联（ASR+文本 LLM）常常仍占优，端到端的价值在延迟、韵律、副语言信息；
2. **基准选择即结论**：只用 ASR 指标评语音助手会严重高估其对话能力，必须用语音化的 QA/IF 基准；
3. 评测工具链开源，支持自定义 TTS 音色与噪声条件复现。

## 8. TTS 与声音克隆基准：Seed-TTS eval 与 TTS Arena

### 8.1 Seed-TTS eval

**Seed-TTS eval**（字节跳动 Seed-TTS 团队开源的评测套件）针对**零样本 TTS / 声音克隆**：克隆语音不仅要"文本对"（内容），还要"音色像"（说话人）与"韵律像"（节奏停顿语调）。指标体系：

| 指标 | 全称 | 计算方式 | 衡量 |
| --- | --- | --- | --- |
| **WER** | Word Error Rate | 用 ASR 转写生成语音，与目标文本算 WER | 内容正确性（间接） |
| **SIM / SECS** | Speaker Embedding Cosine Similarity | ECAPA-TDNN 等说话人编码器提取嵌入，与参考音频算余弦 | 音色相似度 |
| **SWS** | Spoken-Word Similarity | 基于 ASR 词级时间戳，对齐比较生成与参考的词序列相似度 | 词级内容保真 |
| **SPCUR** | Speech Pause Correctness | 比较 ASR 时间戳得到的停顿位置/时长分布 | 停顿韵律正确性 |
| **SFR** | Speech Fluctuation Rate | 比较生成与参考的音高/能量波动统计 | 语调起伏相似度 |
| **SDR** | Speech Duration Rate | 句/词时长比率 | 语速与时长一致性 |

* **用法**：在零样本克隆测试集（多说话人、中英文）上，对比生成语音与参考的上述指标；WER 越低、SIM/SWS/SPCUR/SFR/SDR 越高越好；
* **价值**：把"韵律像不像"从纯主观（SMOS）部分客观化，且全部基于 ASR 时间戳与声学统计，可自动化批量跑。

### 8.2 TTS Arena

**TTS Arena**（Hugging Face Spaces 社区项目，机制同 Chatbot Arena）：

* **流程**：用户输入任意文本 -> 收听两个**匿名** TTS 系统的合成音频 -> 投票更好的一方 -> 累计百万级对战用 **Elo / Bradley-Terry 模型**估计排名；
* **优点**：众包主观偏好，覆盖真实多样文本，难被单一指标 hack，榜单实时更新；
* **缺点**：投票人群不可控（非听音专家）、无音质校准环境、系统更换文本策略可被轻度博弈（刷票/挑选有利 prompt），分数有噪声与波动；
* **同类**：Voice Arena / E2 TTS 竞技场等。工程上常把 **TTS Arena 排名当参考、自家 CMOS/SMOS 当决策**。

## 10. 基准污染与过拟合问题

### 10.1 污染（Contamination）的形态

1. **测试数据泄漏进训练**：
   * LibriSpeech / CommonVoice 的**文本与音频在网上公开**，语音 LLM 的海量爬取预训练数据极可能包含基准测试集本身（音频或文本形式），模型可以"背答案"；
   * 实证信号：模型在 LibriSpeech test-clean 上的 WER 异常低，但对同分布的自录音频明显变差；对测试集**改写扰动**（加噪、变速、换说话人）后大幅掉分，是背诵式过拟合的典型表现。
2. **基准过拟合（benchmark overfitting）**：
   * 团队反复在同一测试集上刷版本、调 prompt，指标提升不再泛化（"为考题而学"）；
   * Elo 类对战榜单上，系统可以通过调整默认音色/风格迎合大众偏好而非真实质量。
3. **裁判偏置（LLM-as-a-Judge 的坑）**：
   * GPT-4 裁判偏好长回答、特定格式、与自身输出风格相近的答案（self-preference）；
   * 裁判模型本身可能也被污染（见过基准参考答案）。

### 10.2 缓解手段

| 手段 | 做法 |
| --- | --- |
| **私有留出集** | 公司内部保密测试集永不公开、不进训练，作为最终真相（发布数字只报私有集） |
| **动态/生成式基准** | Dynamic-SUPERB、程序化生成考题（合成语音 + 模板问法随机化），无法预先背诵 |
| **扰动鲁棒性校验** | 对基准音频加噪/变速/换说话人/TTS 重合成，观察分数稳定性，识别背诵 |
| **n-gram 重叠扫描** | 训练语料与基准文本做 13-gram/canonical 匹配（NLP 惯例移植），命中即剔除或标记 |
| **裁判去偏** | 交换回答顺序、双裁判一致性检查、与人工抽检对齐校准裁判 |
| **少样本协议 + 榜单匿名重测** | Arena 类定期匿名复测、限制投票频控 |

### 10.3 面试视角的结论

* 公开榜单数字**只能横比、不能尽信**：报告成绩时要注明是否去污染、是否私有复验；
* 最好的实践是"**公开基准对外沟通 + 私有集对内决策**"双轨制；
* 评估 Speech-LLM 时永远加测 **speech-text gap**（同题文字版 vs 语音版），这是区分"真听懂"与"背题"最便宜的手段。

## 11. 总结与最佳实践

* **选型地图**：表征理解（SUPERB/SUPERB-SR）-> 多语 ASR/ST（SpeechBench）-> Audio-LLM（AudioBench）-> 语音助手（VoiceBench、Sakura：SESB/Speech-IFEval/Speech-MT）-> TTS/克隆（Seed-TTS eval 客观 + TTS Arena 主观）。
* **评测方式三件套**：客观指标（WER/BLEU/DER/Elo）+ 可验证规则（多选、IFEval 约束校验）+ LLM-as-a-Judge（开放式 QA），后者必须做去偏校准。
* **Speech-LLM 特有指标**：speech-text gap（语音版 vs 文本版基准分差）是衡量"感知拖累理解"的核心信号，Sakura 与 VoiceBench 均以此为设计出发点。
* **克隆评测三维度**：内容（WER/SWS）+ 音色（SIM）+ 韵律（SPCUR/SFR/SDR），Seed-TTS eval 是目前最系统的开源套件。
* **警惕污染**：公开音频/文本基准几乎必然进入预训练语料；用扰动校验识别背诵、用私有留出集做最终决策、用动态基准对抗过拟合。

# 3. 评估与测试集

## 1. 概述

在语音算法工程中，一个常被低估的事实是：**指标决定模型优化的方向，而测试集决定指标是否可信**。模型在"干净、均衡、与训练分布一致"的测试集上 CER 3%，到了真实业务（远场、口音、专有名词、长音频）可能劣化到 15%+ --问题往往不在模型，而在测试集没有覆盖真实分布。

本文系统梳理测试集的**设计原则、分层策略（内测/外测、脏测/纯净测、长音频/流式）、badcase 分析流程、以及数据合规与脱敏**，这是算法工程师日常迭代中真正花时间最多的部分。

```
                     评估测试集体系
                          │
      ┌───────────┬───────┴────────┬─────────────┐
   设计原则      分层策略         Badcase 闭环    合规治理
      │             │                │              │
 场景覆盖      内测 vs 外测      错误归类归因    脱敏(号码/姓名)
 难度分层      纯净 vs 脏测      口音/专名/噪声  授权与知情同意
 说话人均衡    长音频/流式集     修复->回归验证  存储加密/留存期限
 规模与置信    业务场景分桶      badcase 入库    法律法规(GDPR/个保法)
```

## 2. 测试集设计原则

### 2.1 场景覆盖（Coverage）

真实业务语音的场景维度极多，测试集必须显式覆盖每个关键维度组合，常见分桶维度：

| 维度 | 典型取值 |
| --- | --- |
| **信道/设备** | 手机麦克风、耳机、笔记本、会议音箱、远场阵列、电话 8kHz |
| **距离** | 近讲（<0.3m）、中距（1m）、远场（3~5m） |
| **噪声** | 安静办公室、街道、车载、餐厅 babble、键盘声、音乐背景 |
| **口音/方言** | 标准普通话、地方口音（川普/粤普等）、方言、中英混说 |
| **说话人属性** | 性别、年龄段（儿童/老人）、语速（快/慢） |
| **领域** | 通用口语、客服、医疗、法律、直播、游戏语音 |
| **特殊事件** | 多人重叠说话、插话、长静音、咳嗽笑声等非语音事件 |

实践建议：建立一张**场景覆盖矩阵**（维度 x 取值），检查每个格子是否有足够样本（每桶建议 ≥ 数百条，保证该桶指标的置信度），缺格子的地方就是评估盲区。

### 2.2 难度分层（Stratification by Difficulty）

单一总分会掩盖薄弱环节。标准做法是按难度分桶报告：

```
总分 CER = 6.2%
├── 纯净朗读桶      CER = 1.8%   (易)
├── 真实口语桶      CER = 5.5%
├── 口音桶          CER = 9.0%
├── 远场噪声桶      CER = 12.4%  (难)
└── 专有名词/热词桶 CER = 15.1%  (最难, 业务最痛)
```

分层后才能回答"下一个版本应该优化什么"，也能防止模型在简单桶上的收益掩盖难桶的退化。

### 2.3 说话人与口音均衡

* **说话人不重叠**：测试集说话人绝不能出现在训练集中（说话人泄漏会使指标虚高数个点），需要按 speaker ID 严格切分；
* **长尾说话人保护**：口音重、语速极端、儿童与老年说话人在随机采样中占比低，需要**主动超采样（oversample）**保证统计有效；
* **每说话人条数上限**：防止单一说话人主导测试集（如每人 ≤ 20 条），否则指标对该说话人的特性过拟合；
* **性别/年龄配比**：与真实业务分布对齐，或固定一个基准配比便于跨版本比较。

### 2.5 规模与统计置信

* 每个报告指标的桶建议 **≥ 500 句 / ≥ 5000 词**（词数越多 WER 置信区间越窄）；
* 用 **bootstrap 重采样**估计 WER/CER 95% 置信区间；两版本差距小于 CI 宽度时不能判定优劣；
* 测试集要**冻结（frozen）**：一旦上线评估流程，不可增删改样本，否则历史指标不可比。

### 2.6 测试集版本管理

* **版本化**：测试集像代码一样入版本控制（git/数据仓库），每次变更记录 changelog（新增桶、标注修订、剔除坏样本），历史指标按版本号追溯；
* **新旧衔接**：必须扩充时，保留旧子集并按旧子集单独报告，保证与历史数字可比；
* **标注质检**：抽检 5%~10% 双人标注计算一致性（CER 指标下字一致率应 > 99%），标注错误通常贡献 5%~10% 的虚假 badcase，分析前先剔除。

## 3. 内测集 vs 外测集（In-domain vs Out-of-domain）

### 3.1 定义

| 类型 | 定义 | 用途 |
| --- | --- | --- |
| **内测集（in-domain / dev-test）** | 与训练数据同分布（同渠道、同领域、同人群） | 日常回归、训练监控、超参选择 |
| **外测集（out-of-domain / OOD）** | 刻意取自不同分布：新领域、新信道、新口音、新语种 | 衡量泛化能力，暴露过拟合 |

### 3.2 为什么要分

```
              训练分布
            ┌──────────┐
  内测集 ●●●│ ●●●●●●●● │●●● 内测集: 指标乐观, 监控训练是否收敛
            └──────────┘
   外测集 ○○○ (域外): 指标真实, 监控模型是否只会"背"训练分布
```

* 只看内测集：模型可能只是记住了训练分布的捷径（如特定信道特征），换场景即崩；
* 只看外测集：日常迭代信号太噪，收敛判断困难；
* **工业实践**：内测集做高频回归（每次提交跑），外测集做低频里程碑评估（版本发布前跑），两者都恶化才说明方向错误，内升外降提示过拟合。

### 3.3 外测集的构建来源

1. **跨领域采买/收集**：如训练用客服语音，外测用会议、直播语音；
2. **跨信道录音**：训练用近讲，外测用远场阵列回放录制；
3. **公开数据集充当 OOD 探针**：如内部模型在 AISHELL-1 / WenetSpeech test / KeSpeech（口音）上 cross-check，可与公开论文数字互相对照；
4. **线上真实流量采样**（经合规审批后）：最能代表真实分布，是最终标准。

## 4. 脏测与纯净测分层

### 4.1 为什么要分"脏/纯净"

模型迭代时常出现"纯净指标升、脏指标降"的跷跷板现象（如加大 LM 融合权重提升纯净可懂度却让噪声下插入错误暴涨）。因此测试集必须显式分层：

* **纯净测（clean）**：信噪比 SNR > 20dB、近讲、无混响；衡量模型能力上限；
* **脏测（noisy/multi-condition）**：真实或仿真加噪（SNR 0~15dB）、混响（RT60 0.3~1.0s）、信道损毁（ Codec 丢包、 clipping）；衡量真实鲁棒性。

### 4.2 脏数据的构造方式

| 方式 | 做法 | 优缺点 |
| --- | --- | --- |
| **真实录制** | 实地采集嘈杂环境语音 | 最真实；成本高、难以控制变量 |
| **加噪仿真** | 干净语音 + 噪声库混合（MUSAN、DEMAND），随机 SNR | 可控可复现；与真实仍有 gap（需加混响 RIR 卷积、Codec、增益扰动等 chain 增强真实感） |
| **RIR 卷积** | 与房间脉冲响应卷积模拟混响 | 弥补加噪仿真的混响缺失 |
| **线上 badcase 回流** | 收集线上识别差的流量（脱敏后） | 分布最贴近痛点；需合规流程 |

DNS Challenge 的训练/测试集构造（clean + noise + RIR + codec 链式仿真 + 盲测真实集）是脏测构造的业界范本。

## 5. 长音频与流式测试集

### 5.1 长音频测试集

长音频（会议、播客、课程，30 分钟以上）暴露的是短音频评估看不到的问题：

* **分段与 VAD 策略**：切分点错误造成的词截断（boundary error）；
* **幻觉累积**：Whisper 类模型在长静音/音乐段重复生成的概率随时长上升；
* **说话人分离（diarization）联动误差**：转写文本归属到错误说话人；
* **上下文遗忘**：前文纠错信息（如已出现的人名）无法被后文利用。

设计要点：包含长静音段、音乐段、多人对话、语码转换（中英夹杂）；指标除 CER 外，还应看 **分段边界误差** 与 **口语事件（填充词/重复/修正）处理策略**；标注上需要带说话人标签与时间戳。典型公开集：AISHELL-4（会议）、AliMeeting、Ego4D、AMI。

### 5.2 流式测试集

流式（Streaming）ASR 的评估除了最终的 CER，还必须评估**时延（Latency）** 与**中间结果稳定性**：

| 指标 | 定义 | 典型要求 |
| --- | --- | --- |
| **Final CER** | 整句说完后最终结果的字错率 | 与非流式模型差距 < 1~2 个点 |
| **_partial / Streaming CER** | 实时中间结果的字错率 | 反映用户屏幕上的观感 |
| **First-token / Finalized latency** | 从说完一个词到该词被"稳定输出"的时延 | 语音助手 < 300~500ms；同传可放宽 |
| ** flicker rate**（闪烁率） | 中间结果被改写的频率（前缀不稳定比例） | 越低越好，高频改写体验极差 |

流式测试集设计要点：

* 标注需带**词级时间戳**（可用强制对齐生成再人工校验），否则时延无法计算；
* 覆盖不同 Chunk 尺寸（如 320ms / 640ms / 1s）与 lookahead 配置；
* 评估需在**模拟实时馈送**（real-time factor = 1）下进行，而非一次性灌入；
* 报告 CER-Latency 曲线（不同 chunk/beam 配置下的帕累托前沿）比单点指标更有价值。

## 6. Badcase 分析流程

### 6.1 标准闭环

```
 ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
 │ 测试集/  │-->│ 自动打分 │-->│ 错误聚类 │-->│ 归因分析 │-->│ 定向修复 │
 │ 线上回流 │   │ S/D/I 拆分│   │ 与分层   │   │ (模型/数据│   │ + 回归   │
 └──────────┘   └──────────┘   └──────────┘   │ /工程)   │   │ 验证     │
      ▲                                        └──────────┘   └────┬─────┘
      └────────────────── badcase 入库沉淀 <──────────────────────┘
```

### 6.2 错误归类：先按操作类型拆

打分时保留编辑距离回溯的逐对齐结果，按 **S（替换）/ D（删除）/ I（插入）** 拆分：

| 错误类型 | 典型表现 | 常见根因 |
| --- | --- | --- |
| **替换 S 偏高** | 同音字错（"在/再"）、口音导致的音素偏移、专有名词错 | 声学模型对口音敏感、LM 上下文不足、热词缺失 |
| **删除 D 偏高** | 语速快的词被吞、弱读音节漏识、VAD 截断 | 编码器下采样过激、LM 融合权重过高偏向短输出、VAD 阈值不当 |
| **插入 I 偏高** | 静音/噪声段凭空出字、重复词 | 幻觉（AED 类模型高发）、噪声被误识为语音、缺 no-speech 门槛 |

S/D/I 的分布本身就是重要的诊断信号，务必在评估报告中保留。

### 6.3 归因维度：再按成因聚类

对 badcase 逐条（或抽样）打归因标签，统计每类的错误量与占比，形成优先级排序：

| 归因类别 | 示例 | 修复手段 |
| --- | --- | --- |
| **口音/方言** | 川普、粤普导致声学偏移 | 口音数据增补/加权、多方言联合训练 |
| **专有名词/热词** | 人名、产品名、术语错 | 热词表 + contextual biasing、浅融合打分加成 |
| **噪声/混响** | babble 噪声下漏识 | 前端增强、多条件训练数据 |
| **数字/格式** | 日期、金额、手机号转写错 | 专项后处理、数字 TN 规则、约束解码 |
| **分段/边界** | 切分截断首尾字 | VAD 参数、分段策略 |
| **幻觉** | 长静音出字、重复 | no-speech 阈值、重复惩罚、temperature fallback |
| **标注问题** | 参考文本本身错/规范不一致 | 修标注、统一归一化规范（通常占 5%~10%，先剔除再分析） |

### 6.4 Badcase 库沉淀

* 每个修复的 badcase 转成**回归用例**进入回归集，防止下个版本复发；
* 按"归因标签 + 场景桶"索引，支持快速检索（"所有车载场景的插入错误"）；
* 定期统计各归因类别的错误量走势，作为团队 OKR/ roadmap 的直接输入。

## 7. 数据脱敏与合规

语音是敏感个人信息（可唯一识别自然人），测试集的采集、存储、使用必须满足合规要求。

### 7.1 法律框架

| 法规 | 关键要求 |
| --- | --- |
| **《个人信息保护法》（中国 PIPL）** | 处理个人信息需知情同意；敏感个人信息单独同意；最小必要原则 |
| **GDPR（欧盟）** | 合法依据（同意/合法利益）、数据主体权利（删除/可携带）、默认隐私设计 |
| **行业规范** | 采集需告知用途、留存期限、是否第三方共享 |

### 7.2 脱敏手段（PII Redaction）

1. **标注层脱敏**：转写文本中的手机号、身份证号、银行卡号替换为占位符（如 `<PHONE>`）；人名按需保留或哈希（评估 NER 时需保留映射表于受控环境）；
2. **音频层脱敏**：
   * 声纹不可逆处理有难度，实践中靠**访问权限控制**而非修改音频；
   * 敏感片段（报号码段落）可做静音/频谱遮挡（bleep），但会破坏 ASR 评估，需保留未脱敏原件于隔离环境；
3. **说话人身份治理**：speaker ID 化名映射表与音频分离存储，映射表加密、限制访问；
4. **存储与权限**：测试集落加密存储，按项目最小授权；导出需审批水印；
5. **留存期限**：设定保留期（如 2 年）到期删除或匿名化；训练/测试用途变更需重新获得同意范围确认。

### 7.3 工程实践清单

- [ ] 采集有明确授权文案与同意记录；
- [ ] 测试集与训练集 speaker 隔离（防泄漏，也防合规串扰）；
- [ ] 敏感字段自动扫描（正则 + NER 检测号码/证件/地址）；
- [ ] 访问审计日志；
- [ ] 对外公开测试集需二次确认无个人信息（公开学术集例外需符合其 license）。

## 8. 总结与最佳实践

* **测试集决定指标可信度**：按场景覆盖矩阵设计、按难度分桶报告、说话人与训练集严格隔离、规模保证置信区间。
* **内测 + 外测双轨制**：内测集管日常回归，外测集管泛化能力；内升外降即过拟合警报。
* **脏/纯净分层**：干净测看能力上限，脏测（加噪/RIR/codec 仿真 + 真实回流）看鲁棒性，二者跷跷板现象必须在报告里同时呈现。
* **长音频/流式专项**：长音频关注分段/幻觉/说话人联动；流式必须报告 CER-Latency 帕累托曲线与中间结果稳定性，需要词级时间戳标注。
* **Badcase 闭环是迭代引擎**：S/D/I 拆分 -> 归因聚类（口音/专名/噪声/数字/幻觉/标注）-> 定向修复 -> 回归入库，用数据决定优化优先级。
* **合规是底线**：知情同意、PII 脱敏（标注层占位符 + 音频层访问控制）、加密与留存期限管理，缺一不可。

# 5. 表达力与情感控制TTS

## 1. 概述

一个 MOS 4.5 的 TTS 系统如果只能用同一种"播音腔"说话，在实际产品中依然不合格。**表达力（Expressiveness）/情感控制**研究的是：如何让 TTS 摆脱"一个音色一种腔调"，支持情感（喜/怒/哀/惊）、风格（新闻播报/聊天/朗诵）、语气（疑问/强调/迟疑）的**可控生成**。

核心矛盾贯穿全篇：**可控性（Controllability）vs 自然度（Naturalness）**——

* **显式控制**（情感标签、SSML）：可控性 100%，但表达是连续高维的，离散标签会割裂韵律的自然协同，听感"演的"。
* **隐式控制**（参考音频、风格 token、VAE/扩散隐空间）：自然度高（从真实语音迁移），但"控制"退化为"挑选参考"，精细度低。

表达力的物理载体是**韵律三要素（Prosody）**：F0（基频/语调）、能量（Energy/重音）、时长（Duration/节奏）。所有情感控制方法最终都落到对这三者的建模方式上。

---

## 2. 韵律建模基础：F0 / Energy / Duration

### 2.1 三要素的物理意义与提取

| 要素 | 物理量 | 提取方法 | 情感关联 |
| --- | --- | --- | --- |
| **F0** | 基频（Hz，语音 60~400Hz） | YIN / pYIN / WORLD 的 Harvest/DIO / CREPE（神经网络） | 语调升降、音高范围（兴奋 F0 均值与方差增大、悲伤压平） |
| **Energy** | 短时幅度（dB） | 帧 RMS / Mel 谱按频带求和 | 重音、响度起伏（愤怒能量高且起伏大） |
| **Duration** | 音素/音节时长 | MFA 对齐 / 时长预测器 | 语速（开心偏快、悲伤拖长）、停顿（迟疑=长停顿） |

### 2.2 三要素的联合分布才是情感

情感不是三个标量，而是三要素随时间的**联合轨迹**（contour）："惊讶"= 短促音节 + F0 骤升 + 落差大 + 能量脉冲。因此逐帧独立预测 F0/energy（FastSpeech2 的 variance adaptor）能提升自然度，但**不足以表达强情感**——需要能建模联合轨迹相关性的机制（自回归 predictor、VAE、扩散）。

```
文本: "真的吗?!"
        真的      吗      ?!
F0:  /¯¯\     /¯↑\    ↑↑      <- 疑问=句末升调, 惊叹=F0急升
Eng: ██▓     █▓░     ▓█      <- 重音落在"真"与"?!"脉冲
Dur:  [==]  [=]   [==]       <- "吗"短促, 尾部停顿
```

## 3. 显式标签控制 vs 隐式风格控制

### 3.1 显式路线：情感标签 / SSML

* **做法**：训练时每句带情感标注（`<emotion=angry>`），推理时拼接标签 embedding。
* **优点**：控制接口明确、产品化简单、可用 SSML 精确指定位置与强度。
* **缺点**：
  1. **数据昂贵**：同文本多情感平行语料（ESD 即为此设计）录制成本高；
  2. **标签粒度粗**："有点生气"和"暴怒"难以用单标签表达，需连续强度维度；
  3. **风格割裂**：标签 one-hot 使韵律空间被切分，跨情感过渡不自然。

### 3.2 隐式路线：Reference Audio 迁移

* **做法**：参考音频 -> 风格编码（GST/VAE）-> 条件化解码器；或直接拼 prompt（VALL-E 式）。
* **优点**：自然度高（真实韵律的连续迁移），无需人工标注。
* **缺点**：控制 = 选参考；参考音频的内容/音色会**泄漏**（content/style/speaker entanglement）到输出；不可组合（无法"开心的+新闻腔"）。

## 4. GST / StyleToken：软标签的中间路线

### 4.1 Global Style Tokens（2018, Wang et al.）架构

```
 参考音频 Mel -> [Reference Encoder (3层LSTM)] -> r (最后一帧状态)
                                                            │
                                                            ▼
                                            [Style Attention (多头)]
                                                            │  与共享的 Token 字典做 attention
                              Token Bank T = {t_1,...,t_K} (K=10~100, 训练所得)
                                                            ▼
                                    style embedding s = Σ_i α_i · t_i  (软组合)
                                                            │ (加/拼接到编码器输出)
 文本 -> [Encoder] ────────────────────────────────────> [AR Decoder] -> Mel
```

* **无监督风格聚类**：token 字典不预先定义语义，训练后自动学出"升调句尾""低沉沙哑""快语速"等可解释风格原子；风格 = 原子的软组合 $\alpha$，比 one-hot 标签细腻。
* **控制方式**：人工调 $\alpha$（离散探索）或提供参考音频（自动提取）；对**跨说话人风格迁移**（A 的内容 + B 的风格）尤其有效。
* **变体**：
  * **Reference Encoder（2018）**：GST 前身，单向量风格；
  * **Tokens-to-Text / Token2Tech** 类工作把 token 扩展到句级/词级粒度；
  * **StyleTTS** 的 VAE：把 reference 编码换成带 KL 的隐变量，支持采样；
  * **GMVAE / Emo-Factorized 模型**：在隐空间中**解耦情感与音色**（Factorized style-space），同一音色下拨动情感维度。

### 4.2 面试常考：GST 为什么比 one-hot 情感标签好？

1. **无监督**：不需要情感标注，海量无标注录音即可训练；
2. **连续组合**：one-hot 只能表达训练集出现过的情感类别，token 软组合可插值出未见过风格；
3. **迁移能力**：风格与文本解耦后，可以跨说话人、跨内容迁移韵律。

## 5. 扩散韵律与隐空间采样：Diffusion Prosody

### 5.1 为什么用 Diffusion/VAE 建模韵律

韵律轨迹是**长程相关**的（句尾语调由全句语境决定），且**一句多解**（同一文本有多种自然读法）。生成式隐变量天然适合：

* **Diffusion Prosody 模型**（如 PnG-BERT+ 扩散 pitch、StyleTTS2 的 Diffusion 风格头）：把 F0/风格轨迹的生成建为去噪过程，条件为文本语义表示：

$$\mathcal{L}_{\text{simple}} = \mathbb{E}_{p_0, \epsilon, k}\big\| \epsilon - \epsilon_\theta(p_k, k, \text{text}) \big\|^2, \quad p_0 = \text{GT 韵律轨迹}$$

* **多样本采样**：一次文本可采出多种自然读法（产品上的"多候选 TTS"），而回归式 predictor 只输出均值韵律（过平滑、平淡）。
* **代表系统**：**StyleTTS 2** 用扩散头预测风格隐变量；**NaturalSpeech 3** 对韵律子空间分治扩散；**CosyVoice** 以指令 + 扩散解码器实现"用激动语气说"的细粒度控制。

### 5.2 情感强度连续控制

在隐空间中对情感方向做插值：$z = z_{\text{neutral}} + \lambda \cdot (z_{\text{angry}} - z_{\text{neutral}})$，$\lambda \in [0, 1.5]$ 连续调节强度——显式接口（$\lambda$ 滑条）+ 隐式表征（$z$ 空间）的混合是工业产品最常见的折中。

## 6. SSML 与工程化控制接口

### 6.1 SSML（Speech Synthesis Markup Language）

W3C 标准的 XML 方言，主流引擎（Azure / Google / Amazon / 阿里）均支持：

```xml
<speak version="1.0" xml:lang="zh-CN">
  <prosody rate="+20%" pitch="+10%" volume="+6dB">今天天气真好啊！</prosody>
  <break time="500ms"/>
  <emphasis level="strong">注意</emphasis>，前方 <say-as interpret-as="cardinal">300</say-as> 米右转。
  <mstts:express-as style="cheerful" styledegree="1.5">祝你旅途愉快！</mstts:express-as>
</speak>
```

* `<prosody>`：rate/pitch/volume 的百分比或半音控制（作用于时长/F0/能量 predictor 的后处理缩放）。
* `<break>`：强制停顿时长（作用时长建模）。
* `<say-as>`：数字/日期/货币读法（文本前端 TN 控制）。
* `express-as`（微软扩展）：风格名 + **styledegree 强度**，后端对接风格隐空间插值。
* **实现要点**：SSML 标签最终都被翻译为前端特征（时长缩放系数、F0 偏移、风格 embedding），在声学模型的 variance adaptor / 风格注入层生效；标签之间的交互（rate 与 pitch 同时改）需要约束防止韵律崩坏。

## 7. 情感语音数据集

| 数据集 | 语言/规模 | 情感标注 | 备注 |
| --- | --- | --- | --- |
| **EmoVDB** | 英语，5 说话人（2.8k 句/人级别） | 5 类（angry/happy/neutral/sad/surprise），同文本平行 | 克隆/迁移研究常用，规模小 |
| **ESD**（Emotional Speech Dataset, CUHK） | 中英双语，10 说话人 x 350 句 | 5 类（neutral/happy/angry/sad/surprise），**同文本平行** | 中文情感 TTS 事实标准 |
| **MSP-Podcast / IEMOCAP** | 英语，对话/播客 | 维度标注（valence/arousal）+ 类别 | 更真实（非演播室），但音质参差 |
| **AIHub / 内部数据** | 韩语/中文等 | 多类 | 工业界普遍自录 |

* **维度情感（Valence-Arousal）vs 类别情感（离散）**：V-A 连续坐标能插值（"微怒"到"暴怒"），研究界（如 Seen and Unseen emotional style transfer）常用；工业界以离散类别 + 强度参数最普遍。

## 8. 可控性 vs 自然度：权衡总结

```
 可控性 ▲
 (标签/   │  SSML 标签控制          情感标签 embedding
  参数)   │   (rate/pitch 滑条)      (one-hot + intensity)
        │        ▲                     ▲
        │        │                     │
        │        │        强度插值 ◄───┼──── 隐空间采样
        │        │        (λ 混合)      │     (StyleTTS2/GST α 调节)
        │        │                     │
        └────────┴─────────────────────┴────────────────▶ 自然度
                                              参考音频迁移 (GST/VAE/VALL-E prompt)
                                              扩散韵律生成 (多候选, 最自然)
```

| 方法 | 可控粒度 | 自然度 | 需要标注 | 代表 |
| --- | --- | --- | --- | --- |
| SSML prosody 参数 | 连续（但全局） | 低（机械感） | 否 | 各家引擎 |
| 情感 one-hot 标签 | 离散类别 | 中 | 是（情感语料） | ESD 微调模型 |
| GST 软 token | 组合（挑 token/参考） | 中高 | 否 | Tacotron+GST |
| VAE 隐空间 + 插值 | 连续（λ 强度） | 高 | 否 | StyleTTS 1/2 |
| 扩散韵律/风格 | 采样多样 + 条件引导 | **最高** | 否（自监督即可） | StyleTTS2, NaturalSpeech 3, CosyVoice |

**工业实践定式**：产品接口层用**离散风格名 + 强度参数**（可控性、可测试）；模型内部落到**隐空间插值/扩散条件**（自然度）；SSML 兜底精细调节。

## 9. PyTorch 实战：GST 风格模块与情感强度插值

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class GST(nn.Module):
    """Global Style Token: Reference Encoder + 风格 Token 字典 + Style Attention"""
    def __init__(self, mel_bins=80, ref_hidden=128, n_tokens=10, style_dim=128, n_heads=4):
        super().__init__()
        # 1. Reference Encoder: 压缩参考 Mel 为单向量 r
        self.ref_enc = nn.LSTM(mel_bins, ref_hidden, num_layers=2, batch_first=True)
        # 2. Token Bank: K 个可学习风格原子
        self.tokens = nn.Parameter(torch.randn(n_tokens, style_dim) * 0.02)
        # 3. Style Attention: r 作 query 与 token 字典对齐
        self.query_proj = nn.Linear(ref_hidden, style_dim)
        self.attention = nn.MultiheadAttention(style_dim, n_heads, batch_first=True)
        self.out_proj = nn.Linear(style_dim, style_dim)

    def extract_style(self, ref_mel):
        """
        ref_mel: [B, T_ref, mel_bins] 参考音频 Mel
        return:  s [B, style_dim], alpha [B, K] token 软组合权重
        """
        h, (last, _) = self.ref_enc(ref_mel)          # last: [1, B, ref_hidden]
        r = last.squeeze(0)                            # [B, ref_hidden]
        q = self.query_proj(r).unsqueeze(1)            # [B, 1, style_dim]
        token_bank = self.tokens.unsqueeze(0).expand(q.size(0), -1, -1)
        s, alpha = self.attention(q, token_bank, token_bank)  # attention 提取软组合
        return self.out_proj(s.squeeze(1)), alpha.squeeze(1)

def emotion_interpolation(gst, z_neutral_ref, z_emo_ref, lam):
    """
    情感强度连续控制: 在 style 空间对 neutral -> emotion 方向插值
    lam=0 中性, lam=1 全强度, lam>1 夸张 (可到 ~1.5)
    """
    s_n, _ = gst.extract_style(z_neutral_ref)
    s_e, _ = gst.extract_style(z_emo_ref)
    return s_n + lam * (s_e - s_n)          # [B, style_dim]

if __name__ == "__main__":
    gst = GST()
    ref_happy = torch.randn(1, 180, 80)     # ~2 秒开心参考音频
    ref_neutral = torch.randn(1, 180, 80)

    style, alpha = gst.extract_style(ref_happy)
    print(f"style emb: {style.shape}, token weights: {alpha.shape}")
    print(f"token 组合 (前5): {alpha.softmax(-1)[0,:5].detach().numpy().round(3)}")

    for lam in [0.0, 0.5, 1.0, 1.3]:       # 强度滑条: 中性 -> 夸张
        z = emotion_interpolation(gst, ref_neutral, ref_happy, lam)
        print(f"lambda={lam}: style norm = {z.norm(dim=-1).item():.3f}")
```

## 10. 总结与最佳实践

* **建模主线**：韵律三要素（F0/energy/duration）是表达力的物理底座；标签/SSML 是显式接口，GST/VAE/扩散是隐式生成，**强度插值把两者打通**是工业标配。
* **架构建议**：
  1. 有平行情感数据（ESD 类）：标签预训练 + 隐空间插值微调，可控性与自然度兼得；
  2. 无标注情感数据：直接上 GST/StyleTTS2 式隐式建模 + 扩散采样，产品侧用"风格字典"索引控制；
  3. 需要精细编辑（逐词重音）：SSML -> variance adaptor 的参数化路径不可替代。
* **评估**：除 MOS 外增加**情感识别准确率（SER，用情感分类器判合成语音的情感类别）**与说话人相似度（防止改情感时音色漂移）。
* **面试要点**：能画出 GST 结构图并解释 token 无监督聚类成因（attention 软选择 + 字典共享）；能论证"回归式 predictor 表达不了强情感"（均值化/多解性）；能设计一套 SSML 标签到模型内部特征的映射方案。

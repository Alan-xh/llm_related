# 4. Zero-Shot与克隆TTS

## 1. 概述

声音克隆（Voice Cloning）的目标是让 TTS 系统模仿一个**未见（unseen）说话人**的音色。按目标说话人所需数据量，工业界将其分为三个层级：

| 层级 | 所需数据 | 典型耗时 | 代表方案 | 音色相似度（SIM） |
| --- | --- | --- | --- | --- |
| **微调克隆（Fine-tuning）** | 10 分钟~几小时录音 + 文本标注 | 数小时训练 | 早期 Tacotron/FastSpeech2 微调、DurIAN 少样本微调 | 高（0.8~0.9+） |
| **少样本克隆（Few-shot）** | 数秒~1 分钟，无需标注 | 秒~分钟级 enrolment | GE2E/XTTS-V1、YourTTS | 中高（0.7~0.85） |
| **零样本克隆（Zero-shot）** | 3~10 秒参考音频（prompt） | **0（推理时直接合成）** | VALL-E、CosyVoice、Voicebox、XTTS-v2 | 中高（0.6~0.8，持续提升中） |

零样本克隆是大模型时代 TTS 的主战场：核心范式从"显式 speaker embedding 条件化"演进为"**语言模型式 prompt 续写**"--把语音离散化为 codec token，像 LLM 续写文本一样续写音色。

---

## 2. 基础：说话人表征（Speaker Embedding）

### 2.1 d-vector / x-vector

* **d-vector**（2014~）：说话人验证模型（LSTM 分类器）在 enrolment 音频上取**最后一层隐状态的帧级向量平均**作为说话人表征。
* **x-vector**（2018, Kaldi 标准）：TDNN + 统计池化（mean + std）+ PLDA，长时均值稳定，训练即带**说话人分类目标**：

$$e_{\text{spk}} = \text{StatsPooling}\big(\{h_t\}_{t=1}^T\big) = [\mu; \sigma], \quad \mu = \frac{1}{T}\sum_t h_t, \; \sigma = \sqrt{\frac{1}{T}\sum_t (h_t - \mu)^2}$$

* **GE2E（Generalized End-to-End, 2017）**：Google 提出的说话人验证损失，按 batch 构造说话人分组，让 utterance embedding 与本组中心相似、与他组中心远离，成为克隆系统 speaker encoder 的标配训练方式（d-vector 系）。

### 2.2 在 TTS 中注入 speaker embedding

```
 参考音频 -> [Speaker Encoder (冻结/联合训练)] -> e_spk
                                                     │ (concat / AdaIN / SALN 注入)
 文本 -> [Phoneme Encoder] -----------------------> [Acoustic Model] -> Mel -> Vocoder -> 克隆语音
```

* **局限**：单向量容量有限，只能携带"音色身份"，难以传递参考音频的**韵律、情感、录音条件**；对参考音频的时长与内容敏感。

---

## 3. 隐式风格传递：GST / Reference Encoder

**GST（Global Style Tokens, 2018）** 引入 reference encoder 路线（详见第 5 篇）：

* 参考音频 -> Reference Encoder -> style embedding -> 与文本条件共同驱动解码器。
* 与 speaker embedding 的区别：GST 学到的是**风格字典**（情感、语速、录音条件的自动聚类），克隆时能同时迁移韵律与音色的部分信息。
* 该思想是后续所有"reference audio 驱动"系统的雏形：StyleTTS 的 VAE、VALL-E 的 acoustic prompt 本质上都是它的升级版。

## 4. Codec LM 路线：VALL-E 开启的范式

### 4.1 VALL-E（2023, Microsoft）核心架构

```
                        文本 (phonemes + BOS)
                              │
   参考音频 (3s) ──> EnCodec ──┼──> AR Decoder ──> 第一层 codec token (逐个自回归)
   (acoustic prompt)          │        │
                              │        ▼
                              └──> NAR Decoder (x7 层并行) ──> 第 2~8 层 codec token
                                                              │
                                                        EnCodec Decoder ──> 波形
```

* **语音离散化**：用神经 codec（**EnCodec**，8 个 RVQ codebook，75Hz 帧率）把 24kHz 波形转为离散 token 序列；1 秒音频 ≈ 75 帧 x 8 层 = 600 token。
* **AR + NAR 分工**：
  * **第一层 quantizer 的 token 由 AR Transformer 自回归生成**--第一层携带最重要的谱/韵律信息，自回归保证连贯性；
  * **其余 7 层由 NAR 一次性并行生成**（条件 = 文本 + 已生成的高层 token），速度提升约 10 倍。
* **Prompt 续写式克隆**：3 秒参考音频的 token 作为 **acoustic prompt 前缀**拼在待合成文本 token 前面，模型像 LLM 续写一样"延续这个人的声音"--**无需任何说话人建模模块，克隆是免费的**。
* **实验数字**（论文）：LibriSpeech test-clean 上 zero-shot SIM（WavLM 相似度）约 **0.58**（GT 0.68），WER 5.9%（GT 2.5%）；同时具备 3 秒样本保留说话人情感/环境噪声的"录音条件克隆"能力。
* **主要缺陷**：合成稳定性差（漏词、幻觉）、OOD 文本易失败、RTF 高（AR 部分逐 token）。

### 4.2 主要后续系统

| 系统 | 机构/年份 | 核心改进 |
| --- | --- | --- |
| **Bark** | Suno, 2023 | GPT 式 codec LM，支持笑声、叹气、音乐等**非语音声音**与多语言；不可控性较强 |
| **Voicebox**（Meta, 2023） | 非自回归 **Flow Matching** + 填空训练（text-conditioned infilling）；RTF 0.17 级别，SIM/WER 超越 VALL-E（WERS 1.9% vs 5.9%），支持去噪/编辑/跨语种，未开源 |
| **NaturalSpeech 2**（MS, 2023） | **连续潜变量 + 扩散**：非量化的 codec latent 上做 diffusion，外加语音 prompts（音色/韵律/口音）解耦，zero-shot SIM 显著提升 |
| **NaturalSpeech 3**（MS, 2024） | **离散化 FSQ codec + 分治扩散**（F0/内容/语义分解生成），zero-shot SIM ~0.81 级别 |
| **XTTS-v2**（Coqui, 2023） | GPT 风格 + 流匹配 vocoder，支持 16 语种零样本，6 秒参考，社区广泛使用 |
| **CosyVoice / CosyVoice 2**（阿里, 2024） | **监督语义 token（SenseVoice 提取）+ AR LM + 流匹配解码 mel**；语义 token 可控性强（指令微调支持"用开心的语气说"），CosyVoice 2 引入流式与零样本流式克隆，工业落地广 |
| **F5-TTS / E2-TTS**（2024） | 完全非自回归的扩散式 infilling，无需时长对齐，10 秒参考即可高质量克隆，开源生态主流 |

### 4.3 三种零样本范式对比

| 范式 | 代表 | 克隆机制 | 可控性 | 速度 |
| --- | --- | --- | --- | --- |
| Speaker embedding 条件化 | GE2E + FastSpeech2 | 显式向量注入 | 高（向量可编辑） | 快 |
| Codec token prompt 续写 | VALL-E / Bark / XTTS | 前缀 prompt，LM 续写 | 低（自然继承 prompt 风格） | 慢（AR） |
| 扩散/流匹配 infilling | Voicebox / F5-TTS / CosyVoice2 | 噪声 + 条件去噪，prompt 作边界条件 | 中高（可叠加指令） | 中（多步可蒸馏） |

## 5. 评估：similarity / MOS / WER 三角

零样本克隆系统的评估维度：

1. **音色相似度（Speaker Similarity, SIM）**：用说话人验证模型（**WavLM-based SV** 或 Resemblyzer/ecapa）计算合成音频与目标人参考的余弦相似度。VALL-E ≈ 0.58，CosyVoice/F5-TTS ≈ 0.7+，NaturalSpeech 3 ≈ 0.8+。
2. **可懂度/正确性（WER/SWER）**：ASR（Whisper）转写合成语音再与原文比对；克隆系统常见失败是**漏读/幻觉词**（AR LM 特有），因此 Speech WER 是稳定性硬指标。
3. **自然度 MOS / UTMOS**：与普通 TTS 相同。
4. **权衡规律**：相似度与自然度并非同向--强 prompt 约束提升 SIM 但可能把参考音频中的噪声/口吃一并克隆（VALL-E 的"录音条件克隆"是卖点也是风险）；生成式越强（扩散类）自然度越高但音色漂移风险越大。

## 6. 伦理与声音滥用防范（必答考点）

声音克隆是深度伪造（Deepfake）风险最高的模态之一。工业界的基本防线：

* **采集同意**：训练数据严格使用授权录音（有声书、新闻播音等需核查 license）；商用克隆产品要求目标人**朗读随机验证句**留证（如 XTTS、商业 API 的 enrolment 流程）。
* **水印与检测**：合成音频嵌入**不可听水印**（如 AudioSeal 类频域/相位水印）；配合 deepfake 检测器（对抗生成痕迹、声纹-唇纹不一致等）。
* **披露与使用策略**：API 返回 voice-clone 标记；对公众人物声纹建立"禁克隆名单"；语音银行/客服场景显式播报"AI 合成语音"。
* **法规**：中国《互联网信息服务深度合成管理规定》（2023 生效）要求显著标识合成内容并保护声纹权益；欧美相关立法（如欧盟 AI Act）也在跟进。

## 7. PyTorch 实战：Speaker Embedding 驱动的条件 TTS 推理

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class SpeakerEncoder(nn.Module):
    """GE2E 风格 speaker encoder: 统计池化 + 投影 + ArcFace 风格归一化"""
    def __init__(self, mel_bins=80, hidden=256, emb_dim=192):
        super().__init__()
        self.lstm = nn.LSTM(mel_bins, hidden, num_layers=2,
                            batch_first=True, bidirectional=True)
        self.proj = nn.Linear(hidden * 2, emb_dim)

    def forward(self, mel):
        """
        mel: [B, T, mel_bins] 参考音频 Mel 谱
        return: [B, emb_dim] L2 归一化说话人向量 (GE2E 惯例)
        """
        h, _ = self.lstm(mel)                       # [B, T, 2*hidden]
        pooled = torch.cat([h.mean(dim=1), h.std(dim=1)], dim=-1)  # 统计池化
        emb = self.proj(pooled)
        return F.normalize(emb, p=2, dim=-1)        # 单位球面, 余弦相似度直接内积


class ConditionalDecoder(nn.Module):
    """演示: speaker embedding 通过 FiLM (feature-wise affine) 注入 NAR 解码器"""
    def __init__(self, phoneme_dim=384, spk_dim=192, hidden=384):
        super().__init__()
        self.film_gen = nn.Linear(spk_dim, hidden * 2)   # 生成 gamma/beta
        self.block = nn.TransformerEncoderLayer(
            hidden, nhead=4, dim_feedforward=hidden * 4, batch_first=True)
        self.mel_out = nn.Linear(hidden, 80)

    def forward(self, phoneme_frames, spk_emb):
        """
        phoneme_frames: [B, T, phoneme_dim] (length regulator 之后)
        spk_emb:        [B, spk_dim]
        """
        gamma, beta = self.film_gen(spk_emb).chunk(2, dim=-1)   # 各 [B, hidden]
        x = phoneme_frames * (1 + gamma.unsqueeze(1)) + beta.unsqueeze(1)  # FiLM 条件化
        h = self.block(x)
        return self.mel_out(h)                                  # [B, T, 80] Mel 谱

def clone_similarity(wav_a, wav_b, sv_model):
    """用(冻结的)说话人验证模型评估克隆相似度 SIM -- VALL-E 论文评估协议"""
    with torch.no_grad():
        emb_a = F.normalize(sv_model(wav_a), dim=-1)
        emb_b = F.normalize(sv_model(wav_b), dim=-1)
        return (emb_a * emb_b).sum(dim=-1)       # 余弦相似度, 训练报告常取 0.6~0.8 区间

if __name__ == "__main__":
    B, T = 2, 120
    ref_mel = torch.randn(B, 200, 80)            # 3 秒参考音频 Mel (~200 帧)
    text_frames = torch.randn(B, T, 384)         # 已按时长扩展的文本帧特征

    spk_encoder = SpeakerEncoder()
    decoder = ConditionalDecoder()

    spk = spk_encoder(ref_mel)                   # [B, 192] 零样本音色向量
    mel_hat = decoder(text_frames, spk)
    print(f"speaker emb: {spk.shape}, cloned mel: {mel_hat.shape}")
    print(f"参考量级: VALL-E SIM≈0.58 / CosyVoice≈0.7+ / NaturalSpeech3≈0.81 (WavLM-SV)")
```

## 8. 总结与最佳实践

* **技术选型**：
  * 有 10 分钟级授权数据、追求极致相似度：**微调路线**（DurIAN/StyleTTS2 微调）仍是 SIM 上限最高的方案。
  * 秒级样本、需快速接入：**CosyVoice 2 / F5-TTS / XTTS-v2** 类零样本开源系统（3~10 秒 prompt，SIM 0.7+，中文支持好）。
  * 自研大模型：语义/声学 token 解耦（CosyVoice 思路）比纯声学 codec token（VALL-E 路线）**可控性与稳定性更好**。
* **面试要点**：
  1. VALL-E 为什么第一层用 AR、其余层用 NAR？--第一层 RVQ token 信息量最大、决定韵律连贯性，需自回归；余层是残差细化，并行生成即可，速度-质量折中。
  2. 零样本克隆为什么用 WavLM-SIM 而不是 MOS 评估？--克隆的核心指标是"像不像"，MOS 只测自然度；SIM 用独立训练的 SV 模型避免主观偏置。
  3. 少样本 vs 零样本的本质区别：是否需要在目标人数据上做**适配计算**（微调/快速 enrolment），zero-shot 把适配成本降为"拼接 prompt"。
  4. 伦理答法：采集同意 + 水印 + 检测 + 显著标识（《深度合成管理规定》），展现工程与社会责任意识。

# 1. 传统TTS与声学模型

## 1. 概述

语音合成（Text-to-Speech, TTS）的目标是将任意输入文本转化为高质量、高自然度、可听懂的语音波形。一个完整的 TTS 系统通常由三大部分组成：**文本前端（Text Frontend）→ 声学模型（Acoustic Model）→ 声码器（Vocoder）**。

在端到端神经网络 TTS（Tacotron、FastSpeech）出现之前，工业界的主流方案是**拼接合成（Concatenative TTS）**与**统计参数合成（Statistical Parametric TTS, SPSS）**两大流派。即便在今天，传统方法中的文本前端（G2P、多音字消歧、文本正则化）依然是所有现代 TTS 系统不可或缺的组成部分，也是面试中考察候选人工程功底的高频考点。

* **拼接 TTS（如 Unit Selection）**：从大规模录音库中挑选最优波形单元拼接，自然度取决于录音库覆盖度。
* **统计参数 TTS（HMM-GMM）**：用 HMM 建模状态序列、GMM 建模每状态的声学观测分布，参数化生成灵活但存在"嗡嗡声"（buzziness）。
* **神经网络声学模型（Tacotron 系列）**：Seq2Seq + Attention 直接从字符/音素生成频谱，开启了端到端时代，但其 attention 对齐不稳定的缺陷催生了显式时长建模（DurIAN / DCTTS / FastSpeech）。

## 2. TTS 系统总体架构

```
                        ┌──────────────────────────────────────────────────┐
                        │                 文本前端 (Frontend)               │
  原始文本 ──────────>  │  TN(正则化) → 分词 → POS/NER → G2P → 多音字消歧    │
  "2024年收入¥12.5万"   │                → 韵律预测 → 语言特征序列            │
                        └──────────────────────┬───────────────────────────┘
                                               │ 音素/字符序列 + 韵律标注
                                               ▼
                        ┌──────────────────────────────────────────────────┐
                        │            声学模型 (Acoustic Model)              │
                        │  HMM-GMM / DNN / Tacotron / FastSpeech / DurIAN  │
                        └──────────────────────┬───────────────────────────┘
                                               │ 声学特征 (Mel谱 / F0 / MGC / BAP)
                                               ▼
                        ┌──────────────────────────────────────────────────┐
                        │              声码器 (Vocoder)                     │
                        │  STRAIGHT / WORLD / WaveNet / HiFi-GAN / Vocos   │
                        └──────────────────────┬───────────────────────────┘
                                               │
                                               ▼
                                          语音波形 (Waveform)
```

* **声学模型的输出特征**：传统系统输出 F0（基频）、MGC/BAP（谱参数）；端到端系统通常直接输出 80 维 Mel 谱。
* **帧率约定**：一般帧移 10~12.5ms（传统）或 256 samples @ 22.05/24kHz ≈ 11.6ms（Tacotron/Hop），即 1 秒语音对应约 80~100 帧。

## 3. 文本前端（Text Frontend）

文本前端是 TTS 中工程量最大、最容易被低估的模块。其核心任务是**把书面的、非标准的文本转化为可发音的音素序列**。

### 3.1 文本正则化（Text Normalization, TN）

TN 负责将非标准词（Non-Standard Words, NSW）转化为口语读法：

| 原始文本 | 正则化后（中文口语） | 说明 |
| --- | --- | --- |
| `2024年` | `二零二四年` | 年份逐位读 |
| `¥12.5万` | `十二点五万元` | 金额需要货币语境 |
| `1.5kg` | `一点五千克` | 单位缩写展开 |
| `CPU` | `C P U` | 字母串逐字母读 |
| `127.0.0.1` | `一二七点零点零点一` | IP 逐位读 |
| `110` | `一百一十`（数量）/ `一一零`（电话） | 上下文相关（AM PM 分类） |

* **工业实现**：早期基于规则/WFST（如 Kaldi 的 `offline-tn`），现代用**标签分类 + 有限状态自动机**混合方案，或直接用 BERT 类模型做上下文判别（如数字读法分类）。
* **难点**：上下文依赖（"110" 在电话号码与数量中读法不同）、歧义符号（"3-4个" 中的连字符）、中英混读。

### 3.2 G2P（Grapheme-to-Phoneme，字音转换）

G2P 将词/字序列转换为音素（Phoneme）序列：

* **中文**：字 → 拼音（`重` → `zhong4/chong2`），词级切分可消解部分多音字（`重庆` → `chong2 qing4`）。
* **英文**：词 → 音标（`read` → `/riːd/` 或 `/red/`），OOV（Out-of-Vocabulary）词必须靠模型推断。
* **实现路线**：
  1. **词典 + 回退模型**：发音词典（CMUdict，约 13 万词）精确匹配，OOV 用神经 G2P（Transformer/Seq2Seq）预测。
  2. **端到端字符输入**：Tacotron 直接吃字符，把 G2P 隐式地学进网络，但数据需求量大、易读错 OOV 词。
* **为什么用音素而非字符**：音素序列显式携带发音信息，数据需求更小、跨说话人泛化更好、新词可由 G2P 兜底；字符输入则省去前端依赖但对拼写-发音不规则语言（英语）容错差。

### 3.3 多音字消歧（Polyphone Disambiguation）

中文多音字（约 800+ 常用）是前端的核心难点：

* **词表法**：分词后查多音字词典（`银行`→`yin2 hang2`），覆盖高频场景，准确率可达 95%+，但长尾失败。
* **模型法**：把多音字消歧建模为**上下文分类任务**——BERT 取多音字位置的隐状态，对候选读音做 Softmax 分类：

$$P(p \mid c_1, \dots, c_i, \dots, c_n) = \text{Softmax}\big(\text{Linear}(h_i^{\text{BERT}})\big)$$

工业系统通常"词典优先、模型兜底"，对少量极高频歧义字（如"还"、"得"、"了"）单独加规则。

### 3.4 韵律预测（Prosody Prediction）

中文前端还需预测韵律边界（#1 停顿、#2 短语、#3 子句），为声学模型提供停顿与节奏线索，通常用 BERT/BiLSTM + CRF 序列标注实现。

## 4. 拼接合成（Concatenative TTS）

代表系统：**PSOLA / Unit Selection（如微软早期产品、NUA）**。

### 4.1 单元挑选（Unit Selection）原理

从几十小时的录音库中，为每个目标音素单元挑选**代价最小**的候选波形片段并拼接：

$$C_{\text{total}} = \sum_i w_t \cdot C_t(u_i) + \sum_{i,j} w_j \cdot C_j(u_{i-1}, u_i)$$

* **目标代价（Target Cost）$C_t$**：候选单元与目标上下文（音素、韵律、音高）的差异。
* **连接代价（Join Cost）$C_j$**：相邻拼接点的谱不连续度（常用倒谱距离）。

### 4.2 优缺点

| 优点 | 缺点 |
| --- | --- |
| 音质接近真人录音（本身即真人片段） | 录音库庞大（数十小时起步），构建成本极高 |
| 自然度高（库内覆盖充分时） | 拼接处易出现"咔哒"声与韵律突变 |
| 推理速度快（查表拼接） | 风格/音色固定，无法参数化调整 |

## 5. 统计参数 TTS（HMM-GMM / SPSS）

代表工作：Tokyo Tech 的 HTS（HMM-based Speech Synthesis System）。

### 5.1 建模框架

对每帧声学特征向量 $o_t = [\text{MGC}^{(0\dots L)}, \log F_0, \Delta, \Delta^2]$ 建模为 HMM 状态发射概率，用 GMM 表示：

$$P(o_t \mid s_t) = \sum_{m=1}^{M} w_m \, \mathcal{N}(o_t; \mu_m, \Sigma_m)$$

训练用 EM/Baum-Welch；合成时先由文本生成 HMM 状态链（时长由各自的 Duration HMM 预测），再从每状态的输出分布采样/取均值生成参数轨迹，最后经 MLSA/STRAIGHT 声码器重建波形。

### 5.2 决策树状态聚类（Decision Tree Clustering）

三音素（Triphone）上下文相关状态数量爆炸（>10 万），用 phonetic 决策树按"问题集"（如"前一个音是鼻音吗？"）递归分裂聚类，保证未见上下文可回退到最细粒度可用叶子节点——这是 HMM-TTS 泛化能力的核心。

### 5.3 特点

* **优点**：模型小（几 MB）、灵活（可改时长/F0/情感参数）、部署简单。
* **缺点**：**过平滑（Over-smoothing）**——取高斯均值生成导致谱过于平滑，高频细节丢失，听感"机器人嗡嗡声"，MOS 通常仅 3.0 左右；而拼接法可达 4.0+。

## 6. Tacotron 系列：端到端声学模型

### 6.1 Tacotron 1/2 架构

```
 字符/音素 Embedding
        │
 ┌──────▼───────┐   Attention (location-sensitive)
 │  Encoder     │──────────────┐            ┌─────────────────┐
 │ (Conv+BLSTM) │              ├───────────>│  Decoder(AR)    │──> 逐帧 Mel 谱
 └──────────────┘   Context    │  <─────────│  2层LSTM+Prenet │──> Stop Token
                     Vector    └────────────┘  + PostNet       │
                                                             (Tacotron2: Griffin-Lim/WaveNet
                                                              合成波形)
```

* **Tacotron1**（2017）：输出线性谱 + Griffin-Lim 重建波形，MOS 3.82。
* **Tacotron2**（2018）：输出 80 维 Mel 谱 + WaveNet 声码器，MOS 达 **4.53**，逼近真人录音（4.58），是里程碑工作。

### 6.2 Attention 对齐机制

解码第 $t$ 帧时，对编码器输出 $h_{1:N}$ 计算注意力权重：

$$e_{t,i} = v^\top \tanh(W s_{t-1} + V h_i + U f_{t-1,i} + b), \qquad \alpha_{t,i} = \text{Softmax}(e_{t,i})$$

其中 $s_{t-1}$ 为上一解码 RNN 状态（内容项）、$f_{t-1,i}$ 为累积注意力权重经卷积得到的位置特征（location 项）、上下文向量 $c_t = \sum_i \alpha_{t,i} h_i$ 输入解码器。

> **单调对齐的直觉**：TTS 中文本-语音对齐天然单调（文本顺序 = 发音顺序），但标准 attention 无单调性约束，这是 Tacotron 不稳定的根源。

### 6.3 Guided Attention Loss（GTA）

为了让注意力权重沿对角线分布（第 $i$ 个输入大致对齐到第 $\tau \cdot i$ 帧附近），训练时加入引导项：

$$\mathcal{L}_{\text{att}} = \sum_{t}\sum_{i} \alpha_{t,i} \, w_{t,i}, \qquad w_{t,i} = 1 - \exp\left(-\frac{(t/N - i/M)^2}{2 g^2}\right)$$

* $N$ 为解码帧数，$M$ 为编码长度，$g$（常取 0.2）控制对角带宽度；权重在对角线附近趋于 0，远离对角线趋于 1，惩罚"乱跳"的注意力。
* 工程上通常只在前若干 k 步（如 5k~50k step）使用，之后退火让 attention 自由收敛。

### 6.4 Tacotron 的核心缺陷

1. **Attention 对齐失败**：长句/训练不充分时出现重复读（attention 停滞）、跳读（attention 越过未读文本）、注意力崩溃（只生成部分语音即触发 stop token），鲁棒性差。
2. **无法并行生成**：Mel 谱逐帧自回归解码，推理 RTF（Real-Time Factor）高，GPU 上 RTF 约 0.2~0.5（比实时慢 5~2 倍）。
3. **时长隐式**：语音时长完全由 attention 隐式决定，无法显式控制语速/停顿。

## 7. 显式时长建模：DurIAN / DCTTS

针对 attention 的缺陷，一类工作保留自回归解码器但**用显式时长替代 attention**：

* **DCTTS（2018）**：Text2Mel 模块用 duration 指示器（编码器帧复制）替代 attention 对齐。
* **DurIAN（2020, 字节跳动）**：
  * 由**时长预测器**（LSTM + 高斯混合模型预测每个音素的帧数分布）给出对齐，按时长复制编码器隐状态送入自回归解码器；
  * 保留 AR 解码器保证音质（MOS 4.5 级别），同时消除 attention 失败问题；
  * 少量数据微调即可实现高质量声音克隆。
* **与 FastSpeech 的关系**：FastSpeech 走得更远——不仅显式建模时长，还把解码器改成非自回归（详见本书第 3 篇）。

| 方案 | 对齐方式 | 解码方式 | 稳定性 | 音质 |
| --- | --- | --- | --- | --- |
| Tacotron2 | Attention（隐式） | 自回归 | 差（长句易失败） | 高（MOS ~4.5） |
| DurIAN | 显式时长预测 | 自回归 | 高 | 高（MOS ~4.5） |
| FastSpeech2 | 显式时长预测（MFA 蒸馏） | 非自回归 | 高 | 略低于 AR（可追平） |

## 8. PyTorch 实战：Location-Sensitive Attention 与 Guided Attention Loss

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class LocationSensitiveAttention(nn.Module):
    """Tacotron2 的 location-sensitive attention 实现"""
    def __init__(self, enc_dim=512, dec_dim=1024, attn_dim=128, conv_channels=32, kernel=31):
        super().__init__()
        self.loc_conv = nn.Conv1d(1, conv_channels, kernel_size=kernel,
                                  padding=(kernel - 1) // 2, bias=False)
        self.loc_proj = nn.Linear(conv_channels, attn_dim, bias=False)
        self.query_proj = nn.Linear(dec_dim, attn_dim, bias=False)
        self.key_proj = nn.Linear(enc_dim, attn_dim, bias=False)
        self.v = nn.Linear(attn_dim, 1, bias=False)
        # 单调对齐初始化: 偏置项使初始注意力偏向对角线
        self.processors = nn.Linear(attn_dim, 1, bias=False)

    def init_attention(self, enc_out):
        self.prev_alpha = enc_out.new_zeros(enc_out.size(0), enc_out.size(1))

    def forward(self, enc_out, dec_state):
        """
        enc_out:   [B, N, enc_dim]  编码器输出 (N 个音素)
        dec_state: [B, dec_dim]     上一步解码 RNN 隐状态
        return:    context [B, enc_dim], alpha [B, N]
        """
        # 1. Location 项: 上一帧累积注意力 -> 卷积 -> 投影
        loc_feat = self.loc_conv(self.prev_alpha.unsqueeze(1))   # [B, C, N]
        loc_feat = self.loc_proj(loc_feat.transpose(1, 2))       # [B, N, attn_dim]

        # 2. 打分 (内容 + 位置)
        score = self.v(torch.tanh(
            self.query_proj(dec_state).unsqueeze(1)              # [B, 1, attn_dim]
            + self.key_proj(enc_out)                             # [B, N, attn_dim]
            + loc_feat)).squeeze(-1)                             # [B, N]

        alpha = F.softmax(score, dim=-1)                         # [B, N]
        self.prev_alpha = self.prev_alpha + alpha                # 累积注意力
        context = torch.bmm(alpha.unsqueeze(1), enc_out).squeeze(1)  # [B, enc_dim]
        return context, alpha


def guided_attention_loss(alpha, N, M, g=0.2):
    """
    alpha: [B, N_frames, M_text] 注意力权重矩阵
    惩罚偏离对角线 (n/N ≈ m/M) 的注意力分布
    """
    B = alpha.size(0)
    n = torch.arange(N, dtype=torch.float32).view(N, 1) / N      # [N, 1]
    m = torch.arange(M, dtype=torch.float32).view(1, M) / M      # [1, M]
    W = 1.0 - torch.exp(-((n - m) ** 2) / (2 * g * g))           # [N, M]
    W = W.unsqueeze(0).to(alpha.device)                          # [1, N, M]
    return (alpha * W).sum(dim=(1, 2)).mean() / (N * M)

# ==================== 测试 ====================
if __name__ == "__main__":
    B, N_text, N_frames, enc_dim, dec_dim = 2, 25, 200, 512, 1024
    attn = LocationSensitiveAttention(enc_dim, dec_dim)
    enc_out = torch.randn(B, N_text, enc_dim)
    dec_state = torch.randn(B, dec_dim)

    attn.init_attention(enc_out)
    context, alpha = attn(enc_out, dec_state)
    print(f"context: {context.shape}, alpha: {alpha.shape}")     # [2,512], [2,25]

    alpha_seq = torch.softmax(torch.randn(B, N_frames, N_text), dim=-1)
    print(f"Guided Attention Loss: {guided_attention_loss(alpha_seq, N_frames, N_text):.4f}")
```

## 9. 总结与最佳实践

* **前端不可省**：即便端到端模型可以直接吃字符，工业系统几乎都保留 G2P + 多音字消歧 + TN，前端错误（读错多音字、数字读法错）是用户最易感知的 badcase。
* **演进主线**：拼接（高音质、不灵活）→ HMM-GMM（灵活、音质差）→ 端到端 AR（音质高、不稳定）→ 显式时长/NAR（稳定、可控、快）。
* **Attention 是 AR-TTS 的阿喀琉斯之踵**：Guided attention、location-sensitive attention、单调约束都是补丁，根治方案是显式时长建模。
* **面试要点**：能推导 guided attention 公式、解释 location 项作用（把历史对齐信息作为特征，抑制注意力抖动与重复）、说清 HMM-TTS 过平滑的成因。

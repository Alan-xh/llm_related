# 4. 音效生成与文本-音频对齐

## 1. 概述

**通用音频生成（General Audio Generation）** 指语音与音乐之外的音效（sound effects）与环境音（environmental sounds）生成，即 text-to-audio（TTA）：输入 "a dog barking in the rain"，输出对应波形。与语音/音乐相比，其挑战在于：

* **类别开放**：真实世界声音类别极广（AudioSet 有 632 类、>200 万片段）；
* **文本描述弱对齐**：音效没有歌词/乐谱这类精确监督，文本-音频对齐要靠**对比学习**（CLAP）建立；
* **评估困难**：没有 ASR/乐理那样的代理指标，主要依赖 **FAD** 与 **CLAP score**。

代表系统：AudioGen（Meta，AR 路线）、AudioLDM 系列（扩散路线）、Stable Audio / Tango / Make-an-Audio。本文按"条件机制 -> 对齐模型 -> 生成系统 -> 数据 -> 评估 -> 引导策略"展开。

```
Text-to-Audio 系统两要素:

  对齐: 文本/音频 ──> [CLAP 双塔对比学习] ──> 共享 embedding 空间 (检索/条件/评估)
  生成: 文本 ──> [Text Encoder] ──条件──> [AR LM 或 Diffusion] ──> 波形/latent ──> 音频

```

## 2. 文本条件机制：Cross-Attention vs. AdaLN

### 2.1 Cross-Attention（交叉注意力注入）

将文本 encoder 输出的 token 序列 $c_{1:L}$ 作为 key/value，扩散网络中间层特征作为 query：

$$\text{CrossAttn}(h, c) = \text{Softmax}\!\Big( \frac{Q(h) K(c)^\top}{\sqrt{d}} \Big) V(c), \quad Q = W_q h,\ K = W_k c,\ V = W_v c$$

* **优点**：文本 token 与音频时间帧之间建立**细粒度对齐**（哪些词对应哪一段声音），可做 attention map 可视化与词级编辑（prompt-to-prompt 类控制）；
* **缺点**：每层引入额外注意力和 KV 参数，推理开销大；
* **使用者**：Stable Diffusion 系（AudioLDM 2、Tango 系列沿用）。

### 2.2 AdaLN / FiLM（全局调制注入）

将文本 pooling 成单一向量（或与 timestep embedding 相加），预测每层归一化的 scale/shift：

$$h' = \gamma(c, t) \cdot \text{Norm}(h) + \beta(c, t)$$

* **优点**：参数与算力开销极小（无 cross-attn），条件作为全局"风格旋钮"注入；与 DiT（Diffusion Transformer）天然契合；
* **缺点**：丢失词级细粒度对齐，对复杂长描述（多事件序列，如 "thunder, then a dog barks"）时序控制力弱；
* **使用者**：DiT 系（Stable Audio 2.0 后期、FLAN-TTS 类 Flow Matching 模型）；MusicGen 的 LM 中 cross-attention 与全局条件均有使用。

### 2.3 对比与选型

| 维度 | Cross-Attention | AdaLN / FiLM |
| --- | --- | --- |
| 粒度 | token 级（词-时间段对齐） | 全局（整句风格） |
| 参数/算力 | 较高 | 极低 |
| 长描述/多事件 | 强 | 弱 |
| 可编辑性 | 词级 attention 编辑 | 只能整句改 |
| 典型模型 | AudioLDM 2、Tango 2 | DiT 系、Flow Matching 系 |

> 实践中常见**混合**：全局 embedding 走 AdaLN 控制风格/音色，token 序列走 cross-attn 控制内容时序。

## 3. CLAP / AudioCLIP：文本-音频对比学习对齐

### 3.1 CLAP 原理（Contrastive Language-Audio Pretraining）

CLAP（Microsoft, 2022，思想源自 CLIP）采用双塔结构：

* **Audio tower**：HTS-AT（层次 token-语义 audio transformer）或 CNN14，输入 48 kHz 波形；
* **Text tower**：BERT/GPT-2 类文本 encoder；
* **对齐目标**：batch 内 $N$ 个 `<音频, 文本>` 对，最大化配对相似度、最小化非配对相似度（对称 InfoNCE）：

$$\mathcal{L} = -\frac{1}{2N} \sum_{i=1}^{N} \Big[ \log \frac{\exp(\text{sim}(a_i, t_i)/\tau)}{\sum_j \exp(\text{sim}(a_i, t_j)/\tau)} + \log \frac{\exp(\text{sim}(t_i, a_i)/\tau)}{\sum_j \exp(\text{sim}(t_i, a_j)/\tau)} \Big]$$

其中 $\text{sim}(\cdot)$ 为余弦相似度（对 audio/text embedding 先 L2 归一再内积），$\tau$ 为可学习温度（初值 0.07，CLIP 惯例）。

* **训练数据**：AudioCaps（~5 万 caption）、Clotho（~6 千）、Macrosound（LAION 整理的 ~63 万音频-文本对）等；
* **零样本分类**：在 AudioSet/Zeroshot 环境音分类上，用类名做 prompt（"this is a sound of {label}"）即可零样本推理，效果接近全监督。

### 3.2 AudioCLIP 与后续

* **AudioCLIP**（2021）：更早的工作，audio tower 用 ESResNeXt，还支持**音频-图像-文本**三模态对齐；
* **MS-CLAP 2023**：升级 audio tower 为 HTS-AT、text tower 为 GPT-2，成为 AudioLDM 2/Tango 的默认文本编码器；
* **LAION-CLAP**：开源大规模版（63 万对 + 6 种配置），是当前开源自建 TTA 系统的事实标准编码器。

### 3.3 CLAP 在生成系统中的三重角色

1. **条件编码器**：CLAP text embedding 作为 diffusion 的条件（AudioLDM 用 CLAP + FLAN-T5 双编码器拼接）；
2. **检索增强**：生成前先检索近邻真实音频作为条件参考或数据增强；
3. **自动评估**：生成音频与输入文本的 CLAP 相似度即 **CLAP score**（见第 6 节）。

## 4. 音效/环境音生成系统

### 4.1 AudioGen（Meta, 2022）-- AR 路线

* 与 MusicGen 同族：单层 codebook 的 **SoundStream 类 codec**（50 Hz、$K=2048$，专为环境音训练，非分层 RVQ 以降低长序列难度）；
* **条件**：10 层 Transformer LM + T5 text encoder，cross-attention 注入；训练时 10% 文本 dropout 以支持 CFG；
* 特点：对**时序事件组合**（序列事件先后发生）描述的遵循度好（自回归的时间顺序归纳偏置）。

### 4.2 AudioLDM（2023）-- Latent Diffusion 路线

* **第一代**：CLAP（音频侧）训练 VAE -> 在 Mel latent 上扩散（U-Net + cross-attn，条件为 CLAP text emb + 若干步 CFG）；
* **AudioLDM 2**：双前置表示 + GPT-2 "LMA-D" 桥接统一 TTS/TTM/TTA，条件进一步用 FLAN-T5；
* **Tango / Tango 2**（CMU）：AudioLDM 架构 + 数据清洗（低质 caption 过滤）+ **DPO 风格偏好微调**（Tango 2），证明数据质量对 TTA 影响巨大；
* **Make-an-Audio 系**：引入多模态条件（文本 + 音频描述 + 帧级时序控制）。

### 4.3 两条路线对比（面试常考）

| 维度 | AR（AudioGen） | Diffusion（AudioLDM） |
| --- | --- | --- |
| 时序多事件控制 | 强（因果顺序） | 弱（全局迭代） |
| 推理速度 | 慢于实时（逐 token，~50/s） | 10~50 步可并行（DPM-Solver 加速） |
| 采样多样性 | 温度/top-k 控制 | latent 噪声 + CFG scale 控制 |
| 长音频 | token 数线性增长，一致性好 | 受训练窗限制，需滑窗 |
| 生态 | 与 LLM 兼容 | 与图像扩散生态（diffusers）互通 |

## 5. 数据集

| 数据集 | 规模 | 特点 |
| --- | --- | --- |
| **AudioCaps** | ~4.6 万 caption / ~4.6 千音频（AudioSet 子集） | 每条 10 秒、单句英文 caption（~8~10 词），TTA 最常用基准；test 分 human/machine 写法 |
| **Clotho** | ~6 千音频 / 2.4 万 caption | 每条音频 5 个不同 caption（15~50 词），长描述、聚焦细节；由 crowdsourcing 严格质检 |
| AudioSet | 200 万+ 片段 / 632 类 | 只有**标签**（多标签，弱标注），不是 caption 数据；CLAP 预训练主力（标签模板化成句子） |
| Macrosound / WavCaps | 63 万 / 40 万对 | 网络爬取 + 清洗 + （WavCaps 用 GPT 精简 BLAST/clotho 描述），工业预训练主流 |

> **实践要点**：TTA 模型对 caption 风格极其敏感（"a man speaks as a bird chirps" vs "bird chirping"）。工业上常用 LLM 重写/清洗 caption 统一风格；评估时注意 AudioCaps test 中 machine-generated caption 会带来虚高。

## 6. 评估：FAD 与 CLAP Score

### 6.1 FAD（Fréchet Audio Distance）

FAD 是音频生成的 **FID 类指标**：用预训练音频分类器（VGGish 或 PANN/CLAP audio tower）分别提取**生成集**与**真实参考集**的 embedding，假设其服从高斯分布，计算两个分布的 Fréchet 距离：

$$\text{FAD} = \| \mu_r - \mu_g \|_2^2 + \text{Tr}\big( \Sigma_r + \Sigma_g - 2 (\Sigma_r \Sigma_g)^{1/2} \big)$$

* **越低越好**；典型量级：AudioLDM 在 AudioCaps 上 FAD(VGGish) ~ 3~5，高质量系统 < 2；
* **优点**：无需参考样本一一对应，感知相关性比 STFT 距离好；
* **缺点**：度量"分布整体质量"而非"文本遵循度"；VGGish embedding 的感知上限有限（用 PANN/CLAP 提取的 FAD 相关性更佳，记作 FAD$_{\text{CLAP}}$）；参考集大小影响数值可比性。

### 6.2 CLAP Score（文本-音频对齐度）

$$\text{CLAP score} = \cos\big( E_{\text{audio}}(x_{\text{gen}}),\ E_{\text{text}}(c) \big) \times 100$$

* **越高越好**，衡量生成音频与输入文本的语义一致性；典型 0.2~0.4（归一化后）量级；
* **缺陷**：可能被"讨好 CLAP"的生成（adversarial to evaluator）欺骗；同一 CLAP 模型既做条件又做评估时要小心（用不同版本 CLAP 交叉评估更可信）。

### 6.3 其它指标

* **IS（Inception Score 类）**：KL(条件标签分布 || 边缘标签分布)，衡量质量+多样性；
* **kNN-CLAP / retrieval 指标**：生成音频在真实库中最近邻的文本重合率；
* **人评**：Overall Impression（1~100）+ 文本相关性（OL 系工作沿用 AudioCaps 人评协议），最终标准。

## 7. 分类器引导（CG）vs. 无分类器引导（CFG）

### 7.1 Classifier Guidance（Dhariwal & Nichol, 2021）

在扩散去噪时，用**外部分类器** $p_\phi(y \mid x_t)$ 的梯度修正分数方向：

$$\hat{\epsilon}_\theta(x_t, t, y) = \epsilon_\theta(x_t, t) - \sqrt{1 - \bar{\alpha}_t}\, s \cdot \nabla_{x_t} \log p_\phi(y \mid x_t)$$

* 需要一个**对噪声鲁棒训练的分类器**（在加噪数据上训练），工程负担重；音频上少用。

### 7.2 Classifier-Free Guidance（Ho & Salimans, 2022）

训练**同一个条件模型**，随机（如 10~20%）丢弃条件 $c$（替换为空条件 $\varnothing$）；采样时把条件分数与无条件分数做**外推**：

$$\tilde{\epsilon}_\theta(x_t, t, c) = \epsilon_\theta(x_t, t, \varnothing) + w \cdot \big( \epsilon_\theta(x_t, t, c) - \epsilon_\theta(x_t, t, \varnothing) \big)$$

* $w = 1$ 退化为普通条件采样；$w > 1$ 向条件方向外推，**提高文本遵循度但牺牲多样性**（过度引导会导致过饱和/伪影，音频上表现为"过锐"的频谱或重复纹理）；
* 代价：每步要跑**两次前向**（条件 + 无条件）；工程上可用**批内拼接**一次算完；
* **音频系统经验值**：AudioLDM CFG scale ~3（分阶段加权），Stable Audio/Tango 2~5；AudioGen（AR 版 CFG）在 logit 空间做同类外推。

### 7.3 对比

| 维度 | Classifier Guidance | Classifier-Free Guidance |
| --- | --- | --- |
| 额外模型 | 需噪声鲁棒分类器 | 无（单模型，条件 dropout） |
| 训练改动 | 无 | 条件随机置空 10~20% |
| 推理开销 | 分类器梯度反传 | 条件/无条件双前向 |
| 灵活度 | 只能用分类器可表达的标签 | 任意自由文本条件 |
| 工业采用 | 少 | **事实标准** |

## 8. PyTorch 代码实战：CLAP 对比学习 + CFG 采样片段

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


# ------------------------------------------------------------
# 1. 简化版 CLAP 双塔对比学习
# ------------------------------------------------------------
class CLAPModel(nn.Module):
    def __init__(self, audio_dim=2048, text_dim=768, embed_dim=512):
        super().__init__()
        self.audio_proj = nn.Linear(audio_dim, embed_dim)
        self.text_proj = nn.Linear(text_dim, embed_dim)
        self.logit_scale = nn.Parameter(torch.tensor(0.07).log())  # 可学习温度

    def encode(self, audio_feat=None, text_feat=None):
        out = []
        if audio_feat is not None:
            out.append(F.normalize(self.audio_proj(audio_feat), dim=-1))
        if text_feat is not None:
            out.append(F.normalize(self.text_proj(text_feat), dim=-1))
        return out

    def clip_loss(self, audio_feat, text_feat):
        """对称 InfoNCE; audio_feat/text_feat: [N, D] (backbone 输出)"""
        a, t = self.encode(audio_feat, text_feat)          # 各 [N, E], 已 L2 归一
        tau = self.logit_scale.exp().clamp(max=100.0)      # 温度防爆炸
        logits = tau * a @ t.t()                           # [N, N]
        labels = torch.arange(a.size(0), device=a.device)
        loss_i2t = F.cross_entropy(logits, labels)         # audio -> text
        loss_t2i = F.cross_entropy(logits.t(), labels)     # text -> audio
        return (loss_i2t + loss_t2i) / 2, logits

    @torch.no_grad()
    def clap_score(self, audio_feat, text_feat):
        """评估用: 余弦相似度 x 100"""
        a, t = self.encode(audio_feat, text_feat)
        return (a * t).sum(dim=-1) * 100


# ------------------------------------------------------------
# 2. CFG 采样 (diffusion) 与 CFG-logit 采样 (AR) 核心片段
# ------------------------------------------------------------
def cfg_denoise_step(unet, x_t, t, text_emb, guidance_scale=3.0):
    """条件与无条件一次拼接前向, 省一半显存/调度开销"""
    B = x_t.size(0)
    x_in = torch.cat([x_t, x_t], dim=0)                    # [2B, ...]
    t_in = torch.cat([t, t], dim=0)
    c_in = torch.cat([text_emb, torch.zeros_like(text_emb)], dim=0)  # 条件/空条件
    eps = unet(x_in, t_in, c_in)
    eps_cond, eps_uncond = eps.chunk(2, dim=0)
    return eps_uncond + guidance_scale * (eps_cond - eps_uncond)


def cfg_ar_logits(lm, tokens, text_emb, guidance_scale=1.5):
    """AR 模型 (AudioGen 风格) 的 logit 空间 CFG"""
    logits_c = lm(tokens, text_emb)                        # 条件分布
    logits_u = lm(tokens, torch.zeros_like(text_emb))      # 无条件分布
    return logits_u + guidance_scale * (logits_c - logits_u)


if __name__ == "__main__":
    N, D_a, D_t = 8, 2048, 768
    clap = CLAPModel()
    loss, logits = clap.clip_loss(torch.randn(N, D_a), torch.randn(N, D_t))
    print(f"CLAP InfoNCE loss: {loss.item():.4f}  (随机水平 ~ ln(8)={torch.log(torch.tensor(8.)):.3f})")
    print(f"CLAP score (自配对, 训练前): {clap.clap_score(torch.randn(N, D_a), torch.randn(N, D_t)).mean():.2f}")

# 2. AudioLM 与离散 Tokenization

## 1. 概述

**AudioLM**（Google, 2022）开辟了"**音频也能像语言一样建模**"的路线：先把连续波形离散化为一串 token，再用语言模型（LM）自回归生成 token，最后由 decoder 还原波形。这一范式的基础是**神经音频编解码器（Neural Audio Codec）**--SoundStream 与 EnCodec 提出的 **RVQ（Residual Vector Quantization）**，能把 24 kHz 音频压缩到每秒几百~几千 bit 而保持高保真（即 **acoustic tokens**）；而 AudioLM 进一步引入自监督模型（w2v-BERT / HuBERT）K-means 得到的 **semantic tokens**，分层建模"内容"与"声学细节"。

该路线直接孕育了 MusicLM、MusicGen、VALL-E 等模型，是当前音频生成与 Speech-LLM（如 GPT-4o voice）最重要的基础设施之一。

```
AudioLM 范式总览:

  波形 ──> [Semantic Encoder (w2v-BERT + K-means)] ──> semantic tokens (内容/语音学)
       ──> [Codec (SoundStream/EnCodec + RVQ)] ──> acoustic tokens (音色/细节/环境)
                                │
  生成: 文本/提示 ──> [Transformer LM 自回归] ──> token 流 ──> [Codec Decoder] ──> 波形

```

## 2. 神经音频编解码器：SoundStream 与 EnCodec

### 2.1 整体架构：Encoder-Quantizer-Decoder + 对抗训练

SoundStream（Google, 2021）与 EnCodec（Meta, 2022）结构高度一致：

* **Encoder**：一维卷积 + 下采样 strided conv，24 kHz 波形被降采样到 75 Hz 帧率（下采样 320 倍），每帧输出 128 维连续向量；
* **Quantizer**：RVQ 将每帧向量量化为 $N_q$ 个 codebook 索引（如 8 个 codebook、每个 1024 entries）；
* **Decoder**：镜像上采样恢复波形；
* **训练损失**：重构损失（多尺度频谱 L1/L2）+ **对抗损失**（STFT 判别器 + 波形判别器）+ **特征匹配损失（feature matching）**：

$$\mathcal{L} = \lambda_{\text{rec}} \mathcal{L}_{\text{rec}} + \lambda_{\text{adv}} \mathcal{L}_{\text{adv}} + \lambda_{\text{fm}} \mathcal{L}_{\text{fm}} + \lambda_{\text{commit}} \mathcal{L}_{\text{commit}}$$

实测 EnCodec 24 kHz mono @ 6 kbps 的 MOS（4.13）已接近原始音频（4.33），远超传统 Opus/EVS 同码率表现。

```
SoundStream / EnCodec 编码流程 (24kHz, 下采样 320x -> 75Hz 帧率):

波形 x ∈ R^{1xL} ──> [Conv1d] ──> [StridedConv x4 (↓2,4,5,8)] ──> z ∈ R^{128xL/320}
                                                                     │
                                                     ┌─────────────────▼─────────────────┐
                                                     │   RVQ:  q1 -> r1 -> q2 -> r2 -> …  │
                                                     │   (Nq 级残差量化, 每级 1024 codes)  │
                                                     └─────────────────┬─────────────────┘
                                                                       ▼
                                                     [StridedConvTranspose x4] ──> 波形 x̂

```

### 2.2 RVQ（Residual Vector Quantization）原理

RVQ 是 VQ 的级联扩展：用多级 codebook 逐级量化上一级的**残差**。

设第 $i$ 级 codebook 为 $\mathcal{C}_i = \{e_{i,1}, \dots, e_{i,K}\}$（$K=1024$），对连续向量 $z$：

$$q^{(0)} = z, \quad e_i^* = \arg\min_{e \in \mathcal{C}_i} \| q^{(i-1)} - e \|_2, \quad q^{(i)} = q^{(i-1)} - e_i^*, \quad i = 1, \dots, N_q$$

最终量化结果为各级码字之和：

$$\hat{z} = \sum_{i=1}^{N_q} e_i^*, \qquad \text{tokens} = (e_1^*, e_2^*, \dots, e_{N_q}^*)$$

**误差上界**：每级量化误差不超过上一级残差的最远码距，且码本按几何级数 $K^{-i/D}$ 缩小等效体积，因此 $N_q$ 级 RVQ 等效于一个 $K^{N_q}$ 大小的单码本（$1024^8 \approx 2^{80}$ 种组合），却只需存储与查找 $8 \times 1024$ 个码字。

**比特率计算**（帧率 75 Hz、$K=1024=2^{10}$）：

$$\text{bps} = 75 \times N_q \times \log_2 K = 75 \times N_q \times 10 \ \text{bit/s}$$

即 $N_q = 2 \to 1.5$ kbps，$N_q = 8 \to 6$ kbps，$N_q = 32 \to 24$ kbps（EnCodec 支持运行时增减 $N_q$，实现**可变码率**而无需重训）。

### 2.3 Codebook 训练：VQ Loss 与 EMA 更新

量化不可导，训练依赖直通估计器（Straight-Through Estimator, STE）与两组损失：

$$\mathcal{L}_{\text{VQ}} = \underbrace{\| \text{sg}[z] - \hat{z} \|^2}_{\text{codebook loss}} + \beta \underbrace{\| z - \text{sg}[\hat{z}] \|^2}_{\text{commitment loss}}$$

* **codebook loss**：只更新 codebook，把码字拉近 encoder 输出；工程上常用 **EMA 更新**（不梯度下降，而是以各码字的聚类统计指数滑动更新，SoundStream 默认，收敛更稳）；
* **commitment loss**（$\beta=0.25$）：只更新 encoder，约束其输出不要在码字间频繁跳变；
* **STE**：$\hat z$ 的梯度直接拷贝给 $z$（前向用量化值、反向当恒等）。

### 2.4 Codebook Collapse 问题与解决方案

**现象**：训练后期大部分样本只映射到极少数（甚至 1 个）码字，码本利用率从 1024 跌到几十，重构质量骤降。**成因**：死码字得不到梯度 -> 永远不被选中 -> 恶性循环。

工业界常用对策（EnCodec / SoundStream / DAC 均有使用）：

| 方案 | 做法 | 出处 |
| --- | --- | --- |
| **码字重启（dead code restart）** | 统计每步各码字命中数，把命中率低于阈值（如 batch 内 <1 次）的死码字随机重置为当前 batch 的 encoder 输出向量 | EnCodec、DAC |
| **EMA + 随机初始化** | EMA 更新天然平滑，配合码字均匀初始化 | SoundStream |
| **码本划分 / 低维投影** | 把 codebook 从 128 维投影到 8/16 维做欧氏查找（如 $z \to Wz$, $e \to We$），缓解维度灾难导致的距离失效 | DAC（Descript Audio Codec）、EnCodec 变体 |
| ** entropy / 平衡正则** | 对码字使用分布加熵正则，鼓励均匀使用 | SoundStream（balanced entropy） |
| **有限标量量化 FSVQ** | 干脆用标量桶代替向量码本，结构上杜绝 collapse | 2023 后期工作（如 SpeechTokenizer 后续） |

> **面试要点**：codebook 利用率（perplexity）是 codec 训练最重要的监控指标之一，健康训练应接近 $\log K \approx 10$（nats）或码字命中率分布均匀。

## 3. Semantic Tokens vs. Acoustic Tokens 分层

### 3.1 Semantic Tokens（w2v-BERT / HuBERT + K-means）

* **提取**：用自监督模型（w2v-BERT、HuBERT、data2vec）抽取中间层表征（通常 25/50 Hz 帧率），再对帧级特征做 **K-means 聚类**（$K$ 取 500~1024 或更大，AudioLM 用 w2v-BERT 第 12 层、$K=1024$，帧率 25 Hz）；
* **性质**：低帧率、信息瓶颈强，主要捕捉**内容**（语音学、语义、乐句结构），丢弃音色/环境/录音细节；
* **优点**：序列短（25~50 token/s），LM 建模长程依赖容易；对说话人、噪声鲁棒。

### 3.2 Acoustic Tokens（Codec RVQ tokens）

* **提取**：SoundStream/EnCodec 的 RVQ 第 $1 \sim N_q$ 层索引；
* **性质**：高帧率（75 Hz $\times$ $N_q$ 层 = 每秒 $75N_q$ 个 token），保留音色、录音环境、高保真细节；
* **缺点**：直接用 LM 建模全部 acoustic token 时，长程语义一致性差（模型把容量浪费在细节上）、序列过长。

### 3.3 分层对比

| 维度 | Semantic tokens | Acoustic tokens |
| --- | --- | --- |
| 来源 | w2v-BERT/HuBERT + K-means | Codec RVQ 索引 |
| 帧率 | 25~50 Hz（单层） | 75 Hz $\times N_q$ 层 |
| 携带信息 | 内容、语义、结构 | 音色、细节、环境、保真度 |
| 可还原波形 | 否（需配合 acoustic） | 是（codec decoder 直接解码） |
| LM 建模难度 | 低（序列短） | 高（序列长、容量被细节占用） |
| 典型用途 | 内容规划、SST/语音翻译 | 高保真声学实现层 |

## 4. AudioLM 三阶段生成

AudioLM 将生成拆成三个级联的 LM，兼顾**长期一致性**与**高保真**：

```
AudioLM 三阶段:

阶段1 Semantic LM:   [semantic tokens 预训练语料] ──> LM ──> 生成 semantic tokens S
                          │ (建模长程内容/结构)
                          ▼ (S 作为 prompt 条件)
阶段2 Coarse Acoustic: [S + RVQ 第1层(Q1) tokens] ──> LM ──> 生成 Q1 tokens
                          │ (补全音色与主要声学轮廓, 如音色、韵律)
                          ▼ (S + Q1 作为条件)
阶段3 Fine Acoustic:  [S + Q1 + Q2~Q4 残差层] ──> LM ──> 生成 Q2~Q4 (并行/独立)
                          │
                          ▼
                      [SoundStream Decoder] ──> 24 kHz 波形

```

1. **Semantic 阶段**：在纯 semantic tokens 上训练 Decoder-only Transformer；负责"说什么/演奏什么"（长程一致性）；
2. **Coarse acoustic 阶段**：以 semantic tokens 为前缀，生成 RVQ **第一层** token（对应最大能量残差），决定音色、说话人身份、环境；
3. **Fine acoustic 阶段**：以 (semantic + Q1) 为前缀，并行生成 **Q2~Q4 层**（各层独立预测，因为残差层之间条件相关弱），补全高保真细节；最终 tokens 送 SoundStream decoder。

**效果**：语音 continuation 任务上，人评 3 秒提示续写 20 秒，韵律/内容/说话人一致性显著优于纯 acoustic token 基线；同时语音识别与说话人识别模型无法可靠区分生成与真实音频（逼真度量级）。

> **面试要点**：为什么要分层而不是一个 LM 直接生成所有 token？--(1) 高帧率多层级 token 序列太长，注意力资源浪费在细节上，长程内容一致性差；(2) semantic 位置在前，配合 coarse-to-fine 的因果前缀，让"内容规划"与"声学实现"解耦，各阶段数据可独立大规模预训练。

## 5. MusicLM / MusicGen 延续

### 5.1 MusicLM（Google, 2023）

* 三阶段与 AudioLM 同构：semantic（MuLan / w2v-BERT 类表征 K-means）-> acoustic（SoundStream RVQ）；
* **文本条件注入**：MuLan 双塔（音频-文本对比学习）将文本与音频对齐到同一 embedding 空间，作为 semantic LM 的前缀条件，实现 text-to-music；
* 局限：生成速度慢（多阶段自回归 + 层级分解，分钟级音频需数分钟）。

### 5.2 MusicGen（Meta, 2023）

对 AudioLM 式层级做了**工程简化**，成为开源事实标准：

* **Codec**：EnCodec 32 kHz mono，帧率 50 Hz，$N_q = 4$ 层 codebook（$K=2048$）；
* **单阶段 LM + codebook interleaving**：一个 300M/1.5B/3.3B Decoder-only Transformer，用 **delay pattern（ramp pattern）** 把同一帧的 4 层 token 错开一个位置排列，使其仍可用标准 next-token prediction 训练，无需三阶段级联；
* **文本条件**：T5/FLAN-T5 encoder + cross-attention，并使用 **CFG（classifier-free guidance）**；
* **效果**：以 10 倍以上的参数效率超越 MusicLM（人评），单 A100 生成 30 秒音乐仅需数十秒，支持 melody conditioning（以哼唱旋律控制生成）。

```
MusicGen delay pattern (Nq=4, 每帧 4 层 token 错位排列):

帧:      f1     f2     f3     f4   ...
Q1:     [1a]   [2a]   [3a]   [4a]
Q2:           [1b]   [2b]   [3b]
Q3:                  [1c]   [2c]
Q4:                         [1d]
  -> 展平成: 1a, 2a 1b, 3a 2b 1c, 4a 3b 2c 1d, ... (因果可自回归训练)

```

### 5.3 后续演进

* **SpeechTokenizer / Single-Codec / X-Codec**：把 semantic 信息蒸馏进 RVQ 第一层，实现"一层 token 兼顾语义与声学"；
* **Mimi（Kyutai Moshi, 2024**）：12.5 Hz 低帧率 + semantic 蒸馏 + split RVQ，专为大模型流式对话设计；
* **Speech-LLM 融合**：GPT-4o voice、Qwen-Audio 类模型直接以离散 audio token 作为 LLM 词表的一部分。

## 6. PyTorch 代码实战：简化 RVQ 实现

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


class VectorQuantizerEMA(nn.Module):
    """单级 VQ, EMA codebook 更新 + dead code restart (EnCodec 风格)"""

    def __init__(self, num_codes: int = 1024, code_dim: int = 128,
                 beta: float = 0.25, decay: float = 0.99):
        super().__init__()
        self.num_codes, self.code_dim, self.beta = num_codes, code_dim, beta
        self.decay = decay
        embed = torch.randn(num_codes, code_dim) * 0.02  # 随机初始化
        self.register_buffer("embed", embed)
        self.register_buffer("cluster_size", torch.zeros(num_codes))
        self.register_buffer("embed_avg", embed.clone())

    def forward(self, z: torch.Tensor):
        """z: [B, D, T] -> (quantized [B, D, T], ids [B, T], vq_loss)"""
        z_t = z.permute(0, 2, 1)                       # [B, T, D]
        # 最近邻查找: ||z - e||^2 = ||z||^2 - 2 z·e + ||e||^2
        dist = (z_t.pow(2).sum(-1, keepdim=True)
                - 2 * z_t @ self.embed.t()
                + self.embed.pow(2).sum(-1))           # [B, T, K]
        ids = dist.argmin(dim=-1)                      # [B, T]
        q = self.embed[ids].permute(0, 2, 1)           # [B, D, T]

        if self.training:
            with torch.no_grad():
                onehot = F.one_hot(ids, self.num_codes).float()   # [B, T, K]
                cnt = onehot.sum(dim=(0, 1))                       # [K]
                embed_sum = torch.einsum("btk,btd->kd", onehot, z_t)
                # EMA 更新
                self.cluster_size.mul_(self.decay).add_(cnt, alpha=1 - self.decay)
                self.embed_avg.mul_(self.decay).add_(embed_sum, alpha=1 - self.decay)
                n = self.cluster_size.sum()
                cluster_size = (self.cluster_size + 1e-5) / (n + self.num_codes * 1e-5) * n
                self.embed.copy_(self.embed_avg / cluster_size.unsqueeze(1))
                # Dead code restart: 命中过少的码字随机重置为当前 batch 向量
                dead = self.cluster_size < 1e-3
                if dead.any():
                    rand_z = z_t.reshape(-1, self.code_dim)[
                        torch.randint(0, z_t.numel() // self.code_dim, (dead.sum(),))]
                    self.embed[dead] = rand_z
                    self.embed_avg[dead] = rand_z
                    self.cluster_size[dead] = 1.0

        # commitment loss (只约束 encoder); codebook 由 EMA 更新
        vq_loss = F.mse_loss(z, q.detach())
        # Straight-Through: 前向用量化值, 反向梯度直通
        q = z + (q - z).detach()
        return q, ids, vq_loss


class ResidualVQ(nn.Module):
    """RVQ: Nq 级残差级联量化"""

    def __init__(self, num_quantizers: int = 8, **kw):
        super().__init__()
        self.layers = nn.ModuleList([VectorQuantizerEMA(**kw) for _ in range(num_quantizers)])

    def forward(self, z: torch.Tensor, nq: int = None):
        """z: [B, D, T]; 返回量化结果、每层 ids、总 loss"""
        nq = nq or len(self.layers)
        residual, quantized, total_loss, all_ids = z.clone(), 0.0, 0.0, []
        for i, layer in enumerate(self.layers[:nq]):
            q, ids, loss = layer(residual)
            residual = residual - q.detach() + (q - q).detach()  # 残差传递
            residual = residual - q  # 严格残差: r_i = z_i - e_i (在 STE 下可反传)
            quantized = quantized + q
            total_loss = total_loss + loss
            all_ids.append(ids)
        return quantized, torch.stack(all_ids, dim=1), total_loss / nq


if __name__ == "__main__":
    B, D, T = 2, 128, 150        # 2 秒音频 @ 75Hz 帧率
    rvq = ResidualVQ(num_quantizers=8, num_codes=1024, code_dim=D)

    z = torch.randn(B, D, T)     # 模拟 encoder 输出
    q, ids, loss = rvq(z, nq=4)  # 运行时只用前 4 层 -> 75*4*10 = 3 kbps
    print(f"Quantized: {tuple(q.shape)}, ids: {tuple(ids.shape)}  [B, Nq, T]")
    print(f"Bitrate @ nq=4, K=1024, 75Hz: {75 * 4 * 10 / 1000:.1f} kbps")
    print(f"VQ (commitment) loss: {loss.item():.4f}")
```

## 7. 总结与最佳实践

* **RVQ 是离散音频生成的基石**：多级残差码本以 $O(N_q \cdot K)$ 的存储实现 $K^{N_q}$ 的等效词表，且支持运行时可变码率；音频 LM 的"词表大小"即 $K$（1024/2048），远小于文本 LLM，但序列更长（75~600 token/s）。
* **Semantic/Acoustic 分层解耦内容与声学**：semantic tokens 用自监督表征 + K-means 提取，负责长程一致性；acoustic tokens 用 codec RVQ 提取，负责保真度。AudioLM 三阶段（semantic -> coarse -> fine）是这一思想的标准实现，MusicGen 用 delay pattern 将其压缩为单阶段。
* **Codec 训练 checklist**：重构（多尺度谱）+ 对抗 + feature matching + commitment loss；EMA codebook 更新 + dead code restart 防 collapse；监控 codebook perplexity。
* **工业界演进方向**：低帧率 codec（Mimi 12.5 Hz）、语义-声学统一 token（SpeechTokenizer/X-Codec）、以及"离散 AR + 连续扩散精修"的混合管线。

# 2. 音频 Encoder 与 LLM 对接

## 1. 概述

Speech-LLM 的核心链路是：**Audio Encoder 提取连续表征 -> Connector 转换为 LLM 可消费的 token -> LLM 统一推理**。这条链路上有三个关键设计决策，也是面试中最常被考察的三个问题：

1. **Encoder 选型**：用 ASR 导向的 Whisper Encoder，还是自监督的 HuBERT / w2v-BERT，还是音频理解导向的 CLAP / BEATs？
2. **Connector 设计**：Linear Projection（LLaVA 式）、Q-Former、CTC 压缩、平均池化，各自的压缩率与信息保真如何权衡？
3. **注入与对齐策略**：语音 token 放在哪里（prefix / prompt / embedding fusion）、训练时冻结 LLM 还是联合训练？

```
  音频波形 (16kHz)
       │
       ▼
 ┌───────────────┐     [T, D_a] 连续表征 (如 25~50 Hz 帧率)
 │ Audio Encoder │────────────────┐
 └───────────────┘                ▼
                        ┌──────────────────┐
                        │    Connector     │  压缩 + 维度对齐
                        │ (Linear/QFormer/ │──────> [M, D_l] 语音 embedding
                        │  CTC/Pooling)    │              │
                        └──────────────────┘              ▼
                                              ┌─────────────────────┐
  文本 token ────────────────────────────────>│    LLM Backbone     │
                                              └─────────────────────┘
```

## 2. 常见音频 Encoder 对比

### 2.1 四类主流 Encoder

| Encoder | 训练目标 | 表征特点 | 输出帧率 | 典型使用方 |
| --- | --- | --- | --- | --- |
| **Whisper Encoder** | 弱监督多任务（680kh 转写） | 强语义/内容导向，多语种 | 50 Hz（30s 输出 1500 帧） | Qwen-Audio、Qwen2-Audio、MiniCPM-o |
| **HuBERT / w2v-BERT** | 自监督（masked prediction / 对比） | 语义 + 部分声学，离散单元可用于生成 | 50 Hz | SpeechGPT、SLAM 类模型 |
| **CLAP** | 音频-文本对比学习（Contrastive） | 音频事件、语义描述导向 | ~2 Hz（8 秒 1 向量级） | 音频理解 / Audio Caption |
| **BEATs** | 迭代式 audio tokenizer + MLM | 非语义信息（事件、情感、环境） | ~12.5 Hz | SALMONN（与 Whisper 组成双编码器） |

### 2.2 选型考量

* **Whisper Encoder**：语义最强的开箱即用选择，多语种 + 语音鲁棒性好；但对音乐、环境声等非语音事件欠佳，且帧率高（50Hz）导致 token 冗余（大量静音帧）。
* **HuBERT / w2v-BERT**：无需标注可无限扩展；表征更「均匀」覆盖声学细节；其离散 K-means 单元是语音生成模型语义 token 的主流来源。
* **CLAP / BEATs**：面向通用音频理解，弥补 ASR encoder 的副语言盲区；帧率低但时间分辨率不足，不适合对齐细粒度任务。
* **工业实践**：追求内容任务（ASR/S2TT）选 Whisper 系；追求副语言（SER、语音诊疗、情感对话）考虑 Whisper + BEATs 双编码器（SALMONN 方案）；Qwen2-Audio 进一步用 Whisper 初始化后在海量多任务数据上继续预训练 encoder。

## 3. Connector 设计：四大流派

### 3.1 Linear Projection（LLaVA 式）

最简单直接：把相邻若干帧 concat 后经 MLP 投影到 LLM 维度。

$$h_i = W_2 \cdot \sigma\big(W_1 \cdot [e_{i \cdot k}; \dots; e_{i \cdot k + k - 1}]\big) + b$$

* **优点**：参数极少（~20M 级）、训练稳定、信息无损（不学习丢弃）。
* **缺点**：压缩率固定、序列仍长（k=4 时 10s 音频 -> ~60 token 尚可，1 分钟 -> 750 token 吃紧）。
* **代表**：Qwen-Audio（1 层 Linear + SwiLLM 注意力改造）、LLaVA 系视觉方案直接平移。

### 3.2 Q-Former（Query-based 压缩）

引入 $N$ 个可学习 query（如 32 个），对 encoder 输出做 cross-attention，把变长序列压成定长：

$$Q = \text{softmax}\Big(\frac{Q W_q (H W_k)^T}{\sqrt{d}}\Big) H W_v$$

* **优点**：token 数固定（与音频时长无关），LLM 上下文压力恒定；query 可学习「该关注什么」。
* **缺点**：定长压缩带来信息上界（长音频细节被合并）；训练需较精心调参。
* **变体**：SALMONN 使用**窗式 Q-Former（window-level query-based Transformer）**，每隔 1s 的窗压成 1 个 token，兼顾压缩率与时序保真；BLIP-2 原版 Q-Former 带对比/匹配多目标预训练。

### 3.3 CTC 压缩（对齐导向）

用 CTC 前向剔除空白帧：训练 encoder 加一个 CTC 头（对齐到文本），推理时只保留 CTC 非 blank 的帧作为 LLM 输入。

$$\text{keep}(t) = \mathbb{1}\big[\arg\max_v P_{\text{ctc}}(v \mid t) \neq \varnothing\big]$$

* **优点**：token 数自动正比于**语音内容量**而非时长（静音、停顿免费剔除）；对 ASR 类任务对齐天然。
* **缺点**：需要文本监督训练 CTC 头；丢弃的帧可能含副语言信息（笑声常被当 blank 丢掉）；非文本任务（SER）受损。
* **代表**：SLAM / mSLAM、部分 Speech-LLM（如 Parakeet 式 pipeline、FireRedAIT）、以及工业界「Whisper + CTC 二次压缩」方案。

### 3.4 平均池化 / 卷积下采样

对相邻 k 帧做 mean pooling 或 strided conv：

$$h_i = \frac{1}{k}\sum_{j=0}^{k-1} e_{i \cdot k + j}$$

* **优点**：零参数、实现一行。
* **缺点**：粗暴平均模糊快速变化的声学事件；通常只作为 2x~3x 的轻量压缩，配合其他 connector 使用。
* **代表**：Qwen2.5-Omni（Conv 下采样）、MiniCPM-o（多层 conv 逐步下采样至 ~每秒几个 token）。

### 3.5 Connector 对比总结

| 维度 | Linear | Q-Former | CTC 压缩 | Avg Pooling |
| --- | --- | --- | --- | --- |
| 压缩方式 | 固定 k 帧拼 1 | 定长 query 交叉注意力 | 内容驱动变长 | 平均 |
| token 数（10s 语音） | ~60（k=4） | 固定 32 | ~40（按音节数） | ~50（k=5） |
| 信息保真 | 高 | 中（上限定长） | 语义高/副语言低 | 低 |
| 额外监督 | 无 | 无 | 需文本 | 无 |
| 训练难度 | 低 | 中 | 中 | 无 |
| 代表 | Qwen-Audio、LLaVA | SALMONN、BLIP-2 | SLAM 类 | Omni 系 |

## 4. 下采样率与 token 数计算

面试常考「10 秒音频进 LLM 是多少 token」这类量级估算，必须熟练推导。

### 4.1 计算公式

设 encoder 输出帧率 $f_e$（帧/秒），下采样倍率 $k$，音频时长 $L$ 秒：

$$M = \Big\lceil \frac{f_e \cdot L}{k} \Big\rceil$$

### 4.2 典型数值

| 配置 | encoder 帧率 | 下采样 | 语音 token 率 | 10s 音频 token 数 |
| --- | --- | --- | --- | --- |
| Whisper Encoder + Linear | 50 Hz | 4x | 12.5 /s | 125 |
| Whisper Encoder + Conv 降采样 | 50 Hz | 8x | 6.25 /s | ~62 |
| CTC 压缩（中文） | 50 Hz | 内容驱动 | ~4~5 /s | ~45 |
| Q-Former | - | 定长 | 32 总量 | 32 |
| 语义离散 token（HuBERT） | 50 Hz | 2x | 25 /s | 250 |
| 声学 codec token（EnCodec 8 层 RVQ） | 75 Hz x 8 | - | 600 /s | 6000 |

**关键结论**：

1. 连续表征 + 适度下采样可把语音 token 率压到 **5~15 token/s**，与文本 token 率（中文 ~1.5 字/s）同量级偏多，LLM 可直接处理。
2. 声学 codec token（600+/s）**不能**直接进 LLM 常规上下文，必须用 NAR 分层（VALL-E）、残差预测（MusicGen）或强下采样专用 codec（SpeechLLM 的单码本 12.5/s 方案）。
3. 语音 token 率越高，保真越好但序列越长；**25 token/s 是一个经验分水岭**（Moshi：分别用 25Hz 语义 + 声学码流）。

## 5. 语音 token 注入位置

### 5.1 三种注入方式

```
(1) Prefix 注入（最常见，Qwen-Audio / SALMONN / LLaVA 系）
    [ <speech> x M ] [ <instruction> ] [ <response> ]
     ↑ 语音在前作上下文

(2) Prompt 交错注入（SpeechGPT / Speech-LLM 交互数据）
    [ inst ] [ speech_1 ] [ text_1 ] [ speech_2 ] [ text_2 ] ...
     ↑ 语音与文本交错，适合多轮语音对话

(3) Embedding Fusion（早期 / 新 trend: 逐帧相加或交叉注意力融合）
    h = f(text_embed, speech_embed)   # 逐位置融合而非拼接
     ↑ 用于语音直接「调制」文本表征，如 SALMONN 的 window-level 双编码融合
```

### 5.2 对比

| 维度 | Prefix | Interleaved | Fusion |
| --- | --- | --- | --- |
| 实现难度 | 低（拼 embedding 序列） | 中（需构造交错数据） | 高（改 LLM 内部结构） |
| 与 LLM 兼容性 | 完全兼容 | 完全兼容 | 需改造 attention |
| 适用场景 | 单轮音频 QA / ASR | 多轮语音对话 / 语音生成 | 需要细粒度声学调制 |
| 代表 | Qwen-Audio、MiniCPM-o | SpeechGPT、Moshi | 部分 speech-text 预训练模型 |

工程上 **Prefix 是绝对主流**：对 LLM 零侵入，把语音 embedding 当作「外语 token」直接 prepend，LLM 的 attention 自然学会对齐。

## 6. 模态对齐训练策略

### 6.1 Freeze LLM vs 联合训练

| 策略 | 训练模块 | 数据需求 | 风险 |
| --- | --- | --- | --- |
| 全冻结，只训 Connector | Connector（~20M） | 数百小时对齐数据即可 | 对齐上限低，语音理解浅 |
| 冻结 Encoder，LLM LoRA | Connector + LoRA | 数千小时指令数据 | 主流，平衡 |
| 全量联合训练 | Encoder + Connector + LLM | 10 万小时级 | 灾难性遗忘、训练不稳、成本高 |

**典型三阶段**（承接第 1 篇）：

1. **Stage 1 对齐**：冻结 LLM + Encoder，只训 Connector，用 ASR 数据把语音 embedding 拉进 LLM 语义空间。
2. **Stage 2 指令微调**：解冻 LLM（LoRA / 部分层），多任务指令训练。
3. **Stage 3（可选）Encoder 继续 Pre-train**：Qwen2-Audio 证明 encoder 也在海量多任务数据上继续预训练能显著提升（尤其非语音事件）。

### 6.2 为什么 Stage 1 冻结 LLM 有效

冻结 LLM 时，Connector 的梯度完全由 LLM 对文本 token 的损失回传，等价于求解：

$$\min_{\phi} \ \mathbb{E}_{(s, y)} \big[ -\log P_{\theta_{\text{frozen}}}(y \mid f_{\phi}(s)) \big]$$

即**把语音 embedding 优化到冻结 LLM 的「流形」上**。这避免了早期大 lr 撼动 LLM 导致语言能力崩塌，是对齐阶段最稳的起点。LLaVA、Qwen-Audio、SALMONN 均验证了这一点。

### 6.3 灾难性遗忘防御

* 指令微调阶段**混入 20~30% 纯文本指令数据**（含通用对话、代码、数学）；
* LoRA / 部分层解冻优先于全量微调；
* 监控文本基准（MMLU / GSM8K 简版）作为「语言能力哨兵」指标。

## 7. PyTorch 实现：三种 Connector

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

# ---------- 1. LLaVA 式 Linear Connector ----------
class LinearConnector(nn.Module):
    def __init__(self, audio_dim=1280, llm_dim=4096, downsample=4):
        super().__init__()
        self.ds = downsample
        self.proj = nn.Sequential(
            nn.Linear(audio_dim * downsample, llm_dim),
            nn.GELU(),
            nn.Linear(llm_dim, llm_dim),
        )

    def forward(self, enc_out):
        # enc_out: [B, T, D_a]
        B, T, D = enc_out.shape
        T2 = T // self.ds * self.ds
        x = enc_out[:, :T2].reshape(B, -1, D * self.ds)  # [B, T/ds, D*ds]
        return self.proj(x)                               # [B, M, D_l]


# ---------- 2. Q-Former Connector ----------
class QFormerConnector(nn.Module):
    def __init__(self, audio_dim=1280, llm_dim=4096, n_queries=32, n_heads=8):
        super().__init__()
        self.queries = nn.Parameter(torch.randn(n_queries, audio_dim) * 0.02)
        self.cross_attn = nn.MultiheadAttention(audio_dim, n_heads, batch_first=True)
        self.norm = nn.LayerNorm(audio_dim)
        self.proj = nn.Linear(audio_dim, llm_dim)

    def forward(self, enc_out):
        # enc_out: [B, T, D_a] -> 定长 [B, n_queries, D_l]
        B = enc_out.size(0)
        q = self.queries.unsqueeze(0).expand(B, -1, -1)   # [B, N, D_a]
        fused, _ = self.cross_attn(q, enc_out, enc_out)   # 交叉注意力压缩
        return self.proj(self.norm(fused + q))            # 残差 + 投影


# ---------- 3. CTC 压缩 Connector ----------
class CTCCompressor(nn.Module):
    """encoder 侧带 CTC 头, 推理时仅保留非 blank 帧"""
    def __init__(self, audio_dim=1280, llm_dim=4096, vocab_size=5000):
        super().__init__()
        self.ctc_head = nn.Linear(audio_dim, vocab_size)
        self.proj = nn.Linear(audio_dim, llm_dim)
        self.blank_id = 0

    def forward(self, enc_out, ctc_train=False):
        logits = self.ctc_head(enc_out)                   # [B, T, V]
        if ctc_train:
            return F.log_softmax(logits, dim=-1)          # 训练: 返回 CTC log-probs
        # 推理: 剔除 blank 帧(先做相邻去重)
        pred = logits.argmax(-1)                          # [B, T]
        keep = pred != self.blank_id
        keep[:, 1:] = keep[:, 1:] & (pred[:, 1:] != pred[:, :-1])  # 去连续重复
        outs, masks = [], []
        for b in range(enc_out.size(0)):
            outs.append(self.proj(enc_out[b][keep[b]]))
            masks.append(int(keep[b].sum()))
        max_len = max(masks)
        batch = torch.stack([
            F.pad(o, (0, 0, 0, max_len - o.size(0))) for o in outs
        ])
        return batch, torch.tensor(masks)                 # [B, M, D_l], 有效长度


# ---------- 使用示例 ----------
if __name__ == "__main__":
    enc = torch.randn(2, 500, 1280)   # 2 条 10s 音频 @ 50Hz encoder 输出
    print(LinearConnector()(enc).shape)    # [2, 125, 4096]  (4x 下采样)
    print(QFormerConnector()(enc).shape)   # [2, 32, 4096]   (定长压缩)
    comp, lens = CTCCompressor()(enc)
    print(comp.shape, lens)                 # [2, <=M, 4096], 内容驱动变长
```

## 8. 总结与最佳实践

* **Encoder 选型口诀**：内容任务 Whisper、副语言任务加 BEATs/CLAP 双流（SALMONN）、生成任务 HuBERT 语义单元 + codec 声学单元。
* **Connector 选型**：默认 LLaVA 式 Linear（稳、简单、够用）；长音频/上下文吃紧用 Q-Former 定长压缩；ASR 强相关任务可加 CTC 压缩免费剔除静音。
* **token 率红线**：语音 token 率控制在 **5~15 token/s**，10 秒音频约 50~150 token，与文本同数量级；codec 级 600+/s 不能直接进 LLM。
* **对齐训练**：Stage1 冻结 LLM 只训 connector（把语音拉进 LLM 流形）-> Stage2 LoRA 指令微调 + 30% 纯文本防遗忘 -> Stage3 可选 encoder 继续预训练。
* **面试高频落点**：Q-Former 与 Linear 的取舍、CTC 压缩为什么丢副语言、10s 音频 token 数估算、为什么对齐阶段冻结 LLM。

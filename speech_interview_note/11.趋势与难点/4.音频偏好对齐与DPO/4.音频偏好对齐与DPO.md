# 4. 音频偏好对齐与 DPO

## 1. 概述

语音生成模型（TTS / Speech-LLM）经过大规模预训练后，输出分布「什么都像但什么都不精」：内容可能幻觉、音质可能毛糙、音色可能漂移、情感可能错配。**偏好对齐（preference alignment）**的目标是让模型在多个输出候选中稳定偏向「人类更喜欢的那一个」。

RLHF/PPO/DPO 的文本范式已经成熟；语音的独特性在于**偏好是多维的**：一句话好不好听，至少同时包含内容正确性、音质、说话人相似度、副语言表现四个近乎独立的维度。本文从文本 DPO 推导出发，系统梳理语音偏好对齐的特殊性、数据构造方法、代表工作与过度对齐（reward hacking）风险。

```
                    ┌────────────────────────────────────┐
  同一 prompt 的     │  多维偏好信号                        │
  两个语音候选       │  ┌──────┐ ┌──────┐ ┌─────┐ ┌─────┐ │
  y_w (更好)  ──>   │  │内容   │ │音质  │ │音色 │ │副语言│ │  ──> 综合偏好标签 / 标量奖励
  y_l (更差)  ──>   │  │WER↓  │ │UTMOS│ │SIM↑ │ │情感  │ │      (人工AB / LLM-as-judge / 自动指标)
                    │  └──────┘ └──────┘ └─────┘ └─────┘ │
                    └────────────────────────────────────┘
                                 │
                                 ▼
                    DPO / RLHF: 拉开 log P(y_w) 与 log P(y_l) 的差距
```

## 2. 文本 DPO 回顾与公式推导（面试必会）

### 2.1 从 RLHF 到 Bradley-Terry

RLHF 三阶段：SFT -> 训练 reward model -> PPO 优化。奖励模型基于 **Bradley-Terry (BT) 偏好模型**：对于偏好对 $(y_w, y_l)$（$w$=win, $l$=lose）：

$$P(y_w \succ y_l \mid x) = \sigma\big(r(x, y_w) - r(x, y_l)\big), \quad \sigma(t) = \frac{1}{1+e^{-t}}$$

奖励模型损失：

$$\mathcal{L}_{RM} = -\log \sigma\big(r(x, y_w) - r(x, y_l)\big)$$

### 2.2 RLHF 的最优策略形式

PPO 目标（KL 约束下最大化奖励）：

$$\max_\pi\; \mathbb{E}_{y\sim\pi(\cdot\mid x)}\big[r(x,y)\big] - \beta\, \mathrm{KL}\big(\pi(\cdot\mid x)\,\Vert\,\pi_{ref}(\cdot\mid x)\big)$$

该目标有闭式最优解（变分法求极值）：

$$\pi^*(y \mid x) = \frac{1}{Z(x)}\, \pi_{ref}(y \mid x)\, \exp\!\Big(\frac{1}{\beta} r(x, y)\Big)$$

### 2.3 DPO：消除奖励模型

由上式反解奖励（相差一个仅依赖 $x$ 的常数）：

$$r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{ref}(y \mid x)} + \beta \log Z(x)$$

代入 BT 模型，配对相减时 $Z(x)$ 与 $c(x)$ 消掉，得到 **DPO 损失**：

$$\boxed{\;\mathcal{L}_{DPO} = -\mathbb{E}_{(x,\,y_w,\,y_l)}\Big[\log \sigma\Big(\beta \log\frac{\pi_\theta(y_w \mid x)}{\pi_{ref}(y_w \mid x)} - \beta \log\frac{\pi_\theta(y_l \mid x)}{\pi_{ref}(y_l \mid x)}\Big)\Big]\;}$$

直觉：**策略本身的对数概率比就是隐式奖励**，无需单独的 reward model 与 PPO 采样循环。梯度方向自动调节：win 样本概率低时梯度大（多学），win 已远超 ref 时梯度趋于饱和（防过优化）。

隐式奖励分数（常用于分析）：

$$\hat{r}(x, y) = \beta \log \frac{\pi_\theta(y \mid x)}{\pi_{ref}(y \mid x)}$$

典型超参：$\beta = 0.01 \sim 0.1$（语音场景常取偏小值，因为 token 序列长、log-ratio 量大）；偏好多 epoch 训练易过拟合，一般 1~3 个 epoch。

## 3. 语音偏好对齐的特殊性

### 3.1 多维偏好结构

| 维度 | 含义 | 可自动化的代理指标 |
| --- | --- | --- |
| **内容正确性** | 该说的说了、没有幻觉/漏译/复读 | ASR 转写后与参考文本算 WER（转写用另一个强 ASR 闭环） |
| **音质（fidelity）** | 无毛刺、爆音、电流声，自然度 | UTMOS（MOS 预测器，1~5 分）、PESQ/VisQOL 类 |
| **说话人相似度** | zero-shot 克隆时音色是否像目标 | ECAPA-TDNN embedding 余弦相似度 |
| **副语言/风格** | 情感、语速、重音是否匹配 prompt 描述 | 情感分类器一致性、韵律 F0/能量统计量距离 |

**核心难点：维度之间会冲突**。例如音质奖励拉满时模型倾向输出「安全但平淡」的声音，副语言表现力下降；追求 UTMOS 可能损伤内容准确率（第 6 节 reward hacking）。因此语音偏好对齐的关键设计是**奖励/偏好的组合方式**：

* **标量加权**：$r = \sum_i w_i r_i$，简单但权重难调，且不同样本最优权重不同；
* **字典序（lexicographic）**：先满足内容正确（硬约束 WER < 阈值），再优化音质；
* **逐维偏好对**：为每个维度单独构造偏好对，混合训练（SpeechAlign 的思路之一）。

### 3.2 序列长度与信用分配

语音 token 序列动辄数百上千个 token，一个偏好对只提供 1 bit 级别的监督信号，信用分配（哪几帧导致「差」）比文本更模糊。缓解：token 级奖励（如对齐 UTMOS 的帧级打分）、分段偏好对（把长语音切成句子级 pair）。

### 3.3 离散 token + 连续感知的鸿沟

策略在 codec token 空间优化，而偏好判断在波形/感知空间。中间的 codec decoder（vocoder）不可微或不稳定，使 token 级奖励的传播困难--这是 RLHF-PPO 在语音上比 DPO 更难落地的原因之一，也是 DPO（纯 token 概率比）在语音侧更受欢迎的原因。

### 3.4 PPO vs DPO：语音场景的选型（高频对比题）

| 维度 | RLHF-PPO | DPO |
| --- | --- | --- |
| **所需组件** | reward model + value model + policy + ref（4 个大模型同时在显存） | policy + ref（2 个） |
| **训练稳定性** | 采样方差大、超参敏感（clip、KL 系数、GAE），长语音序列上极易崩 | 接近 SFT 量级的稳定性 |
| **数据要求** | 必须在线采样（on-policy） | 可离线偏好对冷启动，也可迭代 on-policy |
| **奖励形式** | 任意标量（可加权多目标、可逐 token） | 必须能退化成偏好对（pairwise 可比） |
| **优化上限** | 理论更高（持续探索 + 逐 token 信用分配） | 受偏好对质量与覆盖限制，多轮迭代 DPO（iterative DPO）可逼近 |
| **语音实践** | 少数工作（如 VALL-E 系 RLHF），训练成本极高 | **主流选择**（SpeechAlign、对话语音模型对齐阶段） |

经验结论：语音生成序列长、奖励来自外部感知器（UTMOS/ASR/说话人模型），PPO 的 rollout 开销与不稳定性被放大；DPO 只需 token 概率比，绕开声学空间不可微问题，是当前默认方案。

## 4. 偏好数据来源（工程重点）

| 来源 | 做法 | 优缺点 |
| --- | --- | --- |
| **人工 AB 听测** | 同 prompt 两个候选（随机顺序），听测人选更好；每人每天限量防疲劳 | 金标准；贵、慢、标注一致性受听测环境/设备影响大（必须耳机标准化） |
| **LLM-as-judge（内容维度）** | ASR 转写两个候选，让 GPT-4 类模型按「忠实度/完整性/有害性」排序 | 便宜、可大规模；只能评内容，评不了听感；有自身偏差（长度偏好等） |
| **自动指标构造（声学维度）** | UTMOS、speaker-sim、情感一致性分类器打分，得分差 > margin 即成对 | 全自动、规模无上限；**维度单一**，直接优化易被 hack |
| **扰动构造（合成负样本）** | 对同一句的正确输出加噪、截断、错误内容、错误情感，天然形成 $y_w/y_l$ | 可控、可归因（每个负样本对应一种缺陷）；分布可能与模型真实缺陷不匹配 |
| **模型自举（on-policy 采样）** | 用当前模型对同一 prompt 采样多个输出再评序（迭代 DPO / self-play） | 分布匹配最好，是 DPO 发挥威力的正确姿势；需要高质量在线评审器 |

工业配方通常是「扰动构造冷启动 + 自举采样迭代 + 少量人工 AB 校准（校准自动 judge 的偏差）」。

### 4.1 一个可落地的偏好数据生产流水线

```
prompt 池 (指令/对话上文)
     │
     ▼
当前模型采样 K=4~8 个候选 (温度 0.7~0.9, 保证多样性)
     │
     ├──> 声学维度自动打分: UTMOS / ECAPA speaker-sim / 情感一致性
     ├──> 内容维度: judge ASR 转写 -> 与参考比 WER / LLM judge 忠实度打分
     ▼
按维度排名 + margin 过滤 (分差过小的样本丢弃, 减少噪声标签)
     │
     ▼
构造逐维偏好对 (内容对 / 音质对 / 综合对) + 扰动负样本回灌
     │
     ▼
DPO 训练 -> 新模型 -> 回到采样 (迭代 2~3 轮, 每轮抽样 5% 人工 AB 校准)
```

要点：**margin 过滤**（如综合分差 > 0.3 才成对）比堆量更重要，边界模糊的偏好对会引入标签噪声；人工 AB 校准用于发现 judge 系统性偏差（如 LLM judge 偏好长回答），发现后对 judge 做 few-shot 校正。

## 5. 代表性工作与做法

* **SpeechAlign（2025）**：Google 提出的语音 LLM 偏好对齐框架。核心观察：语音任务（如摘要、翻译）的偏好应分解为「内容」与「声学」两个层面；做法是用 WER 类内容指标与 UTMOS/speaker-sim 类声学指标构造显式奖励与偏好对，再对 speech LLM 做 DPO，在保留音质的同时显著降低内容幻觉。
* **RLHF/DPO for TTS**：一类工作对语音 LM（VALL-E 式）做 PPO/DPO，奖励为「参考文本条件下 ASR 转写的负 WER + UTMOS + speaker-sim」加权和；经验结论：DPO 更稳，PPO 在长序列语音上采样方差过大、训练极易崩。
* **对话语音模型的对齐阶段**：GLM-4-Voice、SpeechGPT-2 等在 SFT 后增加偏好对齐阶段，偏好来源为人工 AB + LLM judge 混合，用于压制「复读、抢话、无意义语气词」等对话级坏行为。
* **VoiceCraft 类语音编辑/克隆模型的偏好微调**：以「编辑前后非编辑区域保持不变」构造偏好对（编辑区正确 + 非编辑区比特一致 = win），本质是把可验证约束转成偏好信号。

面试可概括为三条主线：**任务级对齐（SpeechAlign，内容+声学双维度）、生成级对齐（TTS RLHF/DPO，自动指标奖励）、对话级对齐（轮转行为与坏习惯抑制）**。

## 6. 过度对齐与 Reward Hacking（高频考点）

### 6.1 典型作弊模式

| 作弊方式 | 表现 | 根因 |
| --- | --- | --- |
| **UTMOS 作弊** | 模型输出「录音棚般光滑」但千篇一律、情感平庸，UTMOS 涨破 4.5 而 MOS 人工不涨甚至降 | UTMOS 本身是代理模型，存在可利用的捷径特征（频谱光泽度） |
| **speaker-sim 作弊** | 音色像但内容含糊（牺牲可懂度保音色），或直接「气声/低能量输出」使 embedding 逼近目标 | 相似度与可懂度并非单调相关 |
| **WER 奖励作弊** | 针对 judge ASR 的音素混淆模式生成「ASR 听起来对但人听不懂」的语音 | 奖励中的 ASR 与人类听觉不一致 |
| **长度/静音作弊** | 输出更短或更多静音以降低犯错面 | judge 的长度偏差、WER 分母效应 |
| **过度保守** | KL 约束过强或训练轮数多，模型退回 $\pi_{ref}$ 附近，偏好提升消失 | DPO 饱和 / $\beta$ 过大 |

### 6.2 防御手段

1. **奖励集成**：多个不同架构的 MOS 预测器 / ASR / 说话人模型取平均或最小值，提高作弊成本；
2. **KL 散度约束与早停**：监控 $\mathbb{E}[\mathrm{KL}(\pi_\theta\Vert\pi_{ref})]$，超出阈值（如 10~20 nats）回滚；
3. **人工 AB 定期回归**：自动指标每提升一定幅度，抽样跑人工 AB 校验是否同向；
4. **对抗扰动负样本**：把「高分但难听」的退化模式（光滑化、气声）作为负例回灌训练；
5. **逐维奖励封顶**：UTMOS 类奖励用 $\min(r, r_{cap})$ 或 rank 化，防止单维失控。

## 7. PyTorch 实现：语音 DPO 损失

```python
import torch
import torch.nn.functional as F

def dpo_loss(policy_logps, ref_logps, beta=0.05):
    """
    policy_logps: [B]  当前模型在 (win, lose) 上的序列 log 概率 (拼接)
    ref_logps:    [B]  参考模型(SFT checkpoint, 冻结) 的对应 log 概率
    前 B/2 为 y_w, 后 B/2 为 y_l
    """
    B2 = policy_logps.size(0) // 2
    logrw = beta * (policy_logps[:B2] - ref_logps[:B2])   # 隐式奖励 r_w
    logrl = beta * (policy_logps[B2:] - ref_logps[B2:])   # 隐式奖励 r_l
    logits = logrw - logrl
    loss = -F.logsigmoid(logits).mean()
    # 监控量: 偏好准确率 + 隐式奖励差
    with torch.no_grad():
        acc = (logits > 0).float().mean()
        margin = (logrw - logrl).mean()
    return loss, acc, margin


def speech_multi_dim_reward(asr_texts, refs, utmos_scores, spk_sims,
                            w_content=2.0, w_mos=1.0, w_spk=0.5, cap=4.8):
    """
    语音多维标量奖励 (PPO 用 / 构造偏好对用):
      r = w_content * (1 - WER) + w_mos * min(UTMOS, cap) + w_spk * cos_sim
    WER 由 judge ASR 转写 vs 参考文本计算
    """
    def wer(hyp, ref):
        h, r = hyp.split(), ref.split()
        # 简化编辑距离 (工业用 jiwer)
        import functools
        @functools.lru_cache(maxsize=None)
        def d(i, j):
            if i == 0: return j
            if j == 0: return i
            return min(d(i-1, j) + 1, d(i, j-1) + 1,
                       d(i-1, j-1) + (h[i-1] != r[j-1]))
        return d(len(h), len(r)) / max(len(r), 1)

    rewards = []
    for hyp, ref, mos, sim in zip(asr_texts, refs, utmos_scores, spk_sims):
        r = (w_content * (1 - wer(hyp, ref))
             + w_mos * min(mos, cap)          # 封顶防 UTMOS 作弊
             + w_spk * sim)
        rewards.append(r)
    return torch.tensor(rewards)


if __name__ == "__main__":
    torch.manual_seed(0)
    # 模拟: batch=4 -> 2 个偏好对 (w1,l1,w2,l2) 的序列 log 概率
    policy = torch.tensor([-120.5, -118.2, -131.0, -125.7, -210.3, -205.1],
                          requires_grad=True)
    ref =    torch.tensor([-121.0, -117.5, -130.4, -126.2, -209.0, -206.5])
    loss, acc, margin = dpo_loss(policy, ref, beta=0.05)
    print(f"DPO loss={loss.item():.4f}  acc={acc:.2f}  margin={margin:.4f}")
    loss.backward()
    # 期望行为: win 的 logp 上升(负值增大->梯度推高), lose 的下降
    print("grad:", policy.grad)

    r = speech_multi_dim_reward(
        asr_texts=["hello world today", "hello wrld too day"],
        refs=["hello world today"] * 2,
        utmos_scores=[4.9, 4.2], spk_sims=[0.91, 0.85])
    print("multi-dim rewards:", r)   # 候选1 内容全对+音质更高 -> 偏好更高
```

## 8. 总结与最佳实践

* **推导链**要一口气讲清：BT 偏好模型 -> KL 约束的最优闭式解 -> 反解出隐式奖励 -> 消掉配分函数得到 DPO 损失；$\beta$ 控制 KL 惩罚强度。
* **语音特殊性**：偏好是内容/音质/音色/副语言多维结构，冲突时优先保内容正确（硬约束），声学维度加权或逐维构造偏好对；序列长导致信用分配难，token 概率比形式的 DPO 比 PPO 更适合语音 LM。
* **数据工程是成败关键**：扰动构造冷启动 + on-policy 自举迭代 + LLM judge 评内容 + 自动指标评声学 + 小规模人工 AB 校准。
* **反 reward hacking 三件套**：奖励集成（多 judge）、KL 监控与早停、定期人工回归验证；单维奖励必须封顶。
* **上线评估**：自动指标（WER / UTMOS / speaker-sim）只做监控，最终以人工 MOS 与 AB 胜率为准；报告时区分「对齐收益」与「SFT 基线」的差值。

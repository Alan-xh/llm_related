# 2. 原生 Speech-to-Speech 端到端架构

## 1. 概述

传统语音对话系统是**级联式（Cascaded）**的：`ASR -> LLM -> TTS`。级联系统模块解耦、可独立迭代，但存在天然缺陷。「原生（native）Speech-to-Speech」指用一个统一模型直接从语音输入生成语音输出，中间不经过（或不显式经过）文本。

### 1.1 为什么绕过文本

文本是语言的**有损压缩**：语音 $\to$ 文本这一步丢掉了大量信息，而这些信息恰恰是「像人一样对话」所必需的：

* **副语言信息丢失**：音色、语调、重音、犹豫（"嗯……"）、笑声、叹息、情绪、环境声，在转写时几乎全部被抹掉，TTS 侧只能靠人工标注或猜测补回。
* **无法完成的任务**：耳语转换（whispered speech）、口音模仿、情感保留转录、笑声/哭声的恰当回应、说话人身份保持（zero-shot voice cloning 的极致形态），这些任务的「输入信息本身就不在文本里」。
* **延迟叠加**：级联三段各自有排队、边界等待（ASR 等端点、LLM 等首 token、TTS 等首音频包），端到端延迟通常 1~3 秒；原生 S2S 理论上可压到 200~500ms。
* **错误传播**：ASR 的错（同音字、专名）会硬性限制整个对话的上限，且 LLM 无法回看原始声学证据纠错。

### 1.2 代价（面试要能辩证回答）

* 失去文本这个**强先验与可解释中间层**：LLM 在文本上积累的海量世界知识难以直接迁移；
* 语音 token 序列长（75Hz×8 层），训练开销大；
* 评估困难：没有中间文本，内容正确性只能靠再跑一遍 ASR 闭环评估；
* 易出现**非语言噪声输出**（无意义语气词、幻觉音效）。

## 2. 三大技术路线总览

```
路线 A: 直接语音到语音 (Direct S2S)
  用户语音 tokens ──> [ 单一 Transformer (语音进 / 语音出) ] ──> 模型语音 tokens ──> vocoder/codec 解码
  代表: GPT-4o (realtime), Moshi, 自然对话式模型

路线 B: 双塔对话模型 (Dual-Encoder / 分离对话状态)
  用户流 ──> [ Inst 流 (只听) ] ─┐
                                 ├──> 时间对齐并行生成 ──> 模型流 [ Out 流 (听说) ]
  代表: Moshi 双流结构 (Mimi + 双 Transformer)

路线 C: 语音 token 中间表示 (Speech Token 作为 LLM 词表扩展)
  语音 tokens ⇄ 文本 tokens 统一进 LLM, 文本作为(显式或隐式)中枢
  代表: Audio PaLM, Spirit-LM, SpeechGPT (RTT), SpeechMLM
```

| 维度 | A: 直接 S2S | B: 双塔/双流 | C: 语音 token + 文本中枢 |
| --- | --- | --- | --- |
| **中间表示** | 无（纯语音 token） | 无，但听/说两流分离 | 文本（显式或交替出现） |
| **副语言保留** | 最好 | 最好 | 较好（取决于文本是否出现） |
| **LLM 知识复用** | 最难（需从文本 LLM 初始化+大规模对齐） | 难 | **最容易**（继承文本 LLM 能力） |
| **可控性/可审查** | 差（无中间文本可干预） | 差 | 好（可对文本段做护栏） |
| **延迟** | 最低 | 最低（支持全双工） | 中（视文本是否串行生成） |
| **代表** | GPT-4o 类、Moshi(亦属B) | Moshi | Audio PaLM、Spirit-LM、SpeechGPT |

## 3. 路线 A：直接语音到语音（GPT-4o 类、Moshi）

### 3.1 基本形态

一个自回归 Transformer，词表 = codec 码本（+ 少量控制 token）。输入历史对话的语音 token，输出模型侧语音 token，经 codec decoder（vocoder）还原波形：

$$P(s_{t} \mid s_{<t},\, u_{1:T_{in}})$$

其中 $u$ 为用户语音 token，$s$ 为模型语音 token。关键工程问题：

* **帧率与多码本并行生成**：GPT-4o 类系统普遍使用低帧率 codec，且每步**并行预测一帧内多个 codebook 层**（delay pattern 的变体：把 $N_q$ 层 token 在时间轴上错开或分组并行生成），使每自回归步对应 60~80ms 音频。
* **交错生成（interleaved generation）**：模型生成语音 token 的同时可插入特殊 token 触发动作（工具调用、静音、喘息等）。

### 3.2 Moshi：双流时间对齐（路线 A 与 B 的结合）

Moshi 的核心创新是 **全双工的时间对齐双流**。Mimi codec 以 12.5Hz 帧率把双方语音编码，模型维护两条并行序列：

```
时间轴 (12.5 Hz, 每步 80ms):   t=1     t=2     t=3     t=4   ...
用户侧 Inst 流 (只有 audio):    u1      u2      u3      u4
模型侧 Out 流 (audio+text):    [s1,x1] [s2,x2] [s3,x3] [s4,x4]
                               ▲ 并行时间对齐: 每个时间步同时消化用户帧并产出模型帧
```

* **Inst 流（Inference stream）**：编码用户音频（含其 codec 的语义层），只进不出，相当于「耳朵」。
* **Out 流**：模型自身的语音 token + 并行文本 token（Moshi 同时生成文本作为「内心独白」，提升内容连贯与可监控性）。
* 由于两条流在**每个时间步都成对出现**，模型可以学到「对方还在说→我保持静音」「对方停顿→我此刻接话」的时序行为，这就是全双工与可打断能力的来源（详见第 3 篇）。

训练数据构造：将单说话人语料用 TTS 合成成对话、或取真实双人对话，把两条流按时间戳切齐，做**并行 next-token prediction**。

## 4. 路线 C：语音 token 作为中间表示

### 4.1 Audio PaLM：词表级统一

Audio PaLM 把 PaLM 的文本词表与音频 codec token 词表**拼接成一个统一词表**，输入输出可以是文本与音频 token 的任意混合。特点：

* 继承文本 LLM 全部能力（初始化自 PaLM），语音能力靠继续训练获得；
* 支持语音到语音、语音到文本、文本到语音的**任意方向迁移**；
* 由于文本 LLM 的先验仍在，语义幻觉显著低于从零训练的纯语音模型。

### 4.2 Spirit-LM：交错式模态融合

Spirit-LM（Meta）用「**文本-语音交错序列**」训练：把平行语料组织成

```
<sst> 声音token <ttt> 文本token <sst> 声音token <ttt> 文本token ...
```

文本与语音 token 在同一序列里逐词交错，使模型在表示空间中把「同一个词的两种形态」绑定起来，获得跨模态的语义自由迁移（两种变体：phonetic 单元与 semantic 单元）。这是「modality interleaving」训练范式的代表。

### 4.3 SpeechGPT 与 RTT 交替生成

SpeechGPT 提出以 **RTT（Recursive Text Transduction）**为中枢的三段式：语音输入 token 化后，模型按「文本响应 -> 语音响应」的顺序生成，即：

$$\text{speech}_{in} \to \text{text}_{in?} \to \text{text}_{out} \to \text{speech}_{out}$$

文本链条作为「思考链」存在，兼顾语义质量与语音表现力。缺点：文本段串行生成会**额外增加一段 LLM 长度的时间延迟**。

### 4.4 SpeechMLM：掩码式统一建模

SpeechMLM（微软）用统一的 Masked Language Modeling 目标同时覆盖语音与文本 token：把语音 token 与文本 token 放进同一个「Mixture-in-Mixture（MIL）」序列，随机 mask 后预测。相比纯自回归，MLM 目标在语音-文本互转（如语音翻译、语音理解）上迁移更平滑，但生成需迭代解码，不适合实时流式。

### 4.5 最新演进：NTP（Next Text Prediction）范式

2025 年前后出现的 NTP 思路（如微软相关工作）：**模型输出语音 token 的同时并行生成「事后文本」**——文本不再是生成语音的前置条件，而是与语音对齐的副产品。这样既保住文本的可控性与评估手段，又不牺牲延迟，被视为「隐式文本中枢」的折中。

## 5. 核心难点：语际干扰与灾难性遗忘

### 5.1 问题定义

把预训练文本 LLM 扩展成语音模型时，语音 token 的分布与文本 token 差异巨大，直接混训会出现：

* **模态干扰（modality interference）**：语音段训练梯度「冲垮」文本能力，常见表现为文本基准（MMLU 等）下降 10 个点以上；
* **语际干扰（interlingual interference）**：语音 token 中声学信息（音色、噪声）与语义信息纠缠，模型学到的映射在「听懂」与「模仿声学」之间互相拉扯；语音内的多语种、方言、口音同样互相干扰；
* **灾难性遗忘（catastrophic forgetting）**：微调阶段的语音数据分布单一（如全是合成对话），文本 LLM 原有能力与安全对齐快速退化。

### 5.2 缓解方案（工业实践）

| 方案 | 做法 | 适用 |
| --- | --- | --- |
| **Modality Adapter / 延迟融合** | 冻结 LLM 主干，仅在输入输出端加 speech adapter（几层 Transformer/MLP），把 codec token 投影到文本空间（如 LLaMA-Omni、SLAM-Omni 思路） | 数据少、须保文本能力 |
| **LoRA / 部分层解冻** | 主干用 LoRA，仅解冻顶部若干层 | 中等规模微调 |
| **模态标记 + 分桶数据配比** | 用 `<speech>`/`<text>` 段标记切分序列，训练数据按文本:交错:纯语音 ≈ 4:3:3 之类的配比混合，持续「回灌」文本数据 | 全参训练必做 |
| **两阶段课程** | 先语音理解（ASR/S2TT 对齐语义），再语音生成（TTS 对齐声学），最后对话微调 | SpeechGPT/GLM-4-Voice 类 |
| **语义-声学解耦**（见第 6 节） | 让语义 token 走 LLM 主干、声学 token 走轻量 head | 降低纠缠 |

## 6. 语义 + 声学解耦方案

### 6.1 双 token 体系（AudioLM / VALL-E 范式）

```
语音 ──> [SSL 模型 HuBERT/w2v-BERT] ──> 语义 tokens (25~50Hz, 表达"说了什么")
     └─> [神经 codec EnCodec]       ──> 声学 tokens (75Hz×Nq, 表达"怎么说的")

LLM 建模:  P(semantic_t | semantic_<t)                 <- 语义 LM (自回归)
声学生成:  P(acoustic_t | semantic, acoustic_<t)        <- 声学 LM/解码 (粗->细两级)
```

* **语义 token**：SSL 离散单元，帧率低、信息密度高，决定内容；
* **声学 token**：RVQ 后层，决定音色、韵律、录音条件；
* 优点：LLM 只需建模低帧率语义流，训练效率高、语义幻觉低；缺点：两套 tokenizer 流水线长、声学 head 需单独训练，端到端优化被切断。

### 6.2 单 codec 内解耦（SpeechTokenizer / Mimi 范式）

用语义蒸馏把 SSL 信息压进 codec 第 1 层（见第 1 篇第 5 节），实现「一套 token、前层语义后层声学」。LLM 对不同层施加不同 attention 权重或用两个 head 分别预测，兼顾简洁与解耦。这是 2024 年后的主流选择。

### 6.3 解耦的评估

* 语义侧：token 的 ABX（音素可区分性）、word-level MI、下游 ASR WER；
* 声学侧：重建的 UTMOS、speaker similarity（ECAPA 余弦）、说话人分类线性探针（probe）；
* 解耦程度：用第 1 层 token 训练说话人分类器，accuracy 越低说明「语义层不漏音色」越好。

## 7. 原生 S2S 的评估体系

没有中间文本意味着传统 BLEU/WER 类指标不能直接套用，工业界普遍采用「**事后转写闭环 + 声学代理指标 + 行为级评测**」三层：

| 层次 | 指标 | 做法 |
| --- | --- | --- |
| **内容正确性** | 转写 WER / 忠实度（摘要、翻译任务的 BLEU/COMET） | 用强 ASR 把模型语音输出转写回文本再评分（注意 ASR 自身错误会低估模型） |
| **声学质量** | UTMOS / speaker-sim / 情感一致性分类准确率 | 代理模型自动打分，大规模回归监控 |
| **对话行为** | 轮转 F1、打断/让话正确率、backchannel 频次、响应延迟分布 | 双流对话评测集 + 人工 AB（详见第 3 篇第 7 节） |
| **幻觉/坏行为** | 复读率、非语言噪声输出率、静音失控率 | 转写文本规则匹配 + 人工抽检 |

注意：转写闭环存在**系统性盲区**--副语言维度（语气是否得体、笑声是否自然）转写完全丢失，只能依赖人工 AB 与 MOS，因此 S2S 评估成本显著高于级联系统，这也是落地的主要工程负担之一。

## 8. PyTorch 示例：多码本并行生成的 S2S 头

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class MultiCodebookParallelHead(nn.Module):
    """
    原生 S2S 模型的输出头: 一步同时预测一帧的 N_q 个 codebook token。
    相比把 8 层 token 展平成 8 步串行生成, 序列长度缩短 N_q 倍,
    每步对应 1/f 秒音频 (f=12.5Hz 时每步 80ms)。
    """
    def __init__(self, d_model=1024, n_q=8, codebook_size=2048, depthwise_len=0):
        super().__init__()
        self.n_q = n_q
        # 每层 codebook 独立 head + 层间信息注入(后层依赖前层预测结果可进一步做,
        # 此处用共享 trunk + 独立 linear 的简化并行版)
        self.heads = nn.ModuleList([
            nn.Sequential(nn.Linear(d_model, d_model), nn.GELU(),
                          nn.Linear(d_model, codebook_size))
            for _ in range(n_q)
        ])

    def forward(self, h):
        # h: [B, T, d_model] 主干最后一层隐状态, T 为帧数(12.5Hz)
        logits = torch.stack([head(h) for head in self.heads], dim=2)
        # -> [B, T, n_q, codebook_size]
        return logits


class SimpleS2S(nn.Module):
    """最小化原生 S2S 骨架: 文本LLM初始化 + 语音token扩展词表"""
    def __init__(self, text_vocab=32000, codebook_size=2048, d_model=1024,
                 n_layer=12, n_head=16, n_q=8):
        super().__init__()
        self.audio_embed = nn.Embedding(codebook_size, d_model)
        self.text_embed = nn.Embedding(text_vocab, d_model)
        layer = nn.TransformerEncoderLayer(
            d_model, n_head, dim_feedforward=4 * d_model,
            batch_first=True, norm_first=True)
        self.trunk = nn.TransformerEncoder(layer, n_layer)
        self.head = MultiCodebookParallelHead(d_model, n_q, codebook_size)

    def forward(self, text_ids, audio_ids):
        """
        text_ids:  [B, L_text]   指令/文本 token (可为空)
        audio_ids: [B, T, n_q]   用户语音 token (含历史模型语音)
        """
        x = torch.cat([self.text_embed(text_ids),
                       self.audio_embed(audio_ids).sum(dim=2)], dim=1)
        h = self.trunk(x)
        h_speech = h[:, text_ids.size(1):]          # 只在语音位置出声学 logits
        return self.head(h_speech)                   # [B, T, n_q, K]


if __name__ == "__main__":
    model = SimpleS2S()
    text_ids = torch.randint(0, 32000, (2, 16))
    audio_ids = torch.randint(0, 2048, (2, 100, 8))   # 100 帧 @12.5Hz = 8s
    logits = model(text_ids, audio_ids)
    print("输出 logits:", logits.shape)                # [2, 100, 8, 2048]
    # 每步生成 80ms 音频 x 8 层 token; 展平串行则需 800 步 -> 序列长度降 8 倍
```

## 9. 总结与最佳实践

* **动机与代价要成对回答**：绕过文本获得副语言信息、低延迟与端到端纠错，但牺牲文本先验、可控性与评估便利。工业落地普遍选择折中（并行文本/RTT/NTP），纯 S2S 多用于研究或实时对话场景。
* **三路线选型**：要最大限度复用开源文本 LLM 与可审查性 → 路线 C（Audio PaLM / Spirit-LM）；要全双工实时对话 → 路线 A+B（GPT-4o 类、Moshi 双流）。
* **训练配方**：冻结+adapter 起步，全参训练必须混入大比例文本与交错数据防灾难性遗忘；语义-声学解耦（双 token 或单 codec 语义蒸馏）是稳定内容质量的关键。
* **生成效率**：多码本并行 head（一步出整帧）+ 低帧率 codec（12.5Hz）是当前实时 S2S 的标准组合。
* **评估闭环**：语音回答跑 ASR 再评内容指标 + UTMOS/说话人相似度评声学，形成双轨评估。

# 2. VAD 语音活动检测

## 1. 概述

**VAD（Voice Activity Detection，语音活动检测）** 的任务是对每一帧音频判断「是语音（speech）还是非语音（noise/silence/music）」。它是语音交互系统的第一道闸门：

* **流式 ASR**：用 VAD 切分语音段（utterance segmentation）、检测句尾 endpoint、过滤静音防止幻觉；
* **打断检测（Barge-in）**：全双工对话中检测用户何时开始说话，立即停止 TTS 播放；
* **省电与省带宽**：端侧设备（TWS 耳机、智能音箱）只有 VAD 触发后才唤醒大模型/上传音频；
* **音频打标与质检**：通话录音中统计说话时长、检测静音段。

VAD 的核心权衡是 **recall（不漏检语音）vs precision / false alarm（不误触发）** 与 **计算开销（端侧要求 < 1ms/帧，CPU 占用极低）**。

---

## 2. 传统方法：能量 / 过零率 / GMM

### 2.1 基于能量与过零率的判决

最古典的 VAD 假设「语音比噪声能量高」：

* **短时能量（Short-Time Energy）**：第 $n$ 帧能量 $E(n) = \sum_{m=0}^{L-1} x_n^2(m)$，浊音（voiced）段能量显著高于静音；
* **过零率（Zero-Crossing Rate, ZCR）**：$ZCR(n) = \frac{1}{2L}\sum_{m=1}^{L} |\text{sgn}(x_n(m)) - \text{sgn}(x_n(m-1))|$，清音（unvoiced，如 /s/、/f/）能量低但 ZCR 高，与能量互补；
* **判决**：能量阈值通常取「前若干帧（假设为噪声）噪声能量的均值 + $k\sigma$」，或对能量分布做双峰（bimodal）假设取谷底。

```python
# 能量 VAD 极简实现
import numpy as np

def energy_vad(pcm: np.ndarray, sr=16000, frame_ms=30,
               noise_frames=5, k=3.0):
    frame_len = int(sr * frame_ms / 1000)          # 480 samples
    frames = pcm[:len(pcm)//frame_len*frame_len].reshape(-1, frame_len)
    energy = 10 * np.log10((frames**2).mean(axis=1) + 1e-10)  # dB
    noise_thr = energy[:noise_frames].mean() + k * energy[:noise_frames].std()
    return energy > noise_thr                       # 帧级 bool
```

**缺陷**：低信噪比（SNR < 5dB）下能量分布与噪声重叠严重；无法区分语音与音乐/键盘声等非语音稳态源。

### 2.2 GMM-based VAD（统计模型方法）

对「噪声帧」和「语音帧」分别训练两个 GMM（特征常取对数 Mel 能量 / MFCC 的差分），用似然比判决：

$$\Lambda(x) = \frac{p(x \mid \text{speech})}{p(x \mid \text{noise})} \gtrless \theta$$

其中 $p(x \mid c) = \sum_{k=1}^{K} w_k \mathcal{N}(x; \mu_k, \Sigma_k)$。工程上还引入 **NISPE (noise update)**：在线更新噪声 GMM 参数以跟踪非平稳噪声。GMM VAD 在 2G/3G 时代的通话系统（如 3GPP EVRC、AMR 的 VAD option）中被广泛标准化。

## 3. 神经网络 VAD：WebRTC 与 Silero

### 3.1 WebRTC VAD（GMM 实现）

WebRTC VAD（`webrtcvad` Python 包）是 Google 开源的**轻量 GMM VAD**，至今仍是很多实时系统的默认选择：

* **特征**：80~log 频带的子带能量（filterbank 的频带级聚合，类似 PLP 前端）；
* **模型**：每帧对每个子带做 GMM 似然比判决（语音/噪声两套高斯），代码为高度优化的 C；
* **帧长限制**：仅支持 10/20/30ms 帧，采样率 8/16/32/48kHz；
* ** aggressiveness 参数**：0（最宽松，FA 高漏检低）~ 3（最激进，漏检高）。

```python
# pip install webrtcvad
import webrtcvad, collections

vad = webrtcvad.Vad(2)                     # aggressiveness: 0~3
FRAME = 480                                 # 30ms @ 16kHz
is_speech = vad.is_speech(frame_bytes, 16000)
```

**缺点**：对非语音稳态音（音乐、空调、键盘）误报偏高；噪声鲁棒性一般；不可再训练（模型硬编码在 C 里）。

### 3.2 Silero VAD（神经网络实现）

**Silero VAD** 是目前开源社区事实上的标准神经网络 VAD（v4/v5）：

* **架构**：极小的全卷积/DNN 前馈网络（约 1~2M 参数，`silero-vad` v5 的 jit 模型仅 ~2MB），输入为原始 PCM 的 log-mel 特征，输出帧级 speech probability；v5 支持可变 chunk（256/512/1024 samples @16kHz），无需逐 30ms 调用；
* **优势**：
  1. 准确率显著优于 WebRTC（尤其音乐/噪声场景，AUC 提升 10+ 点）；
  2. CPU 极快（RTF < 0.001，单核每秒可处理数千帧）；
  3. 多平台：ONNX/jit 导出，可跑 CPU、移动端、浏览器（onnxruntime-web）；
  4. 提供 CTC-style 帧率（每 32ms 一输出）与时间戳。

| 维度 | WebRTC VAD | Silero VAD |
| --- | --- | --- |
| **模型类型** | 子带 GMM（手工特征） | 小型 DNN（学习特征） |
| **参数量** | < 0.1M（硬编码） | ~1.7M（~2MB） |
| **帧约束** | 固定 10/20/30ms | v5 支持变长 chunk |
| **音乐/稳态噪声** | 误报高 | 明显更鲁棒 |
| **可训练性** | 不可 | 可用自己的数据 finetune |
| **CPU 开销** | 极低 | 极低（RTF < 0.001） |

### 3.3 Frame-based vs Model-based（聚合状态机）

无论用什么打分器，VAD 系统都分两层：

* **frame-based（帧级判决）**：逐帧独立输出 speech/nospeech，抖动大，不可直接用；
* **model-based / state machine（带迟滞的状态机）**：对帧级概率做**平滑 + 最小时长约束**，才形成可用的段级（segment-level）输出。

```
帧级原始概率: 0 0 0 0.1 0.3 0.9 0.95 0.9 0.5 0.1 0.2 0.8 0.9 0.7 0.1 0 0
                              └── 语音起 ──┘        └─ 短隙<min_sil ─┘
状态机输出:   ----|====== 语音段（合并短隙） =====|----

状态机:
  SILENCE --连续 N_start 帧>thr--> SPEECH
  SPEECH --连续 N_end 帧<thr-->   SILENCE   (且语音段 >= min_speech_dur)
```

## 4. 关键参数调优：hangover、min duration、阈值

### 4.1 Hangover（拖尾保护）

**hangover** 是最经典的防截断技巧：判定语音结束后，额外延长 $T_{hang}$（如 200~600ms）再真正关门。因为人说话句尾有拖音、气音，能量先掉下去但语音还没结束，若立即截断会把句尾字切掉（ASR 吞字）。

* hangover 太短 -> 句尾截断、ASR 漏字；
* hangover 太长 -> endpoint 延迟上升（实时对话响应变慢）。

### 4.2 最小说音/静音时长（min speech / silence duration）

* **min_speech_duration**（如 50~250ms）：短于该时长的语音段丢弃（去抖动脉冲、咔哒声）；
* **min_silence_duration**（如 400~800ms）：语音段内短于该时长的静音不切分（避免一句话被腰斩），同时它直接决定 ASR endpoint 的句尾确认延迟。

| 参数 | 典型值 | 调大效果 | 调小效果 |
| --- | --- | --- | --- |
| `threshold`（概率门限） | 0.5~0.7 | 漏检增（recall 降） | 误报增（FA 升） |
| `min_speech_duration` | 100~250ms | 过滤掉短促词 | 保留咳嗽/咔哒误触发 |
| `min_silence_duration` | 400~800ms | 切分少、endpoint 慢 | 切分碎、句尾吞字风险 |
| `hangover` | 200~600ms | 句尾安全但延迟高 | 延迟低但截断风险 |
| `speech_pad`（前后padding） | 30~200ms | ASR 上下文足、FA 增 | 首字/末字可能被切 |

### 4.3 阈值调优方法论

1. **先定业务损失函数**：打断场景 FA 代价高（误停止 TTS）；转写场景 miss 代价高（漏字）。
2. **用标注数据扫 ROC**：取真实场景的帧级/段级标注，画 speech probability 的 ROC，按目标 miss rate（如 < 2%）反推 threshold。
3. **分场景阈值**：端侧麦克风、蓝牙耳机、8kHz 电话音质分别建阈值配置。

## 5. VAD 在流式 ASR / 打断检测中的作用

### 5.1 流式 ASR 中的三种角色

1. **前置切分（VAD-first）**：VAD 先切出语音段，只把 speech 段送 ASR（Whisper 类离线模型必须如此，防幻觉、省算力）；
2. **Endpoint 判定（ASR 内嵌）**：流式 Transducer 系统中，VAD/endpoint head 判定句尾，触发 final 结果与二遍纠错；
3. **状态门控**：长静音期间 encoder 保持 idle 或仅跑轻量状态，省 GPU/CPU。

### 5.2 打断检测（Barge-in）链路

```
 TTS 播放 ──> 扬声器 ──> 声学回声 ──┐
                                    ├─> AEC(回声消除) ──> VAD ──> 打断?
 用户语音 ──────────────────────────┘                        │
                                                     是 ──> 停 TTS + 重置 ASR
```

打断检测的关键指标是**打断响应时间**（用户开口到 TTS 停止，要求 < 200~300ms）与**误打断率**（TTS 播放被环境噪声/回声残余误停）。因此：

* AEC 质量直接决定 VAD 打断的上限（残余回声是 FA 的最大来源）；
* 打断判定常用「VAD 触发 + 能量/时长双重确认」（如连续 3~5 帧 speech 且能量 > 门限），用 100~200ms 换取消除误触发。

## 6. VAD 评估指标

| 潜力指标 | 定义 | 说明 |
| --- | --- | --- |
| **Recall（_miss rate_）** | 被检出的语音帧 / 总语音帧 | 转写场景核心指标，漏检 = ASR 吞字 |
| **Precision** | 真语音帧 / 判为语音的帧 | 打断场景核心指标 |
| **FA / hour（每小时误触发次数）** | 每小时音频中非语音被误判为语音段的次数 | 端侧唤醒/打断的一级指标，常见要求 < 0.5~2 次/小时 |
| **FA time ratio** | 误判为语音的非语音时长占比 | 连续指标，比次数更细 |
| **AUC** | speech probability 的 ROC 曲线下面积 | 模型级（不带状态机）对比常用 |
| **段级 F1** | 切出的段与 ground truth 按 IoU>0.5 匹配 | 衡量切分质量（起止点偏移） |

典型量级参考：Silero v4/v5 在常见测试集上 recall > 95%、FA < WebRTC 的 1/5；端侧产品级要求 FA < 1 次/小时 @ recall > 97%。注意 **recall 与 FA 必须成对报告**，单独一个没有意义。

## 7. Python 实战：Silero VAD 流式切分

```python
# pip install silero-vad onnxruntime numpy
import numpy as np, onnxruntime as ort

class SileroVAD:
    def __init__(self, thr=0.5, min_speech=250, min_silence=600,
                 hangover_ms=300, sr=16000):
        self.sess = ort.InferenceSession("silero_vad.onnx")
        self.h = np.zeros(2 * 128, dtype=np.float32)      # LSTM hidden
        self.c = np.zeros(2 * 128, dtype=np.float32)      # LSTM cell
        self.sr = np.array(sr, dtype=np.int64)
        self.thr, self.hang = thr, hangover_ms * sr // 1000
        self.min_speech, self.min_silence = min_speech, min_silence

    def __call__(self, chunk: np.ndarray) -> float:
        """输入 512 samples (32ms) chunk, 返回 speech prob 并更新状态"""
        out = self.sess.run(None, {
            "input": chunk[None, None, :].astype(np.float32),
            "h": self.h.reshape(2, 1, 128),
            "c": self.c.reshape(2, 1, 128),
            "sr": self.sr})
        prob, self.h, self.c = out[0][0][0], out[1].ravel(), out[2].ravel()
        return float(prob)

class VADStateMachine:
    """带 hangover 与最小时长约束的段级状态机"""
    def __init__(self, vad: SileroVAD):
        self.vad, self.in_speech = vad, False
        self.speech_run = self.sil_run = 0        # 连续帧计数
        self.seg_start = None

    def feed(self, chunk: np.ndarray, n_samples: int):
        p = self.vad(chunk)
        if not self.in_speech:
            self.speech_run = self.speech_run + 1 if p > self.vad.thr else 0
            if self.speech_run * n_samples >= self.vad.min_speech * 16:
                self.in_speech, self.seg_start = True, "start"
                self.sil_run = 0
                return "speech_start"
        else:
            self.sil_run = self.sil_run + 1 if p < self.vad.thr else 0
            # 静音需连续超过 min_silence + hangover 才判段尾
            if self.sil_run * n_samples >= (self.vad.min_silence + self.vad.hang) * 16:
                self.in_speech = False
                return "speech_end"
        return None
```

## 8. 高频面试问答 (Q&A)

### Q1: 为什么能量 VAD 在噪声场景失效？怎么改进？

**答**：能量 VAD 隐含「语音能量 > 噪声能量」的假设，低 SNR 下失效；且无法区分音乐、键盘声等高能量非语音。改进路径：(1) 加 ZCR、谱熵、谱平坦度等多特征；(2) GMM/统计判决（似然比 + 噪声模型在线更新）；(3) 神经网络 VAD（Silero），用数据学到语音的判别性表征，对稳态噪声鲁棒。

### Q2: hangover 机制是什么？为什么必须有？

**答**：hangover 是判定语音结束后额外延长一段（200~600ms）再关门。句尾拖音/气音能量低，帧级判决会提前翻转，若立即截断会把最后一个字切掉导致 ASR 吞字；代价是 endpoint 延迟上升。实时对话（要低延迟）与离线转写（要完整）应配置不同 hangover。

### Q3: WebRTC VAD 和 Silero VAD 怎么选？

**答**：WebRTC 是 GMM 硬编码实现、零依赖极轻，但音乐/噪声误报高且不可训练；Silero 是 ~2MB 的小 DNN，准确率明显更高（尤其 FA），RTF < 0.001 同样端侧友好，且可以自有数据 finetune。新项目默认 Silero；只在包体/依赖极度敏感且场景干净时用 WebRTC。

### Q4: VAD 的 threshold、min_silence_duration 具体怎么调？

**答**：先明确业务代价（打断怕 FA、转写怕 miss）；用带标注的真实场景数据画 ROC，按目标 miss/FA 反推 threshold；min_silence_duration 由「希望的句尾确认延迟」直接决定（600ms 阈值 ≈ 说话结束后 600ms 出 final）；最后分设备/信道（麦克风 vs 蓝牙 vs 电话 8kHz）分别配置。上线后持续监控 FA/hour 与人工反馈回归。

### Q5: 实时对话的打断检测链路怎么设计？误打断怎么压？

**答**：链路 = AEC（消除 TTS 回声）-> VAD -> 打断决策（停 TTS + 重置 ASR 状态）。误打断主要来自残余回声与环境噪声：AEC 后再加残余抑制（NISP/NS）；决策上加双重确认（连续 N 帧 speech + 能量门限 + 可选 keywords 二次校验），用 100~200ms 确认延迟换取误打断率数量级下降。

## 9. 总结与最佳实践

* **选型路径**：能量/ZCR（极简、干净场景）-> GMM/WebRTC（轻量、不可训练）-> Silero 类 NN VAD（默认推荐，准确且端侧友好）。
* **帧级打分必须配状态机**：threshold + min_speech_duration + min_silence_duration + hangover + speech_pad 五参数共同决定切分质量与 endpoint 延迟，按业务调优。
* **指标成对报告**：recall 与 FA/hour 缺一不可；打断场景看 FA，转写场景看 recall 与段级 F1。
* **系统视角**：VAD 不是孤立模块，AEC 质量、麦克风通道、ASR endpoint 策略共同决定最终体验；上线后必须有分场景监控与阈值灰度机制。

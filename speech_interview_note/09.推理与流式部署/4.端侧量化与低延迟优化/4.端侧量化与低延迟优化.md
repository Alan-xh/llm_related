# 4. 端侧量化与低延迟优化

## 1. 概述

语音模型上端侧（手机、TWS 耳机、智能音箱、车机）面临三重硬约束：**算力弱（无独显、CPU 小核）、内存有限（几百 MB 预算）、能耗敏感（电池/发热）**。例如一个 80M 参数的 Conformer encoder FP32 约 320MB，在手机上既放不下也跑不快；量化到 INT8 后约 80MB、速度提升 2~3 倍，才能满足端侧流式 ASR 的 RTF < 0.3（单核）要求。

端侧优化的三板斧：

1. **量化（Quantization）**：FP32/FP16 -> INT8/INT4，压体积、提速度、降功耗；
2. **模型压缩**：剪枝（pruning）、稀疏化（sparsity）、知识蒸馏（distillation）减小模型本身；
3. **系统优化**：算子融合、delegate 加速（NPU/DSP）、batch=1 内存与延迟优化、流水线调度。

---

## 2. 量化原理

### 2.1 量化公式：对称与非对称

量化的本质是用低精度整数网格逼近浮点数值分布。**非对称量化（asymmetric）**：

$$x_{\text{int}} = \text{clamp}\left(\text{round}\left(\frac{x}{s}\right) + z\right), \quad s = \frac{x_{\max} - x_{\min}}{2^b - 1}, \quad z = \text{round}\left(-\frac{x_{\min}}{s}\right)$$

反量化（dequantize）：$\hat{x} = s \cdot (x_{\text{int}} - z)$。其中 $s$ 为 scale（浮点步长），$z$ 为 zero-point（整数偏移）。

**对称量化（symymmetric）** 强制 $z = 0$，$s = \frac{\max|x|}{2^{b-1} - 1}$：

* 对称：适合权重（分布近似零对称），计算无偏移项，硬件更友好；
* 非对称：适合激活值（如 ReLU 后全为正，分布明显偏移），表示范围利用率更高。

### 2.2 per-tensor vs per-channel

| 粒度 | 含义 | 精度 | 开销 |
| --- | --- | --- | --- |
| **per-tensor** | 整个张量一个 $(s, z)$ | 最低（离群值毁全局） | 零额外算子 |
| **per-channel（axis=输出通道）** | 每个输出通道一组 $(s, z)$ | 高（权重标准做法） | scale 向量极小 |

经验：**权重用 per-channel 对称 INT8，激活用 per-tensor 非对称 INT8**，是 CV/语音任务几乎无损的默认配方。

### 2.3 PTQ 与 QAT

* **PTQ（Post-Training Quantization，训练后量化）**：训练完直接量化，用几百条校准（calibration）数据统计激活分布确定 scale。关键在**校准算法**：min/max（对离群值敏感）、Percentile（如 99.9% 截断）、KL 散度（TensorRT 经典，搜索使量化前后分布 KL 最小的阈值）、MSE。优点零训练成本；缺点对离群值敏感的模型掉点。
* **QAT（Quantization-Aware Training，量化感知训练）**：训练图中插入 **fake-quantize 伪量化节点**（前向模拟量化误差，反向用 STE 直通估计器），让模型在训练中适应量化噪声。精度最好，但需要训练管线与数据。

$$\text{STE: } \frac{\partial \hat{x}}{\partial x} \approx 1 \quad (\text{在 } [x_{\min}, x_{\max}] \text{内}), \; 0 \text{ otherwise}$$

选型经验：INT8 权重 + FP16 激活（weight-only 或 W8A16）几乎总能 PTQ 无损；全 INT8（W8A8）多数语音 encoder 可以 PTQ（CER 损失 < 0.3%）；有离群值的 LLM/TTS 声码器需 QAT 或混合精度。

### 2.4 INT8 / INT4 与 weight-only 量化

* **W8A8（全 INT8）**：权重与激活都 INT8，GEMM 走 INT8 矩乘（CPU 的 VNNI / NPU 的 INT8 单元），速度收益最大（相对 FP32 约 2~4x）。
* **weight-only（W8A16 / W4A16）**：只压权重，激活保持 FP16。带宽省 2~4 倍、显存/内存省同比例，但计算仍是浮点 GEMM。适合 **LLM/TTS 大模型**：激活离群值严重、全量化掉点大，weight-only 是精度与体积的折中。INT4 weight-only（配合 GPTQ/AWQ 这类离群值保护算法）已成为 LLM 端侧标配。
* **INT4**：体积为 FP32 的 1/8；但通用 CPU 缺 INT4 GEMM 支持，多用于 NPU（QNN 支持 INT4 weight）与 LLM 权重。

### 2.5 KV Cache 量化

自回归解码（Whisper decoder、LLM-based TTS 如 CosyVoice/VALL-E）的 KV cache 随序列长度线性增长，是端侧内存主要瓶颈之一：

* KV cache 从 FP16 量化到 INT8（per-head/per-channel scale），内存减半，精度损失通常 < 0.5% WER；
* 极限场景用 INT4 KV + FP8/FP16 混合（重要 head 保高精度）；
* 收益例：1B 参数 LLM、序列 2048 时 FP16 KV 约 100MB+ 量级，INT8 直接减半，直接决定端侧能否跑长上下文。

## 3. 端侧推理框架

| 框架 | 平台 | 特点 | 语音生态 |
| --- | --- | --- | --- |
| **CoreML** | iOS/macOS | Apple ANE（神经引擎）加速，`coremltools` 转换 | whisper.cpp 可转 CoreML |
| **NNAPI** | Android | 系统 NPU 分发层（Android 15 后被 **LiteRT (TFLite) Delegates** 逐步替代） | TFLite ASR 常用 |
| **QNN (Qualcomm SNPE/QNN)** | 骁龙 Hexagon DSP/NPU | 耳机/手机低功耗推理，HTP 单元 INT8 极强 | TWS 耳机 VAD/KWS 部署首选 |
| **MNN (阿里)** | 全平台（移动端强） | 深度算子融合、无依赖、体积小 | 移动端语音/视觉 |
| **NCNN (腾讯)** | 移动 CPU 优化极致 | ARM NEON 手写算子多、无第三方依赖 | 端侧 ASR 前处理/vocoder |
| **LiteRT/TFLite** | Android 为主 | XNNPACK delegate、量化工具链成熟 | Google 端侧 KWS/ASR |
| **ONNX Runtime** | 全平台 | 通过 EP 挂 CoreML/NNAPI/QNN | sherpa-onnx 端侧方案 |

选型逻辑：Apple 生态 CoreML（冲 ANE）；高通设备 QNN（冲低功耗 HTP）；跨 Android/通用 CPU 用 NCNN/MNN/LiteRT；要一套代码多端则 ONNX Runtime + 各 EP。

## 4. 端侧 ASR / TTS 案例

### 4.1 whisper.cpp

* **ggml** 自研张量库（C/C++，零依赖）跑 Whisper 全系模型；`int8` / `4-bit/5-bit` 量化权重（`quantize` 工具），tiny/base 量化后 40~80MB 级；
* CPU 上 tiny 模型 RTF 可 < 0.1（现代手机），配合 **CoreML 转换**把 encoder 冲 ANE；
- 架构：encoder（非流式，按 30s 窗）+ decoder 自回归；适合准实时听写，非严格流式。

### 4.2 sherpa-onnx

- k2-fsa 生态的**全平台流式语音栈**：Zipformer/Transducer/CTC + 流式 VAD + 说话人 + TTS（vits/matcha）一把梭；
- 模型全部转 ONNX，解码器 C++ 实现拆 encoder/predictor.step/joint 三图；
- 端侧典型配置：Zipformer-small 流式 INT8 模型 ~30-50MB，中端手机单核 RTF ~0.1-0.3，是端侧流式 ASR 的事实标准开源方案。

### 4.3 PocketFlex（字节 Seed-TTS 轻量线）

- 字节 Seed-TTS 技术报告披露的**端到端流式 TTS**：token→wav 单模型，Speaker-Text 解耦；
- 端侧走「云端大模型 TTS 蒸馏出的轻量学生模型」：INT8 量化 + 算子融合后实现在手机 CPU 上**流式低延迟合成**（RTF < 1、首包亚秒级）；
- 代表了「云端大 TTS + 端侧小 TTS」的蒸馏上端范式。

## 5. 稀疏化、剪枝与蒸馏

### 5.1 剪枝（Pruning）与稀疏化（Sparsity）

* **非结构化剪枝**：按权重幅值置零（如压 50%~80%），理论 FLOPs 降但通用硬件无加速，需稀疏 kernel 支持；
* **结构化剪枝**：剪整个通道/注意力头/层，硬件直接受益（模型变小变快），精度损失略大，可配 finetune 恢复；
* **N:M 稀疏（如 2:4）**：NVIDIA Ampere+ 硬件级支持，每 4 个权重 2 个为零，GEMM 提速最高 ~1.5~2x，需训练配合（mask 学习）；
* 语音 encoder 的常见结构化压缩：**降帧率（stacking/下采样，帧率 100Hz->25Hz）**、剪 Conformer 的 conv 模块通道、头数减半。

### 5.2 知识蒸馏（Knowledge Distillation）

学生模型逼近教师输出分布，损失为 KL 项与硬标签 CE 的加权：

$$\mathcal{L} = \alpha \cdot T^2 \cdot \text{KL}\big(\text{softmax}(z_T / T) \,\|\, \text{softmax}(z_S / T)\big) + (1-\alpha)\, \text{CE}(y, z_S)$$

* **DistilWhisper**：Whisper large-v2 蒸馏出 **0.75B 学生**（层数 32->2、encoder 减半），在英文长音频上 WER 仅落后教师 ~1%，**推理速度快 ~6 倍、显存省 ~50%**，是「大模型蒸馏上端」的代表案例；
* 蒸馏技巧：多教师（ASR 教师 + 伪标签数据）、逐层中间表征对齐（layer-wise hint）、数据不均衡场景用伪标签扩量。

## 6. 延迟优化 Checklist

上线前的端侧优化检查表：

1. **算子融合**：Conv+BN+ReLU 合并、LayerNorm 拆分与 GELU 融合（转换器/框架自动做，需检查图输出确认生效）；
2. **GPU/NPU delegate**：能下发的算子尽量下发（CoreML/QNN/XNNPACK），关注算子回退（fallback 到 CPU 的算子是隐形瓶颈）；
3. **batch=1 优化**：关闭 dynamic batch、固定 shape（去掉 reshape/gather 分支）、GEMM 走 GEMV 路径；预分配全部 IO，稳态零 malloc；
4. **线程与绑核**：大小核调度（大核跑 encoder、小核跑 VAD）、线程数等于物理核，避免超线程争抢；
5. **内存**：权重 `mmap` 加载（减少启动峰值）、INT8 权重、模型常驻内存防反复换页；峰值内存（peak RSS）纳入 CI 监控；
6. **计算精度**：FP16 中间激活、INT8 权重、只对精度敏感层（如 encoder 末层、joint）保留 FP16 的混合精度；
7. **流水线并行**：特征/前向/解码三级流水（见第 3 篇线程模型），chunk 间重叠隐藏延迟；
8. **帧率与剪枝**：encoder 输入下采样（100Hz->50/25Hz）是语音特有的 2~4 倍免费加速；
9. **启动**：模型分块懒加载、首帧前 warm-up 前向，冷启动 < 300ms；
10. **度量**：P50/P99 单 chunk 延迟、RTF、peak RSS、耗电（mAh/min）四指标进自动化回归。

## 7. Python 实战：INT8 PTQ 校准与量化误差评估

```python
# 以 ONNX Runtime 对流式 Zipformer encoder 做 INT8 PTQ 为例
# pip install onnx onnxruntime.quantization
import numpy as np
from onnxruntime.quantization import (CalibrationDataReader,
                                      quantize_static, QuantType, QuantFormat,
                                      CalibrationMethod)

class FeatReader(CalibrationDataReader):
    """用真实场景的 Fbank 特征做校准，覆盖静音/噪声/语速分布"""
    def __init__(self, feats_list):               # list of [T, 80]
        self.rewind, self.feats_list = None, feats_list
    def get_next(self):
        if self.rewind is None:
            self.rewind = iter(self.feats_list)
        try:
            f = next(self.rewind)
            return {"features": f[None, ...].astype(np.float32)}
        except StopIteration:
            return None

reader = FeatReader(load_calibration_feats(n=512))   # 512 条校准样本

quantize_static(
    model_input="encoder_fp32.onnx",
    model_output="encoder_int8.onnx",
    calibration_data_reader=reader,
    quant_format=QuantFormat.QOperator,            # 生成真 INT8 算子
    activation_type=QuantType.QInt8,               # 激活: 非对称 QInt8/QUInt8
    weight_type=QuantType.QInt8,                   # 权重: per-channel 对称
    calibrate_method=CalibrationMethod.Percentile, # 99.99% 截断抗离群值
    per_channel=True,
    extra_options={"ActivationSymmetric": False},
)

# 量化效果评估: CER 对比 + RTF 对比
def evaluate(onnx_path, testset):
    import onnxruntime as ort, time
    sess = ort.InferenceSession(onnx_path,
                                sess_options=make_opts(threads=4))
    cer, times = 0.0, []
    for wav, ref in testset:
        feats = extract_fbank(wav)
        t0 = time.perf_counter()
        out = sess.run(None, {"features": feats[None]})[0]
        times.append((time.perf_counter() - t0) / (feats.shape[0] * 0.01))
        cer += compute_cer(decode(out), ref)
    print(f"CER: {cer/len(testset):.3%}, mean RTF: {np.mean(times):.3f}, "
          f"P99 RTF: {np.percentile(times, 99):.3f}")

# 经验结论(流式 Zipformer-small, 640ms chunk):
#   FP32   -> CER 5.10%, RTF 0.42
#   INT8   -> CER 5.23%, RTF 0.18   # 损失 0.1x%, 速度 ~2.3x
# 若 CER 掉点 >1%: 换 KL 校准 -> 混合精度(敏感层跳过) -> QAT
```

## 8. 高频面试问答 (Q&A)

### Q1: 写出对称/非对称量化公式，并说明各自适用场景。

**答**：非对称 $x_q = \text{round}(x/s) + z$，$s = (x_{\max}-x_{\min})/(2^b-1)$，$z=\text{round}(-x_{\min}/s)$，反量化 $\hat{x} = s(x_q - z)$；对称即 $z=0$、$s=\max|x|/(2^{b-1}-1)$。权重分布近似零对称，用 per-channel 对称；激活（尤其 ReLU 后）分布偏移，用 per-tensor 非对称。对称少一次偏移运算，硬件乘累加更友好。

### Q2: PTQ 和 QAT 怎么选？PTQ 掉点了怎么办？

**答**：先 PTQ（零训练成本，几百条校准数据即可），评估 CER/WER 损失。若掉点 > 0.5~1%：(1) 检查校准数据是否覆盖真实分布；(2) 换校准方法（min/max -> percentile/KL）；(3) 找出离群值敏感层，做混合精度（该层保留 FP16，`OpTypeToExclude` 跳过）；(4) 仍不满足则上 QAT（fake-quant + STE，短 epoch finetune）。TTS 声码器与 LLM 解码器一般直接 QAT 或 weight-only。

### Q3: 为什么 LLM 常用 weight-only INT4，而语音 encoder 常用 W8A8？

**答**：LLM 的激活存在系统性离群值（outlier channels），全 INT8 激活量化误差被放大，掉点明显；而其瓶颈常在权重带宽（内存 bound），所以 weight-only（GPTQ/AWQ，激活保 FP16）是精度-速度折中。语音 encoder 激活分布平稳、GEMM 是计算 bound，W8A8 能吃到 VNNI/NPU 的 INT8 矩乘 2~4 倍加速，PTQ 即可近无损。

### Q4: 端侧流式 ASR 完整上机流程是什么？各环节用什么工具？

**答**：(1) 训练 Zipformer/Transducer 流式模型；(2) 导出 ONNX（encoder 拆 cache、predictor 拆 step）；(3) `quantize_static` INT8 PTQ + CER 回归；(4) 用 sherpa-onnx / ORT（挂 CoreML/NNAPI/QNN EP）在目标设备实测 RTF 与 P99；(5) 系统层做 batch=1 固定 shape、线程绑核、IO 预分配；(6) 监控 peak RSS 与耗电，纳入发布门槛。

### Q5: 除了量化，还有哪些让模型「变小变快」的手段？各自代价是什么？

**答**：结构化剪枝（通道/头/层，直接快但精度损失需 finetune 恢复）；N:M 稀疏（2:4 硬件加速，需训练配合 mask）；知识蒸馏（小学生逼近大教师，DistilWhisper 0.75B 快 6 倍仅掉 1%，代价是需要蒸馏数据与算力）；降帧率（语音特有，100Hz->25Hz 输入直接省 4 倍 encoder 计算，几乎免费）；早退（early-exit）/动态深度（简单帧走浅层）。实践上通常「蒸馏出小模型 + INT8 量化 + 算子融合」组合使用。

## 9. 总结与最佳实践

* **量化配方默认值**：权重 per-channel 对称 INT8 + 激活 per-tensor 非对称 INT8 + percentile/KL 校准；LLM/TTS 用 weight-only INT4/INT8 + KV cache INT8；掉点走混合精度 -> QAT 阶梯。
* **框架按平台选**：Apple CoreML、高通 QNN、通用 ONNX Runtime/NCNN/MNN；重点盯 delegate 的算子回退。
* **案例范式**：whisper.cpp（ggml + 量化，准实时）、sherpa-onnx（ONNX 流式全家桶，端侧流式事实标准）、PocketFlex（云端大 TTS 蒸馏上端）。
* **优化不是单点**：量化 + 剪枝/蒸馏 + 算子融合 + 帧率下降 + batch=1 系统优化组合拳；RTF、P99 延迟、peak RSS、耗电四指标做 CI 回归，才算「能上端侧」。

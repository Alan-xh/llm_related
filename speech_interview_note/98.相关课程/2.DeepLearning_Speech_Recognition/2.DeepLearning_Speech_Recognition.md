# 2. DeepLearning_Speech_Recognition

## 1. 概述

深度学习语音识别（Deep Learning based Speech Recognition）在过去十余年完成了从「混合架构」到「端到端」再到「大规模弱监督 / 语音大模型」的三次范式跃迁：

* **DNN-HMM 混合时代（2011~2015）**：DNN 替换 GMM 做声学建模，流水线仍是 AM + 词典 + LM + WFST；
* **端到端时代（2015~2022）**：CTC / RNN-T / Attention 三大范式逐步统治，训练目标直接是「音频 -> 文本」；
* **大规模预训练时代（2022~）**：Whisper 用 68 万小时弱监督数据刷新鲁棒性认知，语音大模型（Audio-LLM）把 ASR 变成 LLM 的「听力器官」。

本文按此主线梳理架构、损失函数、Encoder 演进、语言模型融合、流式设计与大模型趋势，并给出关键论文演进时间线。

```
范式跃迁总览:

GMM-HMM ──> DNN-HMM ──> CTC ──┐
                    RNN-T ─────┼──> 端到端统一 ──> 弱监督大规模 (Whisper) ──> 语音大模型 (Audio-LLM)
                    LAS/AED ───┘         │
                                        Conformer / Zipformer 流式化
```

## 2. DNN-HMM 混合架构

### 2.1 架构与训练流程

DNN-HMM 用 DNN 替换 GMM 来估计 HMM 状态（Senone）的后验，再经先验归一化得到似然：

$$P(x_t \mid s_i) = \frac{P(s_i \mid x_t)\, P(x_t)}{P(s_i)} \quad (\text{除法项在解码中可并入图权重})$$

```
训练: 语音 -> Fbank -> [GMM-HMM 初 bootstrap] -> 帧级强制对齐 -> DNN 交叉熵训练 (-> sMBR 序列判别微调)
解码: 语音 -> Fbank -> [DNN] -> Senone 后验 -> [WFST: H C L G] -> Beam Search -> 文本
                       H: HMM 状态    C: 上下文相关    L: 发音词典    G: 语言模型
```

| 组件 | 作用 | 典型实现 |
| --- | --- | --- |
| 声学模型 AM | $P(x \mid s)$，DNN/BLSTM 预测 Senone | Kaldi nnet3, EESEN |
| 发音词典 | 词 -> 音素串 | Lexicon + G2P 补全 |
| 语言模型 LM | N-gram / RNN LM，解码时打分 | KenLM, Pronical LM |
| 解码图 | HCLG 组合为单一 WFST | Kaldi 标准 |

### 2.2 历史意义与局限

* **贡献**：上下文相关建模（CD-Phone / Senone 聚类）、序列判别训练（sMBR/MMI）、WFST 静态解码图，是 Kaldi 生态的基础；
* **局限**：需要强制对齐引导的多阶段训练、专家依赖重（词典、音素集、状态聚类）、各模块误差无法联合优化--这正是端到端范式的动机。

## 3. 三大端到端范式：CTC / RNN-T / Attention

### 3.1 核心机制对比

| 维度 | CTC (2006/2014) | RNN-T (2013) | LAS / AED (2015) |
| --- | --- | --- | --- |
| 对齐假设 | 帧间条件独立 + Blank 塌陷 | 2D Lattice 路径求和（T×U 网格） | Attention 隐式软对齐 |
| 语言建模能力 | 无内部 LM，需外部 LM | Predictor 显式建模历史文本 | Decoder 强自回归 LM |
| 流式能力 | 天然支持 | 天然支持（工业流式首选） | 原生不支持，需 Chunk 改造 |
| 训练复杂度 | $O(T \cdot V)$ | $O(T \cdot U \cdot V)$（显存大） | $O(T^2 + U^2)$ |
| 幻觉风险 | 几乎无 | 低 | 高（静音/噪声段易重复） |
| 代表系统 | Deepspeech, wav2vec 2.0 头部 | Google/Apple 流式, Zipformer-Transducer | LAS, Transformer-AED, Whisper |

```
CTC:      Audio -> Encoder -> [含 Blank 的逐帧 Softmax] -> 塌陷 B(·) -> Text
RNN-T:    Audio -> Encoder ─────────┐
                                  [+] -> Softmax -> Text   (在 T×U 网格上前向)
          历史文本 -> Predictor ─────┘
AED:      Audio -> Encoder -> ──Cross-Attention──> Causal Decoder -> Text
```

### 3.2 Hybrid CTC/Attention（多任务）

同一个 Encoder 同时接 CTC 与 Attention 两个头，联合损失：

$$\mathcal{L} = \lambda\, \mathcal{L}_{\text{CTC}} + (1-\lambda)\, \mathcal{L}_{\text{CE}}, \quad \lambda \approx 0.5$$

* CTC 约束 Encoder 表达对齐信息，加速收敛并抑制 Attention 早期乱跳；
* ESPNet/Wenet 均以此为默认非流式配方，解码可做 CTC Prefix + Attention 的联合重打分。

## 4. Encoder 演进：LSTM -> Transformer -> Conformer -> Zipformer

### 4.1 演进动机链

```
LSTM (2015~2019)        长依赖建模弱、串行不可并行
   └─> Transformer (2019) 全局注意力并行训练快，但局部细节/平移不变性差
          └─> Conformer (2020) 注意力 + 卷积模块互补，E2E 精度标杆
               └─> Zipformer (2023) 多尺度下采样 + 更快更省，流式新标杆
```

### 4.2 代表结构对比表

| 架构 | 年份 | 核心组件 | 相对特点 / WER 影响 |
| --- | --- | --- | --- |
| BLSTM | 2015 | 双向门控循环 | 帧级局部强、训练慢，流式需改造 |
| Transformer | 2017/2019 | MHSA + FFN，相对位置编码 | 全局建模强、并行快；对局部 phonetic 细节不如卷积 |
| **Conformer** | 2020 | Macaron FFN ×2 + MHSA + **Conv Module** + 池化下采样 | 卷积捕获局部模式 + 注意力捕获全局，LibriSpeech SOTA 时代标杆 |
| **Zipformer** | 2023 | 时间维下采样（2×2×4×8）、**Zipf 重要性加权激活**、Bypass 残差 | 训练快 ~2 倍、参数更少、精度超 Conformer；icefall 主推流式方案 |
| Emformer | 2021 | 块内 Transformer + 全局 Memory Bank | 流式低延迟代表（Amazon） |
| Branchformer | 2022 | 双分支（卷积分支 ∥ 注意力分支） | 可调流式/非流式开销 |
| Squeezeformer / FastConformer | 2022 | 结构仿 MobileNet 剪裁 / 下采样 4× | 推理加速 |
| E-Branchformer | 2022 | 流式友好的 Branchformer | 流式+非流式精度兼顾 |

### 4.3 Conformer Block 结构（重点）

```
                ┌──────────────────────────────────────────────┐
   x ──1/2 FFN──┤── MHSA ──+── Conv(深度可分离+GLU/SwiGLU) ──+──┤──1/2 FFN──┤── LNF ──> out
   (Macaron)    │  (全局)   │       (局部)                   │  (Macaron) │
                └──────────(各子层均带残差与 LayerNorm)─────────┘
```

其下采样采用卷积池化（$\text{stride}=2$，通常连续两次），将 10 ms 帧率降至 40 ms，计算量减 4 倍--这也是现代 Transducer 的标配。

> **面试常问**：Conformer 相比 Transformer 好在哪？答：语音的判别性信息大量存在于局部频谱细节（共振峰转移、摩擦音），卷积模块的局部感受野与参数共享恰好建模这类平移不变模式，与建模全局句法/语音上下文的注意力互补；Macaron 结构与 Swish 激活进一步稳定深网络训练。

## 5. 语言模型融合（Shallow Fusion 为主）

### 5.1 三种融合方式

```
Shallow Fusion (推理期):   score = log P_e2e(y|x) + λ · log P_lm(y)          ← 最常用
Deep Fusion    (训练改头): e2e 隐状态与 LM 隐状态拼接后过联合门控
Cold Fusion    (预训练期): 冻结 LM, 其表示注入 Decoder, 训练时即适配
```

**Shallow Fusion** 在 Beam Search 打分时逐 Token 插入外部 LM：

$$\hat{Y} = \arg\max_Y \left\{ \log P_{\text{E2E}}(Y \mid X) + \lambda \log P_{\text{LM}}(Y) \right\}$$

* 优点：零训练成本、LM 可热替换（领域外文本、热词列表）；
* 缺点：E2E 模型自带 Internal LM，二者双重计入文本先验导致过打分。

### 5.2 Internal LM 的处理

* **ILME（Internal Language Model Estimation）**：推理时显式减去内部 LM 分数：

$$\text{score} = \log P_{\text{E2E}}(Y|X) + \lambda \log P_{\text{LM}}(Y) - \gamma \log P_{\text{ILM}}(Y)$$

* **训练期去偏**：如 Density Ratio / 训练时加入无语音 LM 混合数据，使模型少学语言先验；
* CTC/Transducer 中也可用 WFST（TLG）解码融合 N-gram，是 k2/icefall 的标准做法。

## 6. 流式（Streaming）架构设计

### 6.1 核心问题：未来信息不可见

非流式 Encoder 的双向注意力「偷看未来」，流式必须限制右文上下文（Lookahead）：

```
帧序列:  [F1 F2 F3 F4][F5 F6 F7 F8][F9 F10 F11 F12] ...
          └─ Chunk1 ─┘ └─ Chunk2 ──┘ └─ Chunk3 ───┘
Encoder 限制: Chunk 内 Self-Attention + 右看 N 帧 (Lookahead ~ 0.6~1.2s 因果化)
             + 历史左文通过 Causal Conv / Memory Bank / 有限 Cache 携带
```

### 6.2 关键技术清单

| 技术 | 做法 | 备注 |
| --- | --- | --- |
| Causal / Chunked Attention | 注意力 mask 限制未来帧 | 实现：Wenet U2（统一 chunk 训练/解码）、TF chunk mask |
| Causal Convolution | 卷积左 padding | 下采样层必须同步因果化 |
| Emformer Memory | 每 Chunk 压缩全局记忆向量 | 携带长程历史 |
| Stateless Predictor | RNN Predictor 换 Embedding+N-gram Conv | 降时延、省显存（同帧 max_symbols_per_frame 限制） |
| FastEmit / 延迟正则 | 损失中加入 $\lambda \cdot \text{Latency}$（Token 发射时刻与对齐锚点差） | 训练期显式优化延迟 |
| 模拟流式训练 | 非流式结构与流式结构同参数、随机 chunk 训练 | U2++（双向注意力右看做流式） |
| CIF / Chunk 内单调对齐 | 边界对齐信息做 chunk 切分 | 如 curl-conformer / CIF-based |

### 6.3 评价指标

* **延迟**：首包延迟（Chunk + Lookahead + 网络/解码耗时），语音交互常规要求 $< 300\text{ ms}$，同传要求 $1\sim 3\text{s}$ 语义延迟；
* **稳定性**：流式识别要求中间结果可控变化（partial -> final 稳定度），避免 UI 频繁跳变。

## 7. Whisper 与大规模弱监督

### 7.1 核心设计

Whisper（OpenAI, 2022）：**680,000 小时**互联网弱监督音频（语音+对应字幕），多任务多语态：

* 输入：30 s 对数 Mel 谱 -> 2 层 Conv + 12 层 Transformer Encoder；
* 输出：Transformer Decoder 自回归生成特殊 Token 流：`[语言][任务: 转写/翻译][时间戳][文本]`；
* 任务格式统一为 Seq2Seq，语言识别、翻译、时间戳预测都是 Token 生成的一部分。

### 7.2 弱监督的工程要点

| 要点 | 做法 |
| --- | --- |
| 数据筛选 | 与强 ASR 系统伪标签一致性 + 语言检测 + 启发式过滤（弱标签噪声容忍） |
| 鲁棒性来源 | 海量多领域多噪声数据本身（而非数据清洗极致纯净），零样本泛化强 |
| 已知缺陷 | 30 s 切分无跨窗上下文、长静音/噪声下 Decoder 幻觉重复、无流式、无说话人分离 |
| 修复策略 | 前置 VAD 切分、no_speech 阈值、temperature fallback、重复惩罚、logprob 重排 |

> **面试常问**：为什么 Whisper 不适合直接流式部署？答：Encoder 双向 + 训练分布为固定 30 s 窗，Decoder 自回归生成整段文本，缺乏 Chunk 内单调发射机制；工业流式仍以 Transducer 为主，Whisper 适合离线转写、字幕、伪标签生产（再蒸馏为流式小模型，如 Distil-Whisper）。

## 8. 语音大模型时代的 ASR

### 8.1 趋势与代表

| 路线 | 代表工作 | 核心思想 |
| --- | --- | --- |
| 纯音频自监督 | wav2vec 2.0 (2020), HuBERT, W2v-BERT | 对比学习/掩码预测预训练 Encoder，小数据高精度 ASR |
| 大规模多语种监督 | USM (2023), MMS (Meta, 2023), SeamlessM4T (2023) | 百万小时级多语种/多任务统一模型 |
| 语音 Token + LLM | **AudioLM**, SpeechGPT, **VALL-E**, **SALMONN**, **Qwen-Audio/2**, **Moshi** | 离散化语音 Token（Codec/RVQ）接 LLM，统一理解与生成 |
| 语音到语音对话模型 | Moshi (2024), GLM-4-Voice, GPT-4o (无公开论文) | 全双工低延迟，ASR 隐式成为内部模块 |
| 工业高精度中文 | Paraformer (2022), SenseVoice (2024), FireRedASR, Seed-ASR (2024) | CIF 非自回归 / 多语种情感 / 上下文 LLM 热词 |

### 8.2 ASR 角色的变化

* **从「显式模块」到「能力」**：在 Audio-LLM 中，转写、翻译、说话人属性、情感、音频事件理解统一为指令微调任务，ASR 成为多任务音频理解的一个子集；
* **Codec Token 成为桥梁**：SoundStream/EnCodec 的 RVQ Token 让「听」与「说」共用一套离散表示，TTS 与 ASR 在大模型中合流；
* **蒸馏与端侧化**：大模型伪标签 -> 蒸馏小模型（Distil-Whisper、Seed-ASR 小型化）依然是工业落地主线。

## 10. 高频面试问答（Q&A）

### Q1: DNN-HMM 与端到端的核心区别是什么？各在什么场景仍有优势？

**答**：DNN-HMM 显式拆分为 AM/词典/LM/WFST，需要强制对齐与多阶段训练；E2E 用单一网络直接优化 $P(Y|X)$，训练简单、无需词典。混合系统在小数据 + 强专家知识（固定域、可维护词典、WFST 热词约束）场景仍有工程价值；E2E 在数据充足、多语种、快速定制场景全面占优。

### Q2: CTC、RNN-T、AED 三者如何做工程选型？

**答**：离线高精度多语种 -> AED/Hybrid CTC-Attention（Whisper 类）；实时流式低延迟 -> Transducer（Zipformer/Conformer-Transducer）；追求极致简单轻量、可热词 WFST -> CTC。另外可用 Hybrid 结构一套 Encoder 兼顾流式与非流式双输出（CTC/Transducer 头 + Attention 头）。

### Q3: Shallow Fusion 的 λ 如何调？为什么不能无脑加大 LM 权重？

**答**：λ 在验证集上格点搜索（典型 0.3~0.7）。过大时外部 LM 支配打分，声学证据被忽略，容易出现「LM 通顺但听感不对」的替换错误；且 E2E 模型自带 Internal LM，双重计入文本先验，需要 ILME 修正或降低 λ。

### Q4: 如何把一个非流式 Conformer 改造成流式？

**答**：1) 下采样卷积改 Causal/左 padding；2) Self-Attention 改 Chunk-based mask + 有限 Lookahead；3) 训练时随机 chunk 长度模拟流式（U2 方案），或用 U2++ 保留双向结构推理时右看对齐；4) Predictor 换 Stateless；5) 用 FastEmit 类延迟正则显式压首 Token 发射时刻；6) 评估 Chunk+Lookahead 决定的固有延迟下限。

### Q5: Whisper 的幻觉在工程上如何缓解？

**答**：前置 VAD 去静音与音乐段；利用 `no_speech_prob` 与 `avg_logprob` 阈值丢弃可疑段；temperature fallback（0 -> 0.2 -> ... -> 1.0）打破自回归死循环； repetition penalty；30 s 窗口过度切分导致的断句错误可用更长窗模型或长音频专用解码（如 long-form whisper 的顺序策略 + beam）缓解。

## 11. 总结

* **范式主线**：DNN-HMM（模块化、专家依赖）-> CTC/RNN-T/AED（端到端、三大损失）-> Whisper（弱监督大规模、鲁棒性优先）-> Audio-LLM（Codec Token + LLM，理解生成合流）。
* **Encoder 演进的本质**：局部模式（卷积）与全局依赖（注意力）的配比不断优化，同时通过时间下采样和流式化约束持续压缩推理成本（LSTM -> Transformer -> Conformer -> Zipformer）。
* **工程落地的三大支柱**：流式低延迟（Chunk/因果化/延迟正则）、领域适配（Shallow Fusion/ILME/热词）、大规模数据（弱监督伪标签 + 蒸馏）。
* **面试备考重点**：三大 E2E 损失的推导与对比、Conformer 结构细节、流式改造手段、Whisper 优劣与大模型时代 ASR 角色变化；建议结合本仓库《3.RNN-Transducer》《ASR面试题》交叉复习。

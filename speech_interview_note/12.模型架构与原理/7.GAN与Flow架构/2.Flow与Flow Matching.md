# 2. Normalizing Flows 与 Flow Matching

## 1. 概述

**归一化流 (Normalizing Flows, NF)** 与近年兴起的 **连续流匹配 (Continuous Flow Matching, CFM)** 是音频与语音生成中另一类极其重要的生成范式（代表作：WaveGlow、Glow-TTS、Voicebox、CosyVoice 等）。

* **Normalizing Flow 核心**：通过一系列**可逆双射映射 (Invertible Bijections)**，将简单的先验分布（如标准正态分布 $z \sim \mathcal{N}(0, \mathbf{I})$）变换为复杂的真实音频分布 $x$。
* **Flow Matching 核心**：基于**连续时间神经 ODE (CNF)**，绕过了传统 Flow 必须设计可逆且雅可比行列式易算的严格架构限制，直接拟合从先验到目标的**向量场 (Vector Field)**。

---

## 2. 传统 Normalizing Flow 数学原理

设变量变换 $x = f_\theta(z)$，其中 $f_\theta$ 为可逆映射，其逆变换为 $z = f_\theta^{-1}(x) = g_\theta(x)$。根据概率密度换元公式 (Change of Variables Theorem)：

$$p_X(x) = p_Z(g_\theta(x)) \cdot \left\vert{} \det \frac{\partial g_\theta(x)}{\partial x} \right\vert{}$$

两边取对数似然：

$$\log p_X(x) = \log p_Z(g_\theta(x)) + \log \left\vert{} \det J_{g_\theta}(x) \right\vert{}$$

* **目标**：直接极大化真实数据 $x$ 的**精确对数似然 (Exact Log-Likelihood)**，无需 VAE 的 ELBO 近似，也无需 GAN 的对抗博弈。
* **架构约束**：
  1. $f_\theta$ 必须严格**可逆**（可从 $z \to x$ 生成，亦可从 $x \to z$ 推断）；
  2. 雅可比矩阵 $J_{g_\theta}(x)$ 的行列式必须**极易计算**（通常设计为下三角或对角阵）。

---

## 3. 经典语音流模型

### 3.1 WaveGlow：基于 Flow 的高保真声码器
* **机制**：继承自 WaveNet 和 Glow。
* **Coupling Layer (耦合层)**：采用 **Affine Coupling Layer (仿射耦合层)**。将输入维度 $x$ 拆分为 $x_a, x_b$：
  
  $$z_a = x_a$$

  $$z_b = s(x_a) \odot x_b + t(x_a)$$

  其中 $s(\cdot)$ 和 $t(\cdot)$ 可以是**任意复杂的非可逆神经网络**（WaveGlow 中采用 WaveNet 结构的 1D 卷积网络）。其雅可比行列式为对角阵，对角线元素为 $s(x_a)$。
* **缺点**：模型参数量极大（数亿参数），推理显存占用高。

### 3.2 Glow-TTS：非自回归 TTS 建模
* **创新点**：将 Flow 引入文本到 Mel 谱的生成阶段。结合 **MAS (Monotonic Alignment Search, 单调对齐搜索)** 算法，在无需预先对齐文本与语音的前提下，联合拟合文本到语音的对数似然与对齐轨迹。

---

## 4. 连续流匹配 (Continuous Flow Matching, CFM)

连续流匹配 (CFM) 是目前语音大模型（如 Voicebox、CosyVoice、F5-TTS）最主流的前沿生成范式。

### 4.1 从 ODE 到 Flow Matching
定义连续时间采样过程 $x_t \in [0, 1]$，其中 $t=0$ 对应纯噪声 $x_0 \sim \mathcal{N}(0, \mathbf{I})$，$t=1$ 对应真实音频 $x_1 \sim q(x_1)$。

连续变化由一个**向量场 $v_t(x)$** 控制的常微分方程 (ODE) 驱动：

$$\frac{d x_t}{dt} = v_t(x_t)$$

 Flow Matching 的目标是训练一个神经网络 $v_\theta(x_t, t)$ 去**拟合目标向量场 $v_t(x)$**。

### 4.2 Optimal Transport Continuous Flow Matching (OT-CFM)
为了让生成轨迹尽可能简短且平滑（直线传输），OT-CFM 定义了噪声与样本之间的**条件线性轨迹**：

$$x_t = (1 - t)x_0 + t x_1, \quad t \in [0, 1]$$

对应目标向量场极简为：

$$u_t(x_t \mid x_0, x_1) = \frac{d x_t}{dt} = x_1 - x_0$$

其损失函数极其简单高效（类似于 DDPM 的 MSE 损失）：

$$\boxed{\mathcal{L}_{\mathrm{CFM}}(\theta) = \mathbb{E}_{t \sim \mathcal{U}[0,1], x_0 \sim \mathcal{N}(0, \mathbf{I}), x_1 \sim q(x_1)} \left[ \left\Vert{} v_\theta(x_t, t) - (x_1 - x_0) \right\Vert{}^2 \right]}$$

### 4.3 Flow Matching 与 Diffusion 的对比

| 特性 | Diffusion (DDPM / SDE) | Flow Matching (OT-CFM) |
| --- | --- | --- |
| **轨迹形状** | 弯曲的随机/确定性轨迹 | **直线传输 (Straight Line)** |
| **采样步数** | 需要较多步数 (50~1000 步) | **极少步数 (10~25 步，甚至 Single-step)** |
| **预测目标** | 预测噪声 $\epsilon$ 或得分 $s$ | **预测速度/向量场 (Velocity/Vector Field)** |
| **语音代表作** | AudioLDM, DiffWave | **Voicebox, CosyVoice, F5-TTS** |

## 5. PyTorch 核心代码：OT-CFM 极简实现

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class OptimalTransportFlowMatching(nn.Module):
    """
    Optimal Transport Flow Matching (OT-CFM) 训练与采样核心逻辑
    """
    def __init__(self, vector_field_net: nn.Module):
        super().__init__()
        # vector_field_net: 预测速度向量场的网络 (如 Conformer / DiT / UNet)
        self.net = vector_field_net

    def compute_loss(self, x1: torch.Tensor, cond: torch.Tensor = None):
        """
        x1: 真实语音特征/Mel谱 [B, C, T]
        cond: 文本/音色条件嵌入
        """
        b = x1.size(0)
        t = torch.rand(b, device=x1.device) # t ~ Uniform(0, 1)
        
        # 1. 采样先验噪声 x0
        x0 = torch.randn_like(x1)
        
        # 2. 条件 OT 线性插值轨迹 x_t = (1 - t)*x0 + t*x1
        t_broadcast = t.view(b, 1, 1)
        xt = (1.0 - t_broadcast) * x0 + t_broadcast * x1
        
        # 3. 目标速度矢量 u_t = x1 - x0
        ut = x1 - x0
        
        # 4. 预测速度矢量并计算 MSE 损失
        vt = self.net(xt, t, cond)
        loss = F.mse_loss(vt, ut)
        return loss

    @torch.no_grad()
    def sample_euler(self, shape, cond=None, steps=20, device="cuda"):
        """
        使用简易 Euler 方法求解 ODE 进行快速采样
        """
        x = torch.randn(shape, device=device) # t=0 时为纯噪声
        dt = 1.0 / steps
        
        for i in range(steps):
            t_scalar = i / steps
            t = torch.full((shape[0],), t_scalar, device=device)
            
            # 预测当前位置的速度场
            v = self.net(x, t, cond)
            
            # Euler 积分更新: x_{t+dt} = x_t + v * dt
            x = x + v * dt
            
        return x # t=1 恢复出目标音频特征

```

## 6. 面试高频追问

* **追问 1：连续流匹配 (CFM) 为什么比传统的 Diffusion 采样更快？**
* *答*：因为传统的 Diffusion 前向加噪使得边际分布的变换轨迹是弯曲的，离散求解 ODE/SDE 时需要极小的步长以控制截断误差；而 OT-CFM 通过最优传输理论将先验分布到数据分布的映射约束为**直线轨迹 (Straight Trajectory)**，其向量场几乎平直，因此只需极少步数（如 10~20 步 Euler 积分）即可精准收敛。


* **追问 2：Flow-based 模型在语音合成中的主要瓶颈是什么？**
* *答*：对于传统 Flow（如 WaveGlow），瓶颈在于**维度守恒与严格可逆约束**，导致模型网络设计受限、参数量极其庞大且内存开销高；而对于现代 Flow Matching，虽然消除了可逆约束，但在零样本 (Zero-shot) 语音生成中，对**文本-语音对齐条件与长文本上下文依赖**的建模依然是训练的关键难点。

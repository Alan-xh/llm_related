# 命名实体识别 NER

## 似然与概率
在自然语言处理（NLP）中，**似然**（Likelihood）是一个非常核心的概念。简单来说，**似然衡量的是：在某个统计模型（参数）下，当前观测到的这组文本数据（语料）出现的“可能性”有多大。**

1. 核心定义（概率 vs. 似然）

这是最容易混淆的地方，但区分它们至关重要：

-   **概率（Probability）**：**参数已知**，问结果发生的概率。比如“已知一枚硬币是均匀的（参数p=0.5），抛10次出现6次正面的概率是多少？”
-   **似然（Likelihood）**：**结果已知**，问参数取什么值最合理。比如“我已经抛了10次，结果出现了6次正面，请问这枚硬币正面朝上的概率（参数p）是多少？”

在NLP中，**模型参数（权重）是未知的，而我们手里的文本数据（语料）是已知的**。**似然函数 $L(参数|数据)$** 就是用来回答：**“为了让眼前这堆句子看起来最合理，模型内部的参数应该设成什么值？”**

2. 似然在NLP中的数学体现

在语言模型中，我们通常假设一句话 $w_1, w_2, ..., w_n$ 出现的概率等于每个词在给定上文条件下出现的概率之积（链式法则）：
$P(w_1, w_2, ..., w_n) = \prod_{t=1}^{n} P(w_t | w_1, ..., w_{t-1})$

当我们把模型参数（比如神经网络中的权重 $\theta$）加进去时，这个概率就变成了**似然**：

$L(\theta) = \prod_{t=1}^{n} P_{\theta}(w_t | w_{t-1}, ..., w_1)$

这里的 $L(\theta)$ 就是似然。**训练模型的过程，本质上就是寻找一组参数 $\theta$，使得这个 $L(\theta)$ 的值达到最大**——这就是著名的**最大似然估计（MLE，Maximum Likelihood Estimation）**。

3. 为什么实际中我们总说“负对数似然”（NLL）？

如果你直接把上面那个连乘公式拿来计算，会遇到两个问题：

- 概率值都在0~1之间，连乘几十万个词会得到一个极其微小的浮点数，计算机下溢（变成0）。
- 连乘求导非常复杂。

所以，实际操作中，我们对似然取**对数**（单调函数，不影响最大值的位置），把连乘变成连加：

$\log L(\theta) = \sum_{t=1}^{n} \log P_{\theta}(w_t | \text{context})$
因为概率总是小于1，所以 $\log$ 值总是负数。为了符合我们“损失函数越小越好”的习惯，我们取负号：
$\text{NLL} = -\sum_{t=1}^{n} \log P_{\theta}(w_t | \text{context})$

这就是**负对数似然（Negative Log-Likelihood，NLL）**。
**结论：在NLP中，你每次训练模型时打印出的“Loss（损失值）”，本质上就是负对数似然。** 我们通过梯度下降最小化这个损失，等价于最大化原始数据的似然。

4. 具体场景中的例子

-   **语言模型（如GPT）**：给定上文“今天天气很”，模型预测“好”的概率高。模型训练的目标，就是让整个训练语料（数十亿句话）的似然值最大化。这等价于：让模型在看到真实的下一个词时，赋予它尽可能高的概率。
-   **机器翻译**：给定中文“我喜欢猫”，模型生成英文“I like cats”。这里的似然指的是，在给定中文输入和模型参数下，生成“I like cats”这串英文序列的概率。MLE训练的目标就是让正确译文的条件概率最大。
-   **词嵌入（Word2vec）**：Skip-gram模型的目标是，给定中心词“猫”，最大化其周围词（“喜欢”、“宠物”）出现的似然。

5. 似然的局限性（补充）

虽然MLE是NLP的奠基性方法，但它有一个著名的毛病：**偏爱“安全”但平庸的模型**。因为它只关注训练数据里的词，所以模型可能会倾向于给出非常确定的分布（过拟合），或者在训练数据稀疏时，给从未出现过的词组分配零概率（平滑技术就是为了解决这个）。

不过对于初学者，你只需要记住最核心的一句话：**在NLP中，似然就是模型给真实数据打出的“吻合度分数”，而模型训练的目标（MLE），就是不惜一切代价把这个分数拉到最高。**

在RLHF（基于人类反馈的强化学习）中不再沿用纯MLE，不是因为MLE“错了”，而是因为MLE的优化目标（模仿数据）与RLHF的终极目标（满足人类偏好）之间，存在三条不可调和的鸿沟。

## CRF 条件随机场
这是一个非常经典的问题。针对条件随机场（CRF，Conditional Random Field），通常所说的“损失函数”在深度学习时代特指**负对数似然损失（Negative Log-Likelihood Loss，NLL）**。

但在具体的代码实现（如PyTorch Lightning/TorchText）和数学推导中，它通常被写作 **“负对数似然 + 正则化”** 的形式。为了让你彻底搞懂，我把这个损失函数拆解为三个层面来讲解：

### 1. 核心公式（数学定义）

对于给定的输入序列 $x$ 和对应的真实标签序列 $y$，CRF的损失函数定义为：

\mathcal{L}(\theta) = -\log P(y|x)

展开这个条件概率（利用CRF的全局归一化特性），得到：

$\mathcal{L} = -\left( \text{Score}(x, y) - \log \sum_{y' \in Y(x)} e^{\text{Score}(x, y')} \right)$

其中：

- **$\text{Score}(x, y)$**：真实标签序列的路径得分（包含发射分数 + 转移分数）。
- **$\sum_{y' \in Y(x)} e^{\text{Score}(x, y')}$**：所有可能标签序列的得分之和（配分函数，Partition Function）。

**直观理解**：这个损失函数的目标是**最大化真实路径的得分**，同时**最小化所有其他错误路径的得分**。损失越小，真实路径的概率 $P(y|x)$ 就越大。

---

### 2. 拆解为三项（代码实现视角）

在底层实现（如`torchcrf`或`pytorch_lightning`）中，这个损失函数实际上被拆解为三项计算：

$\mathcal{L} = -(\text{Emissions} + \text{Transitions}) + \text{LogSumExp}$

具体为：

1. **发射分数（Emissions）**：来自上游神经网络（如BiLSTM或BERT）的输出，表示单词 $x_i$ 被标记为标签 $y_i$ 的置信度，求和得 $\sum_i E_{i, y_i}$。
2. **转移分数（Transitions）**：标签之间的状态转移矩阵得分，求和得 $\sum_i T_{y_{i-1}, y_i}$（包含起始和结束状态）。
3. **配分函数（LogSumExp）**：对所有潜在序列的指数得分取对数求和。这部分是计算瓶颈，通常通过**前向算法（Forward Algorithm）**动态规划实现。

所以，损失函数的计算流程是：
$\text{loss} = \text{forward\_score} - (\text{emit\_score} + \text{trans\_score})$
（注意：这里 forward_score 就是 $\log \sum e^{\text{score}}$，减去真实路径得分后取负，即得到NLL。）

---

### 3. 两个极易混淆的“变体”

根据你使用的框架不同，你可能会听到以下两种说法：

- **带 L2 正则化的损失（主流）**：在深度学习模型中，通常会在上述 NLL 损失基础上，加上网络参数（如权重矩阵）的 L2 范数作为正则项，防止过拟合。即：
  $  \mathcal{L}_{total} = -\log P(y|x) + \lambda \|\theta\|^2
  \]
  但在实际工程中，这个 L2 通常由优化器（如AdamW）的 weight_decay 参数处理，而**不写在 CRF 层内部**。

- **Viterbi 解码（推理时）**：很多人误以为 Viterbi 是损失函数，但其实**Viterbi 是解码算法**，用于在推理（预测）阶段寻找概率最高的标签序列，它不参与训练时的反向传播。

---

### 4. 关键注意事项（面试/调参高频点）

- **为什么不用交叉熵（CrossEntropyLoss）？** 因为交叉熵是对**每个位置独立**计算损失，而 CRF 的 NLL 考虑了**整个序列的全局依赖性**（通过转移矩阵），能够强制输出合理的标签转移规则（如“B”后不能接“I”）。
- **数值稳定性**：在计算 $\log \sum e^{x_i}$ 时，为了防止指数溢出，实际代码中会使用 **Log-Sum-Exp Trick**，即先减去最大值，再加回来。
- **损失值范围**：CRF 的损失通常是**正数**（因为概率小于1，取负对数后为正），且数值大小与序列长度成正比。在训练初期，损失值可能很大（几百甚至上千），随着训练收敛，损失会逐渐降低。

### 总结一句话
CRF的损失函数是**负对数似然（NLL）**，在数值上等于 **（所有路径的归一化得分）减去（真实路径的得分）**，它通过最大化真实标签序列的全局概率来优化模型参数。在写代码时，你只需要调用 `loss = -model(emissions, masks, tags)` 即可，底层的动态规划已完成。

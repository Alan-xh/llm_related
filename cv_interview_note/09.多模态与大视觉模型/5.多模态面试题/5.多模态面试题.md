# 多模态面试题

## 1.基础概念

### Q1：什么是多模态对齐（alignment）？

让不同模态（图 / 文 / 音）的表征在统一语义空间中匹配：
- 细粒度对齐：token 级（图像 patch 与词）；
- 实例级对齐：图文对级（CLIP 的对比学习）；
- 通常是预训练目标（ITC），是检索 / 零样本分类的基础。

### Q2：多模态融合方式有哪几种？

| 方式 | 做法 | 代表 |
| --- | --- | --- |
| Early fusion | 模态在输入 / 浅层即融合 | BLIP 的 cross-attention encoder |
| Late fusion | 各模态独立编码后再融合（点积 / 拼接） | CLIP 双塔 |
| Hybrid / 深度融合 | 编码后经融合模块交互 | Flamingo cross-attn、Q-Former |

### Q3：双塔和融合式（单塔）结构的取舍？

- 双塔：图文独立编码、可离线缓存、检索高效，交互浅；
- 融合式：cross-attention 深度交互、精度高，计算贵；
- 工业界检索用双塔召回 + 融合式精排的组合。

### Q4：常见的多模态任务有哪些？

- 理解：VQA、图像描述（captioning）、图文检索、指代分割（referring）；
- 生成：文生图、文生视频、看图对话；
- 定位：visual grounding、开放词汇检测 / 分割；
- 统一：多模态大模型（GPT-4V 式）指令对话。

### Q5：什么是零样本（zero-shot）与开放词汇（open-vocabulary）？

- 零样本：推理时直接处理训练未见类别，无需新样本（CLIP 用 prompt 分类）；
- 开放词汇：类别集合不固定，由文本动态定义（检测 / 分割里替代固定分类头）；
- 二者都依赖视觉-文本对齐空间。

### Q6：多模态预训练的三大经典目标？

1. **ITC**（对比）：图文对正负学习对齐；
2. **ITM**（匹配）：二分类判断图文是否匹配；
3. **MLM / LM**（生成）：掩码重建或自回归生成文本。

## 2.CLIP

### Q7：CLIP 的架构与训练目标？

- 双塔：ViT / ResNet 图像编码器 + GPT-2 式文本编码器；
- 对称 InfoNCE：batch 内配对图文为正样本，其余为负；
- 4 亿图文对（WIT）训练。

### Q8：CLIP 怎么做零样本分类？

类别拼 prompt（"a photo of a {c}"）-> 文本编码器离线编码 -> 图像特征与各类别算余弦相似度 -> softmax 取最大；多模板 ensemble 提点。

### Q9：温度参数 τ 的作用？

- 缩放 logits 控制 softmax 锐度；
- τ 小关注难负样本，训练中可学习并自动降到约 0.01。

### Q10：CLIP 的局限性？

细粒度分类弱、组合推理（计数 / 空间关系 / 属性绑定）弱、OCR 弱、分布外领域掉点严重、对 prompt 敏感、双塔交互浅不适合 VQA。

### Q11：SigLIP 的改进？

- sigmoid 损失替代 softmax：逐图文对独立二分类；
- 不依赖 batch 内负样本，中小 batch 训练更快更好；
- 已成为现代 MLLM 视觉端常用选择。

### Q12：CLIP 与 ALIGN 的区别？

思路相同（噪声大规模图文对对比学习）；ALIGN 用 18 亿对 Google 内部数据、双编码器 + gelu 投影；CLIP 系统研究了零样本迁移与 scaling，影响力更大。

### Q13：为什么 CLIP 检索要先离线编码文本？

双塔结构图文独立，类别 / 库内文本特征只需计算一次并缓存，线上只算图像特征 + 点积，代价极低。

## 3.BLIP / Q-Former

### Q14：BLIP 的两个贡献？

1. MED 架构：单模型统一理解（ITC/ITM）与生成（LM）；
2. CapFilt：captioner 生成伪标题 + filter 过滤噪声，自举清洗数据。

### Q15：BLIP-2 为什么冻结两个 backbone？

- 单模态模型已足够强，端到端训练大 VLM 算力不可承受；
- 冻结避免灾难性遗忘与训练不稳定；
- 只训 188M 的 Q-Former，成本降两个数量级。

### Q16：Q-Former 的结构与作用？

- BERT 式结构 + 32 个可学习 query，cross-attention 读取视觉特征；
- 输出定长 32×768；
- 作用：信息瓶颈（压缩数百视觉 token）+ 给 LLM 的定长 soft prompt 接口。

### Q17：BLIP-2 两阶段训练是什么？

- 阶段一：冻结视觉端，ITC / ITM / ITG 三目标训练 Q-Former；
- 阶段二：冻结 LLM，Q-Former 输出投影成前缀 soft prompt（OPT）或与指令拼接（FlanT5），用 LM 损失对齐。

### Q18：三个目标如何共享一个 Q-Former 而不互相泄漏？

通过不同的 self / cross-attention mask 控制信息流：ITC 图文独立、ITM query 可见两者、ITG 用 causal mask 保证自回归。

### Q19：Q-Former 和 MLP projector 怎么选？

- 冻结 LLM / 需要 token 压缩：Q-Former 合适；
- LLM 可训（指令微调）：简单 MLP 已足够，且保留全部视觉 token，细粒度任务更好（LLaVA-1.5 验证）。

## 4.LLaVA / MLLM

### Q20：LLaVA 的架构与两阶段训练？

- CLIP ViT-L（冻结）+ MLP projector + Vicuna；
- 阶段一：595k caption 只训 projector 做特征对齐；
- 阶段二：158k GPT-4 指令数据，端到端（projector + LLM LoRA）指令微调。

### Q21：多模态指令数据怎么构造？

1. 强 LLM 合成（GPT-4 + 图像标注文本 -> 对话 / 描述 / 推理）；
2. 学术 VQA / OCR 数据格式化为指令；
3. GPT-4V 直接看图合成；
4. 人工校验 / 标注补充；
5. 负样本数据抑制幻觉。

### Q22：LLaVA-1.5 的关键改进？

1. Linear -> 两层 GELU MLP；
2. 224px -> 336px；
3. 混入学术短答案数据；
4. 负样本抗幻觉数据。

### Q23：AnyRes 高分辨率策略是什么？

大图切成多个 336px 网格块 + 全局缩略图，分别过 CLIP 后拼接全部 token 给 LLM；解决固定分辨率限制，OCR / 文档任务大涨。

### Q24：什么是多模态幻觉（hallucination）？怎么缓解？

- 模型描述图中不存在的物体 / 属性；
- 缓解：负样本指令数据、POPE 类评测训练、RLHF / 偏好优化（RLHF-V、LLaVA-RLHF）、视觉对比解码（VCD）、操作反馈（闭环验证）。

### Q25：MLLM 视觉编码器为什么常用 CLIP 而不是 MAE？

- CLIP 特征与语言语义对齐，天然适配投影到 LLM 词空间；
- MAE 特征偏底层、需要微调释放；CLIP 冻结即可用；
- 新趋势：DINOv2 / SigLIP 组合（如 Cambrian-1）兼顾密集特征与语义对齐。

### Q26：GPT-4V、Gemini 与开源 MLLM 的主要差距？

- 训练数据规模 / 质量、高分辨率与长上下文能力、多图与视频理解；
- 开源模型（LLaVA-OV、Qwen-VL、InternVL）在基准上已接近，长尾指令与幻觉控制仍有差距。

## 5.自监督视觉（DINO / DINOv2）

### Q27：DINO 的自蒸馏如何防坍缩？

- Centering：教师输出减批均值，防某原型独大；
- Sharpening：教师低温输出尖锐分布；
- 二者互补，缺一即坍缩。

### Q28：DINO 的涌现性质？

自监督 ViT 的 [CLS] attention 自发关注主体物体、形似分割掩码；有监督训练无此现象。

### Q29：DINOv2 的三大损失？

1. DINO：[CLS] 自蒸馏 CE；
2. iBOT：被 mask patch 的 token 分布对齐（patch 级 MIM）；
3. KoLeo：拉大 batch 内最近邻距离，特征均匀化、各向同性。

### Q30：DINOv2 为什么冻结特征就很好，MAE 却要微调？

- DINO/iBOT 判别式目标 + patch 语义监督 -> 特征线性可分；
- MAE 重建像素偏低层信息，冻结线性探测弱、微调后上限高。

### Q31：LVD-142M 数据集的特点？

- 1.42 亿 curated 图像，无需标签；
- 自举管线：自监督 embedding -> 聚类 -> 去重 -> 采样；
- DINOv2 性能的第一功臣，证明数据管线比算法改动更重要。

### Q32：DINOv2 的典型应用？

- 冻结特征分类线性探测；
- 分割 / 深度估计（Depth Anything 的 backbone）；
- 图像检索、跨图特征匹配 / 3D 重建；
- MLLM 视觉端候选（密集特征强）。

## 6.训练与工程

### Q33：多模态预训练的数据从哪来？

- 网络爬取图文对（WIT、LAION、CC3M/12M）；
- 数据集配对（COCO、Visual Genome）；
- 合成数据（引擎渲染、GPT-4V 生成）；
- 需要清洗（CLIP score 过滤、去重、NSFW 过滤）。

### Q34：常用多模态评测基准？

| 基准 | 评什么 |
| --- | --- |
| MME | 感知 + 认知全维度，答案只判对错，抗猜测 |
| MMBench | 多选题，CircularEval 更严格 |
| MMBench-CN | 中文版 |
| MMMU | 大学水平多学科推理 |
| POPE | 物体幻觉（是 / 否问） |
| TextVQA / DocVQA | 图中文字 / 文档理解 |
| GQA / VQAv2 | 基础 VQA |
| LLaVA-Bench | GPT 打分的开放式对话 |

### Q35：MLLM 训练的常见工程问题？

1. 视觉 token 过长（AnyRes 下数千）-> token 压缩 / 池化；
2. 不同数据格式不统一 -> 统一对话模板；
3. 短答案与长对话风格冲突 -> 控制数据配比；
4. 显存：LoRA / 冻结视觉端、梯度检查点、DeepSpeed；
5. 评测不稳 -> 固定解码参数与 few-shot 设置。

### Q36：如何做图文检索系统？

1. 双塔（CLIP 系）离线编码全库文本 / 图像；
2. 向量库（FAISS / Milvus）建索引；
3. 查询侧编码 + ANN 召回；
4. 可加 cross-encoder 精排；
5. 关键：embedding 归一化、温度校准、增量更新。

### Q37：视觉 token 数与性能的权衡？

- token 多保留细节（OCR / grounding 好）但序列长、推理贵；
- 常用手段：平均池化下采样、query 压缩（Q-Former / Perceiver）、pixel shuffle 合并、高分辨率仅局部使用（AnyRes）。

### Q38：多模态模型怎么支持视频？

- 帧采样（均匀 / 关键帧）逐帧编码，加时序位置标识；
- 帧间 token 池化压缩（如 LLaVA-NeXT-Video 的 pooling 合并相邻帧）；
- 长视频需记忆机制 / 分段摘要（如 MovieChat、LongVLM）。

### Q39：微调 MLLM 时如何防止 LLM 语言能力退化？

- 用 LoRA / 部分参数微调而非全参；
- 指令数据中混入纯文本指令数据；
- 控制学习率与训练轮数；
- 保持冻结视觉端，先对齐再联合训练。

### Q40：多模态方向的发展趋势？

1. 统一模型：理解 + 生成（如 Chameleon、Emu）；
2. 高分辨率 / 长视频 / 多图输入；
3. 更强视觉端（DINOv2 + SigLIP 组合）；
4. 端侧小模型（MobileVLM、MiniCPM-V）；
5. 具身智能与 Agent（视觉 + 操作）；
6. 幻觉评测与对齐（POPE、RLHF）。

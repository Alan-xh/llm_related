# 5.锚框与NMS

## 1.概述

**Anchor（锚框）** 和 **NMS（Non-Maximum Suppression，非极大值抑制）** 是传统目标检测的两大核心机制。理解它们的设计原理、参数选择、改进方法，对学习检测算法至关重要。虽然 DETR 等方法已摆脱 anchor 和 NMS，但绝大多数生产检测器仍依赖它们。

## 2.Anchor（锚框）

### 2.1 什么是 Anchor？

**Anchor** 是预定义的一组**参考框**，覆盖不同尺度、长宽比。检测器在 anchor 基础上回归偏移，得到最终预测框：

$$
\text{box} = (x_a + \Delta x, y_a + \Delta y, w_a \cdot \exp(\Delta w), h_a \cdot \exp(\Delta h))
$$

### 2.2 为什么需要 Anchor？

- 直接回归框的绝对坐标 $(x, y, w, h)$ 难学（数值范围大、不稳定）；
- 基于 anchor 回归偏移 $\Delta$ 数值小、稳定；
- 不同尺度 anchor 覆盖不同大小目标；
- 让分类和回归解耦。

### 2.3 Anchor 设计

#### 2.3.1 尺度

- 通常 3~5 个尺度（如 32, 64, 128, 256, 512）；
- 覆盖小、中、大目标；
- 与 FPN 层对应（浅层小尺度，深层大尺度）。

#### 2.3.2 长宽比

- 通常 3 个长宽比（1:1, 1:2, 2:1 或 1:1, 1:3, 3:1）；
- 覆盖不同形状目标。

#### 2.3.3 数量

- 每位置 anchor 数 $k$ = 尺度数 × 长宽比数；
- SSD：6 个/位置；
- Faster R-CNN：9 个/位置（3×3）；
- 总 anchor 数：$H \times W \times k$，SSD ~8732 个。

### 2.4 Anchor 匹配（标签分配）

把 GT 分配给 anchor：

1. **IoU 阈值**：anchor 与 GT IoU > $T_{pos}$（如 0.7）为正样本，< $T_{neg}$（如 0.3）为负样本，中间忽略；
2. **Max IoU**：每个 GT 至少匹配 IoU 最大的 anchor（防漏检）；
3. **Top-k**：每 GT 取 IoU 最大的 k 个 anchor。

### 2.5 Anchor 的缺点

1. **超参多**：尺度、长宽比、IoU 阈值；
2. **数据集相关**：COCO 上设计的 anchor 不一定适合其他数据集；
3. **正负样本不平衡**：anchor 多，正样本少；
4. **冗余**：大量重叠 anchor，需 NMS。

### 2.6 Auto Anchor

- YOLOv5 用 k-means 在数据集上自动聚类 anchor；
- 自动适应数据集分布；
- 无需手动设计。

## 3.Anchor-Free 方法

### 3.1 动机

- Anchor 超参多、设计复杂；
- 不同数据集 anchor 需重新设计；
- 能否去掉 anchor？

### 3.2 主要方法

#### 3.2.1 CornerNet（2018）

- 预测目标的**左上**和**右下**两个角点；
- 角点 + embedding 匹配组成框；
- 无需 anchor。

#### 3.2.2 CenterNet（2019）

- 预测目标**中心点** + 尺寸；
- 详见 [2.单阶段检测](../2.单阶段检测/2.单阶段检测.md)。

#### 3.2.3 FCOS（2019）

- 每像素预测到框边的距离 (l, t, r, b)；
- Anchor-free + 全卷积。

#### 3.2.4 YOLOX / YOLOv8+

- 现代化 Anchor-free 设计；
- 每像素直接预测。

### 3.3 Anchor-free vs Anchor-based

| 维度 | Anchor-based | Anchor-free |
| --- | --- | --- |
| 超参 | 多 | 少 |
| 设计 | 复杂 | 简单 |
| 精度 | 略高 | 略低（已追平） |
| 速度 | 中 | 略快 |
| 数据集相关 | 强 | 弱 |
| 适合 | 经典检测器 | 现代 YOLO |

## 4.NMS（非极大值抑制）

### 4.1 原理

检测器输出大量重叠框，NMS 去除冗余：

1. 按置信度从高到低排序；
2. 取最高分框，加入结果；
3. 删除与该框 IoU > 阈值的其他框；
4. 重复 2-3 直到所有框处理完。

```
输入: 框列表 [(score, bbox), ...]

1. 排序: 按 score 降序
2. while 列表非空:
     b = 列表[0]  # 最高分
     加入结果
     列表中 IoU(b, 其他) > 阈值 的全部删除
3. 返回结果
```

### 4.2 IoU 阈值

- 通常 **0.5**（COCO 评估也用 0.5）；
- 阈值小：抑制强，可能漏检密集目标；
- 阈值大：抑制弱，可能保留冗余框；
- 不同任务调不同值。

### 4.3 NMS 的问题

1. **顺序操作**：无法并行加速；
2. **超参依赖**：IoU 阈值需手动调；
3. **密集场景差**：相邻目标可能被误抑制；
4. **不是端到端**：增加推理延迟。

### 4.4 Soft-NMS（2017）

**思想**：不直接删除重叠框，而是**降低其置信度**：

$$
s_i = \begin{cases}
s_i, & \text{IoU} < \tau \\
s_i (1 - \text{IoU}), & \text{otherwise}
\end{cases}
$$

或高斯加权：

$$
s_i = s_i \exp(-\text{IoU}^2 / \sigma)
$$

**优点**：密集场景效果好；
**缺点**：仍是顺序操作。

### 4.5 DIoU-NMS（2020）

**思想**：在 NMS 中用 **DIoU**（考虑中心距离）替代 IoU：

$$
\text{DIoU} = \text{IoU} - \frac{\rho^2(b, b_{gt})}{c^2}
$$

- 同时考虑重叠度和中心距离；
- 对密集场景更友好。

### 4.6 Cluster-NMS

**思想**：批量抑制，一次处理多个高分框，**可并行**：

1. 一次矩阵运算计算所有框对 IoU；
2. 同时抑制所有重叠框；
3. 速度比标准 NMS 快。

### 4.7 Learnable NMS / NMS-free

- **Learnable NMS**：用小网络学习 NMS；
- **NMS-free（DETR 系列）**：通过匈牙利匹配避免重复预测，**完全无需 NMS**；
- YOLOv10 通过一致性双分配实现 NMS-free。

## 5.其他后处理

### 5.1 Test-Time Augmentation（TTA）

推理时做多个增强（翻转、多尺度），分别预测后融合：

- 多尺度：把同一目标在不同尺度预测融合；
- 翻转：水平翻转预测后映射回原图；
- 通常提升 1~2%。

### 5.2 Box Voting / WBF

**Box Voting**：高分框的 IoU 重叠区域加权平均；
**Weighted Box Fusion（WBF）**：多个模型预测的框加权融合，比 NMS 更适合 ensemble。

### 5.3 后处理加速

- 跳过低分框（score < threshold）；
- 限制最多 N 个框；
- 并行 NMS（GPU）。

## 6.面试常考问题

**Q1：Anchor 是什么？为什么需要？**

预定义的参考框，覆盖不同尺度、长宽比。基于 anchor 回归偏移比直接回归绝对坐标稳定。让分类和回归解耦。

**Q2：Anchor 怎么设计？**

- 尺度：3~5 个（32~512），覆盖小到大目标；
- 长宽比：1:1, 1:2, 2:1 等；
- 与 FPN 层对应；
- 可用 k-means 自动聚类（YOLOv5 AutoAnchor）。

**Q3：Anchor-based 和 Anchor-free 的区别？**

| 维度 | Anchor-based | Anchor-free |
| --- | --- | --- |
| 超参 | 多 | 少 |
| 设计 | 复杂 | 简单 |
| 精度 | 略高 | 已追平 |
| 速度 | 中 | 略快 |
| 代表 | Faster R-CNN, YOLOv3 | FCOS, CenterNet, YOLOv8 |

**Q4：NMS 的原理？**

1. 按置信度排序；
2. 取最高分框加入结果；
3. 删除与该框 IoU > 阈值的其他框；
4. 重复直到处理完。

**Q5：NMS 的 IoU 阈值怎么选？**

- 通常 0.5；
- 阈值小：抑制强，可能漏检密集目标；
- 阈值大：抑制弱，可能保留冗余；
- 不同任务调不同值。

**Q6：Soft-NMS 解决什么问题？**

- 标准 NMS 直接删除重叠框，密集场景误删；
- Soft-NMS 降低重叠框置信度，不直接删；
- 密集场景效果好。

**Q7：DIoU-NMS 的改进？**

- 用 DIoU（考虑中心距离）替代 IoU；
- 同时考虑重叠和中心位置；
- 对密集场景更友好。

**Q8：NMS 的问题？**

1. 顺序操作，无法并行；
2. 超参依赖；
3. 密集场景差；
4. 增加推理延迟；
5. 不是端到端。

**Q9：DETR 为什么无 NMS？**

- 匈牙利匹配保证每个 GT 只被一个 query 学；
- query 之间不重复预测同一目标；
- 无需 NMS 去冗余。

**Q10：YOLOv10 怎么实现 NMS-free？**

- 一致性双分配：
  - 训练时一对多（学得多）；
  - 推理时一对一（无 NMS）；
- 通过一致性损失让一对多结果匹配一对一。

**Q11：标签分配是什么？**

把 GT 分配给 anchor/query 的过程：

1. IoU 阈值法（Faster R-CNN）；
2. Max IoU（每 GT 至少匹配一个）；
3. Top-k（每 GT 取 IoU 最大的 k 个）；
4. OTA/SimOTA（最优传输）；
5. TaskAlignedAssigner（YOLOv8）。

**Q12：Anchor 数量对性能的影响？**

- 太少：召回低，漏检；
- 太多：正负样本不平衡，训练慢；
- 折中：Faster R-CNN 9/位置，SSD 6/位置，DETR 100 query 总数。

## 7.总结

- **Anchor** 是预定义参考框，基于它回归偏移更稳定；
- **Anchor-free** 简化设计，是现代 YOLO 趋势；
- **NMS** 去除冗余框，IoU 阈值通常 0.5；
- **Soft-NMS / DIoU-NMS / Cluster-NMS** 是 NMS 改进；
- **DETR / YOLOv10** 实现 NMS-free，端到端检测；
- **标签分配**（IoU、Top-k、OTA）决定正负样本；
- Anchor 和 NMS 是传统检测的核心，DETR 时代正在抛弃它们。

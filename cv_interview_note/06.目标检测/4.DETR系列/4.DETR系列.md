# 4.DETR系列

## 1.概述

**DETR（Detection Transformer）** 由 Facebook 在 2020 年提出，**首次将 Transformer 端到端应用于目标检测**，**完全摒弃 anchor 和 NMS**，开辟了检测领域的第三条路。DETR 之后，Deformable DETR、DINO、RT-DETR 等改进版本持续刷新 SOTA，成为检测领域的新主流。

## 2.DETR 原版（2020）

**论文**：End-to-End Object Detection with Transformers (Carion et al., Facebook)

### 2.1 核心思想

- 把检测视为**集合预测问题**（set prediction）；
- 用 **Transformer Encoder-Decoder** 直接预测 N 个框（N=100）；
- **匈牙利匹配**做标签分配；
- **无 anchor、无 NMS**。

### 2.2 架构

```
Image -> CNN Backbone (ResNet-50) -> Feature Map (H/32 × W/32 × C)
                                          │
                                          ▼
                                  Transformer Encoder
                                          │
                                          ▼
                                  Transformer Decoder
                                  (输入: N 个 object queries)
                                          │
                                          ▼
                              N 个 (class + bbox)
```

### 2.3 Object Queries

- N 个可学习的 embedding（N=100）；
- 作为 Decoder 的输入 query；
- 每个 query 学到一个"位置 + 内容"的模式；
- 输出 N 个预测。

### 2.4 匈牙利匹配（Hungarian Matching）

**问题**：N=100 个预测，GT 可能只有 K 个（K < N），如何分配？

**方案**：

1. 计算所有预测-GT 对的匹配成本：

$$
C_{ij} = -\hat{p}_j(c_i) + \mathbb{1}_{c_i \neq \emptyset} L_{bbox}(b_j, b_i)
$$

2. 用**匈牙利算法**找最优一对一匹配；
3. 损失只计算匹配上的对；
4. 未匹配预测的类被设为"无目标"（$\emptyset$）。

### 2.5 损失函数

$$
L = \lambda_{cls} L_{cls} + \lambda_{bbox} L_{bbox} + \lambda_{giou} L_{giou}
$$

- $L_{cls}$：CE（含"无目标"类）；
- $L_{bbox}$：L1 损失；
- $L_{giou}$：GIoU 损失。

### 2.6 优点

1. **无 anchor、无 NMS**：真正端到端；
2. **架构简洁**：CNN + Transformer；
3. **可扩展**：易扩展到分割、姿态等任务；
4. **大目标精度高**：全局注意力。

### 2.7 缺点

1. **训练慢**：需要 500 epochs 才能收敛（vs Faster R-CNN ~12 epochs）；
2. **小目标精度低**：高分辨率 feature map 计算量大，DETR 用 stride=32，分辨率低；
3. **Query 难学**：N 个 query 学到"位置"的过程慢。

## 3.Deformable DETR（2021）

**论文**：Deformable DETR: Deformable Transformers for End-to-End Object Detection (Zhu et al., 商汤)

### 3.1 核心改进

1. **可变形注意力**：每 query 只关注少量采样点（4 个），而非所有位置；
2. **多尺度 feature**：用 ResNet 的 4 个 stage 特征（C3-C5）；
3. **迭代框精修**：每个 decoder 层基于前层预测精修框；
4. **Two-stage**：先粗筛 query，再精修。

### 3.2 可变形注意力

$$
\text{DeformAttn}(q, p) = \sum_{m=1}^{M} W_m \sum_{k=1}^{K} A_{mk} \cdot x(p + \Delta p_{mk})
$$

- $M$ 个 head，每 head $K=4$ 个采样点；
- $\Delta p_{mk}$：可学习偏移；
- $A_{mk}$：可学习注意力权重；
- 复杂度 $O(MK)$，与序列长度无关。

### 3.3 优点

1. **训练快**：50 epochs 即可收敛（vs DETR 500）；
2. **小目标精度提升**：多尺度 + 高分辨率特征；
3. **内存占用低**：稀疏采样；
4. 性能超越 DETR。

## 4.DAB-DETR（2022）

**论文**：DAB-DETR: Dynamic Anchor Box Learning for Object Detection

**核心改进**：把 **query 显式解耦为 anchor box（位置 + 尺寸）+ 内容**：

- 4D 位置 + 尺寸作为 query；
- 在 decoder 中**动态更新** anchor box；
- 让 query 学得更快、更准。

## 5.DN-DETR（2022）

**论文**：DN-DETR: Accelerate DETR Training by Denoising

**核心思想**：**去噪训练**：

- 给 GT 加噪声作为"噪声 query"；
- 让模型学去噪（还原 GT）；
- 与匈牙利匹配主任务联合训练；
- 让 query 学得更稳、更快。

## 6.DINO（2022）

**论文**：DINO: DETR with Improved Denoising Anchor Boxes for Open-Vocabulary Object Detection (Zhang et al., IDEA)

**核心改进**：

1. **对比去噪（CDN）**：正负样本对比，更稳；
2. **Mixed Query Selection**：混合 query 选择；
3. **Look Forward Twice**：精修时看两层；
4. 性能 SOTA：COCO mAP 63.3%（vs DETR 42.0）。

## 7.RT-DETR（2023）

**论文**：Real-Time DETR: Real-Time Detection Transformer (百度)

### 7.1 核心目标

- DETR 之前慢于 CNN 检测器；
- RT-DETR 让 DETR 实时化。

### 7.2 改进

1. **高效混合 encoder**：解耦 intra-scale 和 cross-scale 特征融合；
2. **不确定性最小化 query 选择**：减少 query 数量（如 100 -> 30）；
3. **IoU-aware query selection**；
4. 在 COCO 上达到 108 FPS，性能优于 YOLOv8。

### 7.3 性能

- RT-DETR-R50：108 FPS，COCO mAP 53.0；
- RT-DETR-R101：74 FPS，COCO mAP 54.0；
- 首次 DETR 在速度上比肩 YOLO。

## 8.DETR 系列对比

| 模型 | 年份 | 收敛 epochs | mAP | 速度 | 特点 |
| --- | --- | --- | --- | --- | --- |
| DETR | 2020 | 500 | 42.0 | 慢 | 开创端到端 |
| Deformable DETR | 2021 | 50 | 49.0 | 中 | 可变形注意力 |
| DAB-DETR | 2022 | 50 | 51.0 | 中 | 显式 anchor |
| DN-DETR | 2022 | 12 | 49.8 | 中 | 去噪训练 |
| DINO | 2022 | 12 | 63.3 | 中 | CDN + 改进 |
| RT-DETR | 2023 | - | 54.0 | 快（108 FPS） | 实时 DETR |

## 9.DETR 的优势与挑战

### 9.1 优势

1. **端到端**：无 anchor、无 NMS；
2. **架构简洁**：易扩展；
3. **全局推理**：适合复杂场景；
4. **大目标强**：全局注意力；
5. **可扩展性好**：open-vocab、跨模态等。

### 9.2 挑战

1. **训练慢**（DETR 500 epochs，改进后 12~50）；
2. **小目标弱**（高分辨率 feature map 计算大）；
3. **推理速度**：原始 DETR 慢于 CNN（RT-DETR 已解决）；
4. **query 设计**：如何让 query 学到位置 + 内容。

## 10.DETR 应用到其他任务

### 10.1 实例分割

- **Mask2Former**：DETR + Mask 分类，统一实例/语义/全景分割；
- **Mask DINO**：DINO 改进的分割版本。

### 10.2 姿态估计

- **ED-Pose**：DETR 用于姿态估计；
- **Group DETR**：分组 query 用于多人姿态。

### 10.3 3D 检测

- **DETR3D**：3D 检测；
- **PETR / PETRv2**：3D PETR；
- **StreamPETR**：时序 3D 检测。

### 10.4 视频

- **VisTR**：视频实例分割；
- **VIDTR**：视频检测。

## 11.面试常考问题

**Q1：DETR 的核心创新？**

1. 检测视为集合预测；
2. Transformer Encoder-Decoder；
3. 匈牙利匹配做标签分配；
4. 无 anchor、无 NMS。

**Q2：DETR 为什么需要匈牙利匹配？**

- N 个预测 vs K 个 GT（K < N）；
- 一对一匹配保证每个 GT 只被一个 query 学；
- 避免重复预测；
- 不需 NMS。

**Q3：DETR 训练为什么这么慢？**

- query 需要从随机初始化学到"位置 + 内容"模式；
- 匈牙利匹配初期不稳定；
- 全局注意力收敛慢。

**Q4：Deformable DETR 解决什么问题？**

- 全局注意力计算量大，无法用高分辨率；
- 可变形注意力：每 query 只关注 4 个采样点；
- 支持多尺度 + 高分辨率；
- 训练快 10 倍。

**Q5：DN-DETR 的去噪训练？**

- 给 GT 加噪声作为"噪声 query"；
- 让模型学去噪（还原 GT）；
- 与主任务联合训练；
- 让 query 学得更稳。

**Q6：DINO 相比 DN-DETR 的改进？**

1. 对比去噪（CDN）：正负样本对比；
2. Mixed Query Selection；
3. Look Forward Twice；
4. 性能 SOTA。

**Q7：RT-DETR 怎么实现实时？**

1. 高效混合 encoder；
2. 不确定性最小化 query 选择（减少 query 数）；
3. IoU-aware query selection；
4. 首次 DETR 速度比肩 YOLO。

**Q8：DETR 为什么无 NMS？**

- 匈牙利匹配保证每个 GT 只被一个 query 学；
- query 之间不会重复预测同一目标；
- 无需 NMS 去冗余。

**Q9：DETR 在小目标上为什么弱？**

- stride=32 feature map 分辨率低（224 输入 -> 7×7）；
- 小目标在低分辨率下信息丢失；
- Deformable DETR 用多尺度 + 高分辨率解决。

**Q10：Object Query 是什么？**

- N 个可学习 embedding（N=100）；
- 作为 decoder 的输入 query；
- 学到"位置 + 内容"的模式；
- 输出 N 个预测。

## 12.总结

- **DETR** 开创端到端 Transformer 检测，无 anchor、无 NMS；
- **Deformable DETR** 可变形注意力 + 多尺度，训练快 10 倍；
- **DAB-DETR** 显式 anchor box query；
- **DN-DETR** 去噪训练，加速收敛；
- **DINO** CDN + 多改进，SOTA；
- **RT-DETR** 实时 DETR，比肩 YOLO；
- DETR 系列正在取代传统 CNN 检测器，成为检测新主流。

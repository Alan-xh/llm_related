# 评估部署面试题

## 1.评估指标

### Q1：Precision 和 Recall 的定义及权衡？

- P = TP/(TP+FP)，查准，关注误检；
- R = TP/(TP+FN)，查全，关注漏检；
- 调阈值权衡，或用 F1 / F-beta 按业务代价加权。

### Q2：为什么类别不平衡时 Accuracy 会失效？

- 全预测多数类即可得到高 Accuracy；
- 例：1% 正样本全预测负，Accuracy 99% 但 Recall 0；
- 应改用 F1、PR-AUC、macro 平均。

### Q3：AUC 的物理含义？

- 随机取一正一负样本，正样本得分更高的概率；
- 阈值无关，衡量排序能力；
- 0.5 等价于随机猜。

### Q4：ROC-AUC 与 PR-AUC 如何选择？

| 场景 | 推荐 |
| --- | --- |
| 正样本稀少（检测、风控） | PR-AUC |
| 类别均衡、看整体排序 | ROC-AUC |

- ROC 的 FPR 在负样本巨大时增长慢，容易高估模型。

### Q5：macro-F1 与 micro-F1？

- macro：每类 F1 平均，小类等权，关注小类时用；
- micro：全部 TP/FP 汇总后算，大类主导；
- weighted：按样本数加权。

### Q6：mAP@0.5 与 mAP@0.5:0.95 的区别？

- 0.5：单阈值，定位要求松（VOC 风格）；
- 0.5:0.95：10 个阈值平均，定位要求严（COCO 风格）；
- 后者通常显著低于前者，更能反映框质量。

### Q7：COCO 的 AP small/medium/large 怎么划分？

| 指标 | 面积 |
| --- | --- |
| AP-S | < 32² |
| AP-M | 32² ~ 96² |
| AP-L | > 96² |

- 小目标 AP 普遍低，需单独看分层指标。

### Q8：mAP 的计算流程？

1. 预测按置信度降序排序；
2. 逐个按 IoU 阈值判 TP/FP（每个 GT 只匹配一次）；
3. 累积画 PR 曲线求 AP；
4. 多类 AP 取平均得 mAP。

### Q9：NMS 阈值如何影响 mAP？

- 阈值低：密集目标框被误删 -> 漏检 -> mAP 降；
- 阈值高：冗余 FP 增多 -> mAP 降；
- 验证集上调优，常用 0.5 左右；Soft-NMS 密集场景更稳。

### Q10：mIoU、Dice、PQ 分别用于什么任务？

- mIoU：语义分割主指标（类平均 IoU）；
- Dice：医学分割常用，等价像素级 F1，对小目标敏感；
- PQ：全景分割（SQ × RQ，IoU>0.5 匹配）。

### Q11：生成模型常用指标？

| 指标 | 方向 | 衡量 |
| --- | --- | --- |
| FID | 低好 | 生成分布与真实分布距离（Inception 特征） |
| IS | 高好 | 清晰度 + 多样性（KL） |
| LPIPS | 低好 | 深度特征感知相似度 |
| CLIP Score | 高好 | 图文一致性 |

### Q12：上线检测模型只看 mAP 够吗？

- 不够：还需 FPS/延迟、固定阈值下的误检/漏检率、长尾类别、bad case、鲁棒性；
- mAP 是阈值无关的均值，线上是固定阈值工作点。

## 2.模型压缩

### Q13：模型压缩的主要方法？

- 剪枝（去冗余）、量化（低精度）、知识蒸馏（大教小）、紧凑网络设计；
- 可叠加：轻量 backbone + 蒸馏 + INT8 量化是常见组合。

### Q14：结构化与非结构化剪枝？

| 维度 | 非结构化 | 结构化 |
| --- | --- | --- |
| 剪什么 | 单权重 | 整通道/滤波器 |
| 加速 | 需稀疏硬件 | 通用硬件直接加速 |
| 精度（同压缩率） | 损失小 | 损失大 |
| 工业 | 研究为主 | 主流 |

### Q15：幅度剪枝流程？为什么要迭代？

- 训练收敛 -> 按 L1/L2/BN-γ/Taylor 准则排序 -> 剪最不重要的 -> 微调恢复；
- 一次剪太狠精度崩且难恢复，分多轮小步剪 + 微调。

### Q16：PTQ 与 QAT 的选择？

- PTQ：免训练、少量校准数据、分钟级，INT8 常损失 <1%，先试；
- QAT：伪量化节点 + STE 训练，精度更好，低比特（INT4）必用；
- 路径：PTQ 掉点超预期再上 QAT。

### Q17：写对称与非对称量化公式？

- 对称：q = round(x/s)，z=0，适合权重；
- 非对称：q = round(x/s)+z，s=(xmax-xmin)/(qmax-qmin)，适合激活（ReLU 非负）；
- 反量化 x̂ = s(q-z)，误差上界 s/2。

### Q18：为什么权重用 per-channel 量化？

- 各通道权重分布差异大，per-tensor 一组 scale 会牺牲部分通道精度；
- per-channel scale 离线固定，几乎无推理开销；
- 激活通常只能 per-tensor。

### Q19：QAT 中的 STE？

- round 不可导，反向时梯度直通（视导数为 1）；
- 截断范围外梯度为 0；
- 让训练感知量化误差，权重落在量化网格附近。

### Q20：知识蒸馏的温度 T 作用？

- T>1 软化分布，放大类间相似信息（dark knowledge）；
- 太小近似 one-hot，太平滑失去判别性；
- 常用 T=3~10，loss 乘 T² 对齐梯度。

### Q21：logit 蒸馏与特征蒸馏？

- logit：对齐最终输出，简单通用，信息有限；
- 特征：对齐中间表示（加适配层），信息更丰富；
- 检测/分割等密集任务特征蒸馏收益大（如 FGIR 只在目标区域模仿）。

### Q22：蒸馏什么时候失效？

- student 容量不足装不下知识；
- teacher/student 结构差异过大难以对齐；
- 蒸馏数据与 teacher 训练分布不一致；
- teacher 本身不够强。

### Q23：FLOPs 降 4 倍为什么实际只快 2 倍？

- 延迟 = 计算 + 访存 + 启动开销；
- 通道剪枝可能恶化计算/访存比（算术强度下降）；
- 框架实现与调度也是瓶颈；
- 以目标硬件实测为准。

## 3.推理优化与性能

### Q24：延迟与吞吐的区别及优化手段？

- 延迟：单请求耗时；吞吐：单位时间请求量；
- 降延迟：融合、低精度、小 batch、减 launch；
- 提吞吐：dynamic batching、多 stream、预处理流水线；
- 二者需权衡。

### Q25：roofline 模型？

- 横轴算术强度（FLOP/Byte），纵轴可达性能；
- 拐点 = 峰值算力 / 带宽；
- 低于拐点访存受限（优化融合/布局），高于拐点计算受限（优化低精度/算法）。

### Q26：推理时 BN 为什么能融合进卷积？

- 推理时 BN 是常数仿射变换；
- 缩放折叠进 W、偏移进 b，数学等价、零损失；
- 少一次访存和一个 kernel。

### Q27：算子融合为什么有效？

- 减少中间结果读写（访存受限算子收益最大）；
- 减少 kernel launch 开销；
- 典型：Conv+BN+ReLU、Add+ReLU。

### Q28：NHWC 与 NCHW 如何选？

- NHWC 空间连续，SIMD 与 INT8 打包友好，GPU/ARM 常更快；
- NCHW 逐通道自然；
- 布局转换有成本，交由引擎做全局布局传播。

### Q29：CUDA stream 的作用？

- stream 内串行、stream 间并行；
- 多路视频并发推理、计算与拷贝重叠；
- GPU 已饱和时无收益。

### Q30：dynamic batching 原理与代价？

- 时间窗内攒请求成大 batch，摊薄权重加载提吞吐；
- 代价：排队延迟；
- 需设 max queue delay 上限。

### Q31：模型慢如何系统排查？

1. nsys 看时间线：CPU 忙 / GPU 忙 / 相互等待？
2. ncu 看慢 kernel：带宽利用率、occupancy；
3. 访存受限 -> 融合、布局、量化；
4. 计算受限 -> 低精度、Winograd；
5. CPU 受限 -> 减 launch、预处理下沉；
6. 都闲 -> 数据加载/调度问题。

### Q32：cudnn.benchmark=True 的适用条件？

- 输入尺寸固定时开启，自动搜索最优卷积算法并复用；
- 尺寸多变时每次重搜反而慢，应关闭。

## 4.部署框架与工程实践

### Q33：描述完整部署链路？

```
PyTorch -> ONNX(opset/动态shape) -> TensorRT engine / NCNN
        -> 集成前后处理 -> Triton/服务 -> 监控
```

### Q34：ONNX 的 opset 是什么？

- 算子集版本，决定可用算子与语义；
- 太低缺算子、太高老引擎不支持；
- 按目标引擎要求选（常见 11~17）。

### Q35：TensorRT engine 为什么要目标机上编译？

- 编译期做 kernel 调优、内存规划，绑定 GPU 型号与 TRT 版本；
- 换卡换版本需重编；
- timing cache 可加速重复编译。

### Q36：遇到不支持的算子怎么办？

- 升级 opset / 引擎版本；
- 改写为等价基础算子；
- 写 plugin（TRT）/ 自定义层（NCNN）；
- 子图 fallback 到 onnxruntime。

### Q37：FP16 部署精度下降怎么处理？

- 先确认 FP32 已与 PyTorch 对齐（排除预处理）；
- 逐层对比找敏感层；
- 敏感层回退 FP32（混合精度）；
- FP16 相对误差 1e-3 量级正常。

### Q38：部署后精度严重不符，排查清单？

- 预处理：BGR/RGB、mean/std、插值方式、padding；
- 后处理：坐标解码、NMS 实现；
- 导出：是否 eval 模式、opset 语义、自定义算子；
- 精度模式：FP16/INT8 敏感层；
- 输入：shape/dtype。

### Q39：如何验证 ONNX 导出正确？

- 同输入对比 PyTorch 与 onnxruntime 输出（allclose 容差 1e-4~1e-5）；
- onnx.checker 检查；Netron 可视化核对。

### Q40：动态 shape 与静态 shape 的取舍？

- 静态最快（充分优化），尺寸固定时首选；
- 动态灵活但慢，需 min/opt/max profile；
- 折中：按档位编译多个 engine。

### Q41：NCNN/MNN/TFLite 怎么选？

- NCNN：无依赖、ARM 深度优化，手机 CPU 主流；
- MNN：移动 + IoT，支持 NPU；
- TFLite：Android/TF 生态、NNAPI delegate。

### Q42：Triton 的价值？

- 统一管理多模型多框架（TRT/ONNX/PyTorch backend）；
- dynamic batching 提吞吐；
- ensemble/BLS 编排预处理-推理-后处理流水线；
- HTTP/gRPC + Prometheus 监控。

### Q43：onnxruntime 与 TensorRT 的关系？

- 各自独立引擎：ORT 跨平台易用，TRT 极致 NVIDIA 性能；
- ORT 可通过 TensorRT EP 内部调 TRT engine；
- 常见组合：外层 ORT API + 内层 TRT 加速。

### Q44：CV 部署与 LLM 部署的主要差异？

- CV：变分辨率/切图、预处理流水线、NMS 后处理、CN 侧图优化；
- LLM：自回归 + KV Cache（PagedAttention）、连续批处理、vLLM/TGI；
- 详见 [llm_interview_note/06.推理](../../../llm_interview_note/06.推理/)。

### Q45：一个模型要同时上 GPU 服务器和手机，怎么设计部署方案？

- 统一导出 ONNX 作为中间产物；
- GPU：TensorRT engine（FP16/INT8）+ Triton 服务化；
- 手机：NCNN/MNN INT8；
- 各端分别做精度对齐与延迟测试；
- 量化等压缩见 [2.模型压缩](../2.模型压缩/2.模型压缩.md)。

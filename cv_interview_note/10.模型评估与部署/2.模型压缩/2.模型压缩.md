# 2.模型压缩

## 1.概述

深度模型精度越来越高，但**参数量、计算量、内存占用**也随之膨胀，难以部署到移动端/边缘设备。**模型压缩**在尽量保精度的前提下降低模型开销，是工业落地的核心环节。

### 1.1 压缩四板斧

```
                模型压缩
       ┌──────────┬──────────┬──────────┐
     剪枝        量化       知识蒸馏    紧凑网络设计
  (去掉冗余)  (低精度表示)  (大模型教)   (结构设计)
```

- **剪枝**：删除冗余权重/通道；
- **量化**：FP32 -> INT8/INT4；
- **知识蒸馏**：大模型（teacher）指导小模型（student）；
- **紧凑网络**：从架构设计下手（见 [2.轻量化网络](../../02.CNN与经典架构/4.轻量化网络/4.轻量化网络.md)）；
- 四者可**叠加使用**：紧凑网络 + 蒸馏 + 量化是常见组合。

### 1.2 参数量与 FLOPs 计算

**卷积层**（输入 $C_{in}$，输出 $C_{out}$，核 $k \times k$）：

$$
Params = C_{out} \times (C_{in} \times k \times k + 1)
$$

$$
FLOPs = C_{out} \times H_{out} \times W_{out} \times C_{in} \times k \times k \times 2
$$

- 乘加各算一次所以 ×2（有的工具只算 MACs，不乘 2，注意口径）；
- **全连接层**：$Params = in \times out + out$；

```python
# 常用统计工具
# torchinfo: summary(model, input_size=(1, 3, 224, 224))
# thop:      from thop import profile; flops, params = profile(model, inputs)
# fvcore:    from fvcore.nn import FlopCountAnalysis
```

- **注意**：FLOPs 低 ≠ 速度快，实际延迟受**内存带宽、算子实现、硬件**影响（见 [3.推理优化](../3.推理优化/3.推理优化.md)）。

## 2.剪枝

### 2.1 非结构化 vs 结构化

| 维度 | 非结构化剪枝 | 结构化剪枝 |
| --- | --- | --- |
| 剪什么 | 单个权重置 0 | 整个通道/滤波器/层 |
| 压缩表现 | 稀疏矩阵，需专门存储 | 直接变小稠密模型 |
| 硬件加速 | 通用 GPU/ASIC 难加速 | 通用硬件直接加速 |
| 精度损失（同等压缩率） | 小 | 较大 |
| 工程实用性 | 低（研究为主） | 高（工业主流） |

- **结构化剪枝**（通道剪枝）是工业首选；
- 非结构化稀疏需要稀疏算子/专用硬件（如稀疏 tensor core）才有收益。

### 2.2 幅度剪枝流程

**基于权重大小**的最经典方法：

```
1. 训练完整模型至收敛
2. 按权重大小排序，剪掉最小的 p%（置 0 或删通道）
3. 微调恢复精度（finetune 若干 epoch）
4. 可重复 2-3（迭代剪枝）
```

**通道剪枝的常用准则**：

- 按 **BN 层 γ 系数**剪（学习到的缩放因子小 -> 通道不重要）；
- 按 L1/L2 范数：通道权重范数小 -> 不重要；
- 按**Taylor 展开**：一阶泰勒 $|\Delta L| \approx |\frac{\partial L}{\partial w} \cdot w|$；
- 按**重建误差**：剪后特征与原特征距离最小；
- 剪枝准则本质都在回答"**删掉谁损失最小**"。

### 2.3 迭代剪枝

- 一次剪太狠（如 50%）精度崩，无法恢复；
- **剪一点 -> 微调 -> 再剪**，逐步到位；
- 常见日程：每轮剪 10%~20%，直到目标压缩率；
- 经验：ImageNet 级 CNN 剪 30%~50% 通道，微调后精度损失可控制在 1% 内。

### 2.4 剪枝代码示意（按 BN-γ 剪通道）

```python
# 以 BN 的 gamma 范数为通道重要性
import torch.nn as nn

def prune_ratio(model, ratio=0.3):
    gammas = []
    for m in model.modules():
        if isinstance(m, nn.BatchNorm2d):
            gammas += m.weight.data.abs().tolist()
    gammas.sort()
    thresh = gammas[int(len(gammas) * ratio)]
    return thresh  # 小于该值的通道视为不重要，可加 mask 置 0
```

- 实现：剪枝后需要**物理删除通道并修剪相邻层**（卷积输出通道、BN、下一层输入通道），否则只是 mask 不加速。

## 3.量化

### 3.1 PTQ vs QAT

| 维度 | PTQ（训练后量化） | QAT（量化感知训练） |
| --- | --- | --- |
| 是否需要训练 | 不需要（少量校准数据） | 需要 finetune |
| 精度损失 | 稍大 | 小 |
| 成本 | 分钟级 | 小时~天级 |
| 适用 | 已训好模型快速量化 | 精度敏感 / 低比特（INT4） |

### 3.2 量化公式

**对称量化**（zero_point = 0）：

$$
q = clip(round(\frac{x}{s}), q_{min}, q_{max}), \quad s = \frac{max|x|}{127} \ (INT8)
$$

**非对称量化**：

$$
q = clip(round(\frac{x}{s}) + z, q_{min}, q_{max})
$$

$$
s = \frac{x_{max} - x_{min}}{q_{max} - q_{min}}, \quad z = q_{min} - round(\frac{x_{min}}{s})
$$

- 反量化：$\hat{x} = s \cdot (q - z)$；
- **对称**：适合权重（近似零均值）；**非对称**：适合激活（如 ReLU 后非负，零点偏移有意义）；
- 量化误差：$|x - \hat{x}| \le s/2$。

### 3.3 per-tensor vs per-channel

| 粒度 | 说明 | 精度 | 开销 |
| --- | --- | --- | --- |
| per-tensor | 整个张量一组 (s, z) | 低 | 最小 |
| per-channel | 每个输出通道一组 | 高（推荐权重） | 略增 |

- 权重量化普遍用 **per-channel**；
- 激活一般只能 per-tensor（动态值域难以按通道统计）。

### 3.4 INT8 / INT4

| 位宽 | 模型体积（相对 FP32） | 精度损失 | 备注 |
| --- | --- | --- | --- |
| FP16/BF16 | 1/2 | 几乎无损 | 常开 |
| INT8 | 1/4 | 通常 <1%（QAT/校准好） | 主流 |
| INT4 | 1/8 | 需 QAT + 混合精度 | 权重量化为主（LLM 常见） |

- 混合精度量化：敏感层保留高精度，不敏感层低比特。

### 3.5 激活校准

- 激活值范围在**推理时才知道**，PTQ 需用少量数据（几百张）跑前向统计；
- **方法**：
  - min/max：直接取最值，受离群点影响大；
  - KL 散度（TensorRT 用）：寻找截断阈值使量化前后分布 KL 最小；
  - 百分位：取 99.9% 分位数截断离群点；
- 校准数据要有代表性，否则线上分布漂移会放大误差。

### 3.6 量化感知训练（QAT）与 STE

- 训练时**插入伪量化节点**（fake quant）：前向模拟量化误差，反向用梯度；
- 量化 round 不可导，用**直通估计器（STE）**：

$$
\frac{\partial q}{\partial x} \approx 1 \quad (\text{在量化范围内})
$$

- 超出截断范围梯度为 0，STE 让权重学会"适应量化网格"；
- PyTorch 示例：

```python
import torch
from torch.ao.quantization import get_default_qat_qconfig
from torch.ao.quantization.quantize_fx import prepare_qat, convert_fx

model.train()
qconfig = get_default_qat_qconfig("x86")  # 或 "qnnpack"(ARM)
model_prepared = prepare_qat(model, {"": qconfig})
# 正常训练若干 epoch（后期 freeze 量化参数再微调）
model_quantized = convert_fx(model_prepared.eval())
```

- 顺序建议：先 PTQ 试水，掉点超过 1% 再上 QAT。

## 4.知识蒸馏

### 4.1 Hinton KD（软标签蒸馏）

**Loss** 由两部分组成：

$$
L = \alpha \cdot L_{hard} + (1-\alpha) \cdot T^2 \cdot KL(softmax(z_t/T) \, \| \, softmax(z_s/T))
$$

- $z_t, z_s$：teacher / student logits；
- **温度 T**（T>1）软化分布，放大"类间相似度"信息（"猫不像卡车，略像狗"）；
- 软标签携带**暗知识**（dark knowledge），比 one-hot 信息量大；
- 典型设置：T=3~10，α=0.1~0.9 视任务调。

### 4.2 特征蒸馏

- 不只蒸 logits，还对齐**中间特征**：

$$
L = L_{CE} + \lambda \cdot \| r(f_s) - f_t \|^2
$$

- $r(\cdot)$：适配维度用的 1×1 conv / 线性层；
- student 模仿 teacher 的**表示**，检测/分割等密集任务几乎必用；
- 代表工作：FitNets（hint learning）。

### 4.3 自蒸馏与其他

- **自蒸馏**（self-distillation）：同一网络深部分支教浅分支，或早 epoch 教晚 epoch（Born-Again Networks）；
- **在线蒸馏**：多个模型互教（Deep Mutual Learning）；
- **数据免费蒸馏**：用 teacher 生成/合成数据训练 student。

### 4.4 检测蒸馏（FGIR 简述）

- 检测蒸馏的代表性思路是**细粒度特征模仿**（Fine-Grained Feature Imitation）：
  - 让 student 的 neck 特征在**teacher 检出目标的区域**逐通道对齐；
  - 背景区域不强制对齐（背景冗余、会引入噪声）；
- YOLO 系列的 distill 多采用 **logit 蒸馏 + 特征蒸馏 + CWD（通道 Wise 蒸馏）** 组合；
- 检测蒸馏通常能给学生带来 1~3 mAP 提升，且零推理开销。

### 4.5 蒸馏代码示意（logit KD）

```python
import torch
import torch.nn.functional as F

def kd_loss(logits_s, logits_t, labels, T=4.0, alpha=0.5):
    hard = F.cross_entropy(logits_s, labels)
    soft = F.kl_div(
        F.log_softmax(logits_s / T, dim=1),
        F.softmax(logits_t / T, dim=1),
        reduction="batchmean") * T * T
    return alpha * hard + (1 - alpha) * soft
```

## 5.紧凑网络设计

- 思路：直接设计高效结构（深度可分离卷积、倒残差、通道混洗、重参数化等）；
- 代表：MobileNet 系列、ShuffleNet 系列、GhostNet、EfficientNet、RepVGG；
- **详见本仓库 [02.CNN与经典架构/4.轻量化网络](../../02.CNN与经典架构/4.轻量化网络/4.轻量化网络.md)**，此处不重复展开；
- 与压缩三件套关系：设计是"天生小"，剪枝/量化/蒸馏是"后天变小"，常叠加。

## 6.方法对比

| 方法 | 典型压缩率 | 精度损失 | 工程成本 | 备注 |
| --- | --- | --- | --- | --- |
| 结构化剪枝 | 2~4×（体积/计算） | 1~3% | 中（需剪枝+微调+物理删通道） | 通用硬件直接加速 |
| 非结构化剪枝 | 10×+（稀疏） | 小 | 高（需稀疏算子） | 研究为主 |
| PTQ INT8 | 4×（体积） | <1% | 低（分钟级） | 首选快速方案 |
| QAT INT8 | 4× | <0.5% | 中（需训练） | 精度敏感场景 |
| INT4（权重） | 8× | 1~3% | 高 | 常配 QAT + 混合精度 |
| 知识蒸馏 | 取决于 student | 可为正收益 | 中（需 teacher + 训练） | 零推理开销 |
| 紧凑网络 | 3~10× | 1~5% | 高（重新训） | 从头设计 |

**典型落地组合**：轻量 backbone（如 MobileNetV3）+ 检测蒸馏 + PTQ INT8，再导出 TensorRT/NCNN。

## 7.面试常考问题

**Q1：模型压缩有哪些方法？各自的优缺点？**

- 剪枝：去冗余，结构化可通用加速；
- 量化：低精度表示，收益大（4×@INT8），低比特需 QAT；
- 蒸馏：零推理开销提升小模型精度，需 teacher 与训练；
- 紧凑网络：从头设计，效果上限高但需重训；
- 实际中叠加使用。

**Q2：结构化和非结构化剪枝的区别？为什么工业多用结构化？**

- 非结构化剪单个权重，产生稀疏矩阵，通用硬件难以加速（需专门稀疏库/硬件）；
- 结构化剪整个通道，模型直接变小，任何硬件都能加速；
- 工业追求**实际延迟下降**，故首选结构化。

**Q3：幅度剪枝的流程？**

- 训练至收敛 -> 按重要性（L1/L2、BN-γ、Taylor）排序 -> 剪掉最不重要的 -> 微调恢复；
- 一次剪太多会崩，用迭代剪枝逐步进行。

**Q4：PTQ 和 QAT 怎么选？**

- 先试 PTQ：成本低、速度快，INT8 通常损失 <1%；
- PTQ 掉点明显或要 INT4，再上 QAT；
- QAT 用 STE 让 round 可反传，训练中模拟量化误差。

**Q5：写一下对称和非对称量化公式？**

- 对称：$q = round(x/s)$，z=0，适合权重；
- 非对称：$q = round(x/s) + z$，适合激活（ReLU 后非负）；
- 反量化 $\hat{x} = s(q-z)$，量化误差上界 s/2。

**Q6：为什么权重量化用 per-channel？**

- 不同通道权重分布差异大，per-tensor 一组 scale 会导致部分通道精度崩；
- per-channel 每通道独立 scale，精度更高；
- scale 可离线固定，几乎无推理开销。

**Q7：激活为什么需要校准？怎么做？**

- 激活范围推理时才知道，PTQ 需跑少量代表性数据统计 min/max；
- 方法：min/max、百分位截断、KL 散度（TensorRT）；
- 校准数据不代表性会导致线上精度崩。

**Q8：QAT 中 STE 是什么？**

- Straight-Through Estimator；
- round 不可导，反向传播时把梯度近似为 1 直接传给输入；
- 让权重在训练中适应量化网格，显著降低量化误差。

**Q9：知识蒸馏中温度 T 的作用？**

- T>1 软化输出分布，放大类间相似度信息（dark knowledge）；
- T 太小近似 one-hot 信息少，T 太大分布太平滑失去判别性；
- 常用 T=3~10，loss 中需乘 T² 对齐梯度尺度。

**Q10：logit 蒸馏和特征蒸馏的区别？**

- logit：只对齐最终输出，简单通用，信息量有限；
- 特征：对齐中间表示（需适配层），信息更丰富；
- 密集任务（检测/分割）特征蒸馏收益更大，如 FGIR 只在目标区域模仿。

**Q11：蒸馏一定有效吗？什么时候失效？**

- student 容量太小：装不下 teacher 知识；
- teacher 与 student 结构差异过大：特征难对齐；
- 数据不足或与 teacher 训练分布不一致；
- teacher 本身不强时，蒸馏收益小。

**Q12：FLOPs 降了 4 倍，为什么实际只快 2 倍？**

- 实际延迟 = 计算 + 访存 + 启动开销；
- 通道剪枝减少计算但访存比可能恶化；
- 框架实现、算子调度、带宽都是瓶颈；
- 必须以目标硬件实测延迟为准（roofline 分析）。

**Q13：模型体积减小和延迟降低是一回事吗？**

- 不是。体积主要由参数量/位宽决定，延迟由计算量、访存、实现共同决定；
- INT8 量化既减体积又加速（有 INT8 加速单元时）；
- 非结构化剪枝减体积不加速；
- 终极指标是**目标硬件上的实测延迟**。

## 8.总结

- **四板斧**：剪枝（去冗余）、量化（低精度）、蒸馏（教师教）、紧凑设计（天生小），可叠加；
- **剪枝**：工业用结构化，幅度/BN-γ/Taylor 为准则，迭代剪 + 微调；
- **量化**：PTQ 先行、QAT 兜底；权重 per-channel 对称、激活 per-tensor 非对称；INT8 是甜点；
- **蒸馏**：软标签带 dark knowledge，特征蒸馏适合密集任务，零推理开销；
- **一切以实测为准**：FLOPs 只是参考，目标硬件延迟才是真指标；
- 部署侧衔接见 [4.部署框架](../4.部署框架/4.部署框架.md)。
